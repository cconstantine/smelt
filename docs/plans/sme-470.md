# SME-470 plan: every network fetch gets a retry, a bound and a pin

**Branch:** `cconstan/sme-470-sweep-every-network-fetch-at-build-ci-and`, cut from `origin/main` `347f7fba` (2026-11-09). Plan files are removed before merge (the user, 2026-11-09).

## What and why

GitHub and other hosts answered 5xx on five fetch paths in about a day (the ticket lists them). Each was fixed on its own. This sweep lists **every** fetch that the build (Dockerfiles, `scripts/`, `build.rs`, `dx bundle`), CI (`.github/`, its scripts) and the running server make, plus the installs the server's LSP catalog suggests. Each fetch gets three things, or it is baked into an image, or it gets a written reason for neither:

1. a retry on a transient failure (408, 429, 5xx, a refused or reset connect) **before any of the body is used**;
2. a bound;
3. a pinned version with a checksum.

**The rule from SME-466:** a body cut off partway never feeds a retried second copy into a pipe. New guards download to a file, check it, then use it.

Probed at plan time, in this seat:

- **curl truncates its `-o` file before a retry.** A stand-in sent 512 KiB of a 1 MiB `Content-Length` body and then closed. `curl --retry 3 --retry-all-errors -o out` (8.14.1) logged `(18) end of response with 524288 bytes missing`, made a second GET, and `out` was byte-exact at 1,048,576 bytes. Without `--retry-all-errors` a `(18)` is not retried. Script: `cut_then_ok.py` in the seat's scratch dir. The Developer turns it into a mode of the flaky server (T1 below).
- **apt 3.0.4 (trixie) already retries and checks hashes.**
  - `Acquire::Retries` defaults to 3, with backoff, for transient errors: `apt-pkg/acquire-item.cc:787` and `apt-pkg/acquire-worker.cc:695–704` at tag 3.0.4 on salsa.
  - It treats 408 and the 5xx codes as transient: `methods/basehttp.cc:893–899`.
  - It checks every `.deb` against the signed index's SHA256.
- **apt 3.0's `--print-uris -qq` no longer prints a hash.** The real line is `'http://deb.debian.org/debian-security/pool/updates/main/b/brotli/libbrotli1_1.1.0-2%2bdeb13u1_amd64.deb' libbrotli1_1.1.0-2+deb13u1_amd64.deb 303640 ` (nothing after the size). So `scripts/browser-check/setup.sh`'s curl'd `.debs`, fetched over plain `http://`, **cannot be checked from that output.**
  - A non-root `apt-get -o Debug::NoLocking=1 -o Dir::…=<cache> --reinstall --download-only install <pkg>` works as a user with no dpkg lock and saves `libbrotli1_1.1.0-2+deb13u1_amd64.deb`, with a decoded `+`. curl `-O` saves the name with `%2b` instead.
- **dx 0.7.9's release asset** `dx-x86_64-unknown-linux-gnu.tar.gz`:
  - has sha256 `3b132551b480bc96f938f9f0d37936ee1190f994977539dcc347eaf38540d005`, the same in DioxusLabs' published `.sha256` file and in GitHub's asset digest;
  - holds a single top-level `dx`;
  - prints `dioxus 0.7.9 (3e43ffa)` when run in `rust:1.96-trixie`.
  - aarch64, from the GitHub asset digest: `8cf14db0b11b43b31dd6d39e71b00e567f2fccfde85ae3a8f7ef0f8745e5ccfb`. The Developer checks it against `dx-aarch64-unknown-linux-gnu.sha256`.
- **`rancher/k3s:v1.34.6-k3s1` ships `kubectl`** (`Client Version: v1.34.6+k3s1`). The compose `k3s` service runs that image.
- `https://dl.k8s.io/release/v1.34.0/bin/linux/amd64/kubectl.sha256` exists (HTTP 200), if the Driver prefers a fetch over the k3s binary (Q3).

## Design

### A. `scripts/fetch-pinned URL OUT SHA256|-` (new, about 3 KB)

Modelled on `ci-install-compose`'s `try_source`.

- Up to `FETCH_ATTEMPTS` attempts (default 4), with `FETCH_PAUSES` between them (default `2 5 15`; the tests set `0 0 0`).
- Each attempt runs `curl -fsSL --connect-timeout ${FETCH_CONNECT_TIMEOUT:-30} --speed-limit 1024 --speed-time ${FETCH_SPEED_TIME:-60} --max-time ${FETCH_MAX_TIME:-300} -w '%{http_code}' -o "$tmp" URL`.
  - `$tmp` comes from `mktemp "$OUT.tmp.XXXXXX"`, is emptied before each attempt, and is removed by a trap.
- Retried: curl's connect, timeout, partial-body and reset errors; HTTP 408, 429 and 5xx; a sha256 mismatch (a CDN error page served as 200).
- **Not retried:** any other 4xx, since a wrong pin or URL isn't transient. It fails on attempt 1, naming the status.
- A file is used only once it is whole. Only a checked file is renamed into `OUT` (`mv -f`), so a cut-off body never reaches a consumer. With `-`, the caller checks `OUT` before using it (only rows B6, B8 and B9, each checked on the next line).
- Output, one line per failed attempt: `fetch-pinned: <url> attempt k of n failed: <reason>`. Giving up prints `fetch-pinned: gave up on <url> after n attempts (last: …)` and exits 1, leaving any old `OUT` untouched.
- **Worst case for one fetch:** stalls give 4 × (30 + 60) + 22 ≈ 6.4 min; a slow-but-moving download gives 4 × 300 + 22 ≈ 20.4 min. Callers with big files (dx at 33 MB) keep the defaults; the minimum speed of 1 KB/s is never a real download's speed.
- `http://` is allowed (row B10 used it), because the sha256 is the integrity check. No `--proto` restriction.
- Dockerfile stages `COPY scripts/fetch-pinned /usr/local/bin/fetch-pinned` (in `dx-tools`, `dx-cli`, `base`, `claude`). `docker/sandbox/Dockerfile` can't COPY it: its context is `target/sandbox-agent/`. Row B9 there keeps an inline `curl --retry 4 --retry-all-errors --connect-timeout 30 --speed-limit 1024 --speed-time 60 -o` with the fingerprint check: the same guard, written out, with its reason in a comment.

### B. `scripts/pull-image [--if-missing] REF` (new, about 1.5 KB)

- `--if-missing` with `docker image inspect REF` succeeding: says `already present` and exits 0.
- Otherwise up to 3 attempts of `timeout ${PULL_TIMEOUT:-300} docker pull -q REF`, with pauses `${PULL_PAUSES:-15 45}`.
- One line per failed attempt (a timeout says `gave up after Ns`), and a final `pull-image: REF: 3 attempts, last: …` with exit 1.
- Callers: `build-sandbox-image.sh:78` (always pulls, as now), and `start-stack`'s new step with `--if-missing` (row C4).

### C. `src/http_fetch.rs` (new, `#[cfg(feature = "server")]`, about 7 KB with its tests)

```rust
pub(crate) struct Policy { pub attempts: u32, pub backoff: &'static [Duration], pub per_try: Duration, pub deadline: Duration, pub max_bytes: usize }
pub(crate) enum Fetched { Body(String), NotFound }
pub(crate) async fn get_text(url: &str, policy: &Policy) -> Result<Fetched, String>
```

- One `reqwest::Client` per call, with `timeout(per_try)`, as both callers build one now. The whole loop sits under `tokio::time::timeout(deadline)`.
- **Retried, only before any body:**
  - a `send()` error that `is_connect()`, `is_timeout()` or `is_request()`;
  - a status of 408, 429 or 5xx.
- **Not retried:** 404 (returns `NotFound`), any other non-success status (fails at once), and any error while reading the body (a cut-off body fails with no second GET). A 2 MB or 32 MB cap overrun fails with no retry.
- Error texts stay as today: `"{url} answered {status}"` (the last status, after the retries), `"{url} is too big (over N MB)"`, `"{url} isn't text"`. A spent deadline says `"{url} didn't answer within {deadline}s ({attempts} tries)"`.
- **Policies:**
  - `catalog::FETCH`: 3 attempts, backoff 1 s then 2 s, 15 s per try (as now), **30 s deadline (new)**, 2 MB. `lookup` joins its two fetches, so a user waits at most 30 s, against 15 s today. That is the price of riding out a 5xx; a fast 5xx costs about 3 s.
  - `pricing::FETCH`: 3 attempts, backoff 2 s then 5 s, 60 s per try, 120 s deadline, 32 MB. It runs in the background refresh.
- `catalog::fetch` (`catalog.rs:161–177`) and `pricing::fetch` (`pricing.rs:258–275`) are deleted and their callers call `get_text`:
  - `catalog.rs` loses about 900 B and lands about 24 KB.
  - `pricing.rs` loses about 700 B; `NotFound` maps to its old `"{url} answered 404 Not Found"`.
- **Commit shape:** the helper has no non-test caller on its own, so it lands **in one commit with both callers** (plan.md's dead-code rule), each test seen red first.
- **`rederived_install` is untouched** (Q2: no suggested-text change). Its existing test, `src/lsp/pods/tests/script.rs:131`, stays green as the check.
