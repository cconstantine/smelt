## What

`TrustCards` renders the file as `pre { "{request.content}" }` (`src/frontend/pages/chat/trust_card.rs:42`), and the context detail view renders the loaded file and the whole system prompt the same way (`src/frontend/pages/chat/context.rs:351` and `:359`). Dioxus escapes HTML, so Unicode's `Default_Ignorable_Code_Point` characters pass into the DOM and render as nothing: the user reads a file with text in they cannot see, and Trust puts that text into every turn's system prompt.

SME-276 (merged, `817ed6c`) solved this for what the *model* reads, and its function is the one to reuse: `plain_multiline_text` (`src/git/server/instructions.rs:72`) writes every character `plain_path_text` refuses — control characters, line separators, bidi controls, and the `hides_text` default-ignorable set (`:42`) — as its `\u{…}` escape, keeps `\n` and `\t`, and is idempotent, because the escape is ASCII. It is `pub`, but inside the `#[cfg(feature = "server")]` module (`src/git.rs:122`), so the chat frontend cannot reach it.

So: move that rule into the ungated part of `src/git.rs`, where the types that cross the client/server boundary already live, add one count function beside it, and render the card's preview and the context view's two panes through it — with one line naming how many characters had to be escaped, and saying the escapes are this view's showing, not the file's text.

No second copy of the code-point set, and nothing computed server-side: the content already travels to the client, so deriving the display string there costs nothing on the wire, where a new field on `TrustRequest`/`ProjectInstructions` would double it and put display logic on the server.

**The invisible characters do reach the card today.** `load_instructions` reads the file through `PodShell::run`, whose stdout goes through `String::from_utf8_lossy` (`src/sandbox/exec.rs:142`), and default-ignorables are valid UTF-8, so they survive unchanged into `instruction_requests.content` and `loaded_instructions.content`.

Two places in the repo already solve this: `hides_text` (SME-276 — the one to reuse, and what the brief asks for) and `invisible` in `src/lsp/catalog.rs:284` (SME-182: the same set plus the line/paragraph separators and the interlinear annotation characters), escaped there by its own `format!("\\u{{{:x}}}", …)`, for the same reason — a user reviewing text they cannot fully read. This plan takes SME-276's and leaves `catalog.rs` alone (Trade-offs).

## How

### The rule, moved

`src/git/plain_text.rs` holds the four moved functions with their current bodies and doc comments, `hides_text` keeping its DerivedCoreProperties citation. It is declared in `src/git.rs` ungated, because `plain_multiline_text` is now a display rule the client needs; that file's own header already says the summaries at its top cross the client/server boundary and are therefore ungated.

One item is added, and it takes its condition from `plain_multiline_text` itself, so the count and the escape cannot drift apart:

```rust
/// How many characters of `text` `plain_multiline_text` escapes — the ones a
/// reader can't see (SME-277): the default-ignorables, the control characters,
/// and the ones that reorder the text around them. `text` with nothing to
/// escape counts 0 and escapes to itself.
pub fn hidden_characters(text: &str) -> usize {
    text.chars().filter(|c| not_plain(*c) && *c != '\n' && *c != '\t').count()
}
```

`plain_path_text` stays in `instructions.rs` (it is the rule about what may go on a line of the *system prompt*, which the client never renders). Moving it too would leave it with no caller in the `web` build, where `check.sh` fails on warnings — both builds are warning-free, and in a binary crate a `pub` function nobody calls is dead code. In the `web` build `hides_text`, `breaks_a_line` and `not_plain` are reached from `plain_multiline_text`, which the chat frontend calls, so nothing warns in either build.

### The view

`src/frontend/pages/chat/shown_text.rs` is the one place the wording lives, so the card and the context view cannot drift:

```rust
/// `content` as the user can read it: every character that renders as nothing,
/// reorders the line, or is a control character is shown as its `\u{…}` escape
/// (SME-276's rule), and when there are any, a line says so above them
/// (SME-277). What Trust loads is unaffected — that goes by hash.
pub(super) fn shown_pre(content: &str, pre_class: &'static str) -> Element
pub(super) fn hidden_text_notice(count: usize) -> Element // rsx!{} at 0
```

The notice is one `<p class="muted">`, singular/plural on `count`:

> {n} character(s) in this file render as nothing, or change how the text around them shows, so they are shown here escaped as `\u{…}`. The escapes are this view's, not the file's: Trust loads the file as it is, and so does the model.

`.muted` already exists (`assets/css/01-base.css:320`), and `.trust-card-preview pre` is `white-space: pre-wrap; word-break: break-word; max-height: 240px; overflow: auto` (`assets/css/07-pages.css:495`), so a long run of escapes wraps inside the existing scroll box. That is why the fix escapes rather than drawing per-character badges: a badge wants a `<span>` per character and a new CSS rule; the escape is the tested function as it stands, and it is what smelt already shows the model and what `{:?}` shows in `catalog.rs`.

### The two sinks

**Trust card.** `render_trust_card_preview(request)` renders `hidden_text_notice(hidden_characters(&request.content))` and then `pre { plain_multiline_text(&request.content) }`, still inside `details.trust-card-preview` with `open: true`, under the unchanged `<summary>{request.path}</summary>` — a path is `plain_path_text`-checked server-side (SME-271), so it cannot need escaping. The question line, the "Trust loads exactly the file below" paragraph and both buttons are unchanged, and both buttons keep sending `request.hash`.

**Context view.** `shown_pre(&doc.content, "context-detail-prompt")` per file, and the same call for the System prompt pane: the loaded AGENTS.md text is inside that pane too, so escaping one and not the other would leave the same hidden text invisible a pane away. `instructions_source`'s summary line keeps reporting the file's byte count — it describes the file, and the file is unchanged.

**Not changed:** the loaded content, the stored rows, `render_project_instructions`, `load_instructions`'s answer to the model, or anything else the model reads. SME-276's decision stands: the model gets the file as it is, so it can still edit the file it reads without writing the escapes back.

## State model

Nothing new is stored and nothing new is written. The escape is derived at render time from content already in the row, so no record gains a state, no transition moves, and there is no new operation that can fail partway.

- **The rows and their writers, all unchanged.** `instruction_requests` (a card) is written by `request_or_load` (`instructions.rs:291`, the model asking about an undecided remote), replaced by a later `request_instruction` for the same file (see `src/git/server/trust.rs:88`'s comment: the model asking again replaces the request's copy, and the card follows), and deleted by `settle`/`drop_cards_for_remote` (`:77`, `:113`), by `trust_named_remote` (`:169`), or by the conversation's delete cascade. `loaded_instructions` is written by `settle` on Trust (`:97`) and by `request_or_load` on a trusted remote, and emptied per remote on a Decline (`unload_instructions_for_remote`).
- **The hash invariant is what this plan must not disturb.** `settle` refuses Trust when `request.hash != shown_hash` (`src/git/server/trust.rs:90`), and the card sends `request.hash`, which is the `sha256` of the **raw** content (`instructions.rs:170`). The card renders an escaped string but decides with the hash, so "Trust loads exactly the file the user read" still holds: they read a *showing* of the file, and the bytes loaded are the bytes the hash pins. Expected, and to be seen green without edit: `git::server::trust_race_tests`, `api::git::tests`.
- **Every reader of this content, and what it shows after.** The trust card (escaped, with the count); the context view's per-file pane (escaped, with the count); the context view's System prompt pane (escaped — it embeds the same text); the model's own system prompt (`render_project_instructions`, raw — unchanged); `load_instructions`'s answer (a path and a byte count); the sandbox panel's "Loaded AGENTS.md" line (a path, plain-checked). The three escaped readers all go through `shown_pre`, so they cannot disagree about the same file.
- **Each card state, and what the user sees.**
  | State | What the card shows |
  | -- | -- |
  | No card — nothing asked yet, or the user named the repo (trusted at once, SME-224) | Nothing new. |
  | Awaiting the decision, file with nothing hidden | No notice; the preview is byte-identical to today. |
  | Awaiting the decision, file with hidden characters | Notice with the count, preview escaped. |
  | File edited and asked again while the card waits | The card follows the new row and recounts. The stale hash no longer matches, which is what the refusal at `trust.rs:90` is for; unchanged. |
  | Answered (either way) | `settle` takes the card, and every other card for that remote goes with it, so no stale showing survives on screen. |
  | Refused for the hash mismatch | The unchanged wording, on the card's own error line (`trust_card.rs:68`). |
- **Other tabs, other conversations, the pod.** The preview comes from `RepoSummary.trust_requests` (`repos.rs:75`), published by `publish_repos` after each of those writes, so every tab derives the same string from the same stored content: two tabs on one card cannot disagree. Another conversation's card for the same remote is another row, derived the same way. Nothing lives in the sandbox, and this change never rewrites the file on disk, so a pod restart, a re-clone, or a model edit changes a preview only by changing the row it reads.
- **The worst case is bounded.** `INSTRUCTIONS_MAX_BYTES` is 32 KiB, so a card's content is at most ~11k characters, every one of which can need escaping: `hidden_characters` one pass, `plain_multiline_text` one pass, ~88 KB of text inside the existing 240 px scroll box. No loop and no growth after the first render — this is not the SME-209 class (a parse whose cost is unbounded).

## Trade-offs to flag

- **The card no longer shows a byte-for-byte copy of the file.** A file that literally contains the eight ASCII characters `\u{200b}` now looks like one that holds a zero-width space. The alternative — leaving it raw — is the bug. The hash still pins what Trust loads, and the notice says the escapes belong to the view.
- **The reused rule escapes more than the invisible.** `not_plain` also fires for `CR`, `ESC`, `DEL`, the bidi controls and the variation selectors (U+FE00–FE0F), which change how the *preceding* glyph shows rather than hiding themselves. Deliberate: the set and its tests are SME-276's, and forking the set is what this ticket is told not to do. Hence the wording "render as nothing, or change how the text around them shows" rather than "invisible".
- **`src/lsp/catalog.rs::invisible` (SME-182) is a second copy of a similar set** — wider, by the line and paragraph separators and the interlinear annotations — and `shell_word` escapes with its own `format!("\\u{{{:x}}}", …)`. Left alone: it guards a shell command, not a trust decision, and folding the two would change a refusal in a path this ticket otherwise does not touch. Worth its own tidy ticket.
- **`docs/current-state/features.md` is 37,879 bytes — 2,121 under the ceiling** — before this plan's ~170-byte clause. Measured rather than assumed, so it fits; but the next ticket that touches it should carry a split commit first, the SME-205 way. Worth the Project Manager a Backlog ticket.
- **Still shown raw, by scope:** the context view's **Tools** panes (an MCP server's description and JSON schema, `context.rs:391–396` — see question 3), tool results and terminal output in the transcript, the sandbox panel's raw branch name (SME-273), and persona-file content once it is shown for trust (SME-235, SME-236 — `shown_pre` is the helper they would use).
- **Derived per render, not memoised.** A 32 KiB AGENTS.md is escaped and counted again on each re-render of the card or the dialog: two linear passes, and the card re-renders on repo publishes, not on keystrokes.
