# SME-236: child agents — plan

**Branch:** `sme-236-child-agents`, worktree `~/smelt-worktrees/smelt-SME-236`, cut from `origin/main` at `421558b` (SME-269's merge).

The design is `docs/design/personas/agents.md` and `checkouts-and-volumes.md` (SME-234), with the user's later change from SME-234's comments (default depth 5, the root may override limits) left to SME-245: this ticket ships with depth 1, `start_agent` offered only to a conversation without a parent. Where this plan departs from the design pages, it says so and the docs commit updates the page.

## What

A conversation's model gets four tools: `start_agent(brief, repo?, ref?, persona?)`, `list_agents()`, `stop_agent(id)` (a root's), and `finish(report)` (a child's). A child is a whole conversation with a `parent_id`, an `agents` row holding its lifecycle and persona snapshot, and its own sandbox. Reports and notices reach a conversation through a durable queue, `agent_messages`, drained under the recipient's turn lock like finished commands and woken with `Notice::Wake`. A child that ends a turn without `finish` gets its parent a notice; a start that fails, or that a restart cuts off, ends `failed` with the error as its report. Deleting a conversation deletes its whole subtree, and the sidebar's Delete says how many agents go with it. Why: scope item 1 of "Personas and sub-agents", the core of SME-38 (superseded).

## Decisions the ticket left to the Planner

- **`agents.rule_chain` and `agents.credentials` are not added here.** SME-241 and SME-242 add and fill them: a column nothing writes would need a default that means something, and a wrong default (no credentials, or every rule) is worse than none. The key-removal exits are still built here (see "The start"), as one cleanup that SME-242 fills.
- **The subtree delete stays in this ticket** (the Architect's split proposal). Once `parent_id` cascades, a plain delete of a parent already deletes its children's rows, but would leave their pods running and their turns going: the teardown of the subtree is needed for correctness the moment children exist. What a split would move out is small (`deleting_at`, the root lock against a racing `start_agent`, the notice to the parent, the confirm label), so the split isn't worth a second ticket's overhead. The PR is large; see Trade-offs.
- **`agents.started_at`** (new, not in the design's table): set when the start completes. A child `stop_agent` stopped *during* its start has `state = 'stopped'` and `started_at IS NULL`; the user's send in it is refused like a failed one, so a child can never become `active` without its clone and persona (see the state model).
- **The child's first turn is woken by a queued notice to itself.** The start ends by queuing a `notice` to the child ("Your start is done: … When your work is done, call `finish` with your report") in the transaction that makes it `active`, then `Notice::Wake`. A wake with nothing pending does nothing (`run_turn_steps`' `is_wake && persisted.is_empty()`), and the brief was saved at creation, so the notice is what gives the first turn something to drain; it also survives a restart between `active` and the turn (the sweep wakes it).
- **The user's Stop on a child notifies its parent** (agents.md, "Stop"): without it a parent waits for a report that won't come. The stored pause (`paused_at`) and its restart behaviour stay SME-238's.
- **A child's brief turn needs no special clone wait:** the start clones before it makes the child `active`, so by the first turn `wait_for_clones` returns at once. `CLONE_WAIT` is unchanged.

## The schema (one migration)

```sql
ALTER TABLE conversations
    ADD COLUMN parent_id BIGINT REFERENCES conversations (id) ON DELETE CASCADE,
    ADD COLUMN deleting_at TIMESTAMP;
CREATE INDEX conversations_parent_id ON conversations (parent_id) WHERE parent_id IS NOT NULL;

CREATE TABLE agents (
    conversation_id  BIGINT PRIMARY KEY REFERENCES conversations (id) ON DELETE CASCADE,
    root_id          BIGINT NOT NULL REFERENCES conversations (id) ON DELETE CASCADE,
    depth            INT NOT NULL CHECK (depth >= 1),
    brief            TEXT NOT NULL,
    persona_name     TEXT,          -- asked for at start_agent; the rest once read
    persona_path     TEXT,
    persona_commit   TEXT,
    persona_body     TEXT,          -- links rewritten
    persona_settings JSONB,         -- the `smelt` map as parsed ({"model": …})
    state            TEXT NOT NULL CHECK (state IN ('starting','active','finished','stopped','failed')),
    created_at       TIMESTAMP NOT NULL DEFAULT now(),
    state_changed_at TIMESTAMP NOT NULL DEFAULT now(),
    started_at       TIMESTAMP     -- the start completed; NULL while starting, and for a start that never completed
);
CREATE INDEX agents_root_id ON agents (root_id);

CREATE TABLE agent_messages (
    id                   BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    to_conversation_id   BIGINT NOT NULL REFERENCES conversations (id) ON DELETE CASCADE,
    from_conversation_id BIGINT REFERENCES conversations (id) ON DELETE SET NULL,
    from_label           TEXT NOT NULL,
    kind                 TEXT NOT NULL CHECK (kind IN ('report','notice')),  -- SME-238 adds 'message'
    body                 TEXT NOT NULL,
    created_at           TIMESTAMP NOT NULL DEFAULT now(),
    delivered_at         TIMESTAMP,
    delivered_message_id BIGINT REFERENCES messages (id) ON DELETE SET NULL
);
CREATE INDEX agent_messages_undelivered ON agent_messages (to_conversation_id, id) WHERE delivered_at IS NULL;
```

The `kind` check is replaced by SME-238 when it adds `message`. Every `UPDATE agents SET state` is `… WHERE conversation_id = $1 AND state = <expected>` (or `IN (…)` for the subtree's bulk stop), and also sets `state_changed_at = now()`.

## How

### The tools (`src/anthropic/tools/agents.rs`)

`Tool` gets `offer: Offer` (`All`, `Root`, `Child`); every existing tool is `All`. `tool_definitions(pool, conversation_id)` reads the conversation's `parent_id` once (`db::conversation_parent`) and leaves out what isn't offered; `native_tool_definitions()` (tests, unchanged signature) lists them all. `execute` refuses a call to a tool the caller isn't offered ("start_agent is only for a conversation without a parent" / "finish is only for an agent"), checked from the database, not from what was offered: a call can come from history after the conversation changed. The four go at the end of `REGISTRY`, after `questions::tools()`, so every existing tool keeps its place in the request.

- **`start_agent(brief, repo?, ref?, persona?)`** (`Root`). `brief` 1–30,000 characters. `repo` is a path `/workspace/<dir>` naming one of the caller's `ready` checkouts. `ref` requires `repo`: 1–255 bytes, no control characters or whitespace, not starting with `-`, no `..`, no `@{`, not ending in `.lock` or `/` (passed to git as an argument and in `refs/remotes/origin/<ref>`, never through a shell string). `persona` requires `repo` and is a valid persona name (`personas::is_persona_file_name(&format!("{name}.md"))`). Steps, in order:
  1. Checks that need the parent's pod, before anything is written (`ChildCheckout`, below): with `repo` and no `ref`, **the parent's commit** (`child_ref::parent_commit`): `git fetch --quiet origin` under `timeout`, then the branch (`git symbolic-ref --short -q HEAD`; detached → refused), its upstream (`git rev-parse --abbrev-ref --symbolic-full-name @{u}`; none → refused), `git merge-base --is-ancestor HEAD @{u}` (fails → "N commits not on <upstream>", refused), `git status --porcelain --untracked-files=no` (non-empty → refused). Each refusal says what to do: commit and push, or pass `ref` (volumes aren't offered until SME-239, so the message doesn't suggest one). The result is `(commit, upstream branch name without the remote)`. With `persona` and no `ref`, **the persona is in the parent's checkout now**: `list_persona_files` in the parent's pod contains `.agents/personas/<name>.md`, else refused ("no persona `<name>` in /workspace/<dir> (its personas: …); list_personas lists them"). With a `ref`, the persona is checked only at the child's ref, during the start.
  2. One transaction (`db::create_child`), locks in the order of the lock table below: `lock_remote_trust(remote_key)` (with `repo`), then the caller's row `FOR NO KEY UPDATE`; refuse if the caller is gone, has `deleting_at`, or has an `agents` row (depth 1: it isn't a root), or (generally) its `agents.state` is `stopped`; with `repo`, refuse unless `repo_trust.trusted` is true for the checkout's `remote_key` ("the user hasn't trusted this repo; load its AGENTS.md with load_instructions so they're asked" / "the user declined to trust this repo"); insert the child's `conversations` row (`parent_id` = caller, `provider_id`/`model` = the caller's resolved choice from `providers::conversation_model`: `Chosen` or `Default`, else both NULL), its `agents` row (`starting`, `root_id` = caller, `depth` 1, `brief`, `persona_name`), the brief as the child's first `user` message (`create_message_on`, which also titles it), and with `repo` its `conversation_repos` row as `cloning` (same `url`, `remote_key`, `dir`; `branch` = the ref when it names a branch or tag, else NULL). Commit.
  3. `publish_app(ConversationsChanged)`; spawn the start (below) in the request's span; return at once: "Started agent #N (`<dir>:<name>` | no persona) on <repo at commit|ref> … Its report arrives as a message when it calls finish; list_agents shows its status."
- **`list_agents()`** (`All`, so a child sees its (empty) list too): the caller's own children only (`WHERE parent_id = $caller`), newest first: `id`, `title`, `persona` (`<dir>:<name>` or null), `status`, `created_at`, `last_message_at` (`max(messages.created_at)`), `agents_started` (its own children's count). `status`, first that holds (agents.md's table, without SME-238's "waiting for its parent"): `starting`, `failed`, `stopped` (from `state`), `running` (`turn::turn_running`), `waiting for the user` (an unanswered `pending_questions` row, or an `instruction_requests` card), `finished`, `idle`.
- **`stop_agent(id)`** (`All`): refused unless `id` is the caller's child (`agents` row with that conversation's `parent_id` = caller). One transaction: the subtree's ids (recursive CTE on `parent_id` from `id`), those conversation rows `FOR KEY SHARE` in id order, then `UPDATE agents SET state = 'stopped' WHERE conversation_id = ANY($subtree) AND state IN ('starting','active','finished') RETURNING conversation_id`. Commit, then `turn::stop_conversation` on every subtree id (state first, then the stop, so a wake admitted between them is ended by the stop: SME-217's order). Pods and terminals are left alone. Result: "Stopped agent #N (and K agents under it)." A child already stopped or failed: "agent #N was already stopped/failed".
- **`finish(report)`** (`Child`): `report` 1–30,000 characters. One transaction: the parent's and the child's conversation rows `FOR KEY SHARE` in id order; `UPDATE agents SET state = 'finished' WHERE conversation_id = $child AND state = 'active'` (0 rows → refused: "you were stopped by your parent" / "you've already finished"); insert the `report` row to the parent (`from_label` = the child's label). Commit; `turn::notify(parent, [Notice::Wake])`. Returns "Your report was sent to your parent. Your turn ends here; the user may still write to you." `run_tools` treats a successful `finish` like `ask_user`'s `asked`: its results are saved and the turn ends without another model call. A failed `finish` (refused) is an ordinary error result and the turn goes on.

### The start (`src/agents/start.rs`), a spawned task

All pod work goes through `ChildCheckout` (`src/agents/checkout.rs`), a trait with `parent_commit`, `parent_persona_paths`, `clone`, and `read_file`; `PodCheckout` implements it with `PodShell`, `clone_child_repo`, `list_persona_files` and `read_instructions_file`. Tests register a fake per parent conversation id (as `sandbox::agent::test_dialers` does per pod), so the start's database behaviour is tested without a cluster, and `src/sandbox/tests/child_checkout.rs` tests `PodCheckout` itself against a real pod.

Steps, each ending the start through `fail_start` on error:

1. **Clone** (with `repo`): `clone_child_repo(pool, child, repo_row, target)`, where `CloneTarget` is `Commit { sha, branch }` (the default: the parent's commit, on a branch of the upstream's name) or `Ref(ref)`. It is `clone_recorded` with the target passed down: a plain `clone_into_pod(url, None, dir)` (the default branch), then `checkout_ref` in the checkout: for `Commit`, `git cat-file -e <sha>^{commit} || git fetch --quiet origin <sha>`, then `git checkout -q -B <branch> <sha>` and `git branch -q --set-upstream-to=origin/<branch>` (ignored if the remote branch is gone); for `Ref`, `refs/remotes/origin/<ref>` → `git checkout -q -B <ref> origin/<ref>` (tracking); else `refs/tags/<ref>` → `git checkout -q --detach <ref>`; else a full or abbreviated hex id → as `Commit` but `--detach`; else refused ("no branch, tag or commit `<ref>` on <url>"). The `ClonedRepo` recorded is read after the checkout. Fetch by id is allowed for any object the server has under protocol v2 (gitprotocol-v2, `fetch`: "Wants can be anything and are not limited to advertised objects"; v2 is git's default since 2.26), checked here on git 2.47.3 against a `file://` bare remote: a reachable non-tip commit and an unreferenced one both fetched. The real-cluster test checks the sandbox image's git does the same.
2. **Trust, again** (with `repo`): `lock_remote_trust` + `get_repo_trust` in a transaction; not `Some(true)` → fail ("the user no longer trusts <url>").
3. **AGENTS.md** (with `repo`, when the recorded `agents_files` has the top-level `AGENTS.md`): `read_instructions_file`, `file.commit = head_commit`, `request_or_load(pool, child, repo, "AGENTS.md", file)`. `Loaded` → on. `AwaitingTrust` (the user Forgot the remote between step 2 and here) → fail. A declined remote → fail with `request_or_load`'s message.
4. **Persona** (with `persona`): `read_file(".agents/personas/<name>.md")` in the child's checkout (symlink-safe, as `list_personas` reads it). `None` → fail ("no persona `<name>` at <ref>"). `personas::parse`; an error → fail with it. `links::absolute(body, "/workspace/<dir>/.agents/personas")` (below). The snapshot: `persona_name`, `persona_path`, `persona_commit` (the clone's commit), `persona_body`, `persona_settings` (`{"model": …}`).
5. **Model**: with a persona `smelt.model`, `db::provider_for_model(pool, name, parent_provider)`: a `provider_models` row with that model, tried in the order persona-files.md gives (the parent's provider, the default model's provider, then the others by provider name). Found → the child's `provider_id`/`model`. Not found → the child keeps its parent's model, and a `notice` to the parent says so.
6. **Done**, one transaction (lock table): `UPDATE agents SET state = 'active', started_at = now(), persona_* = … WHERE conversation_id = $child AND state = 'starting'`; the model update; the start notice to the child itself (`kind = 'notice'`, `from_label` `smelt`): what was cloned (path, branch, commit), the persona loaded, the model, and "When your work is done, call finish with your report. The user can also write to you here." 0 rows updated (a `stop_agent` or delete landed first) → no notice, and the start ends through `StartExit` only. Commit; `notify(child, [Notice::Wake])`.

**`fail_start(child, error)`**, one transaction: `UPDATE agents SET state = 'failed' WHERE … AND state = 'starting'`; if it updated, a `report` to the parent: "agent #N's start failed: <error>"; the same text saved in the child's own transcript (a `user` notice, so the user opening it sees why). Commit; wake the parent. 0 rows (stopped or deleted meanwhile) → nothing queued.

**`StartExit`**, a guard the start holds from its first step: on every way out (done, failed, refused, the conversation deleted, the task dropped) it deletes the child's `instruction_requests` (a card its AGENTS.md load made), and runs `drop_start_credentials(child)`, the one place SME-242 removes the key for a child without `git-ssh` (today every child keeps it, as every pod does, so its body is empty and the exit tests watch the card deletion and a test hook counting exits). The guard's cleanup runs in a spawned task, as `CloneGuard`'s does.

### The persona's links (`src/personas/links.rs`)

`absolute(body, dir) -> String`: pulldown-cmark's offset iterator finds each `Link` and `Image` (inline, and reference definitions through `reference_definitions()`), and each destination that is relative (no scheme, not starting with `/` or `#`) is replaced in the source text by `dir` joined with it, `..` and `.` resolved lexically and a `#fragment` kept; anything resolving above `/workspace/<dir>` is left as written. The rest of the body is byte-for-byte unchanged. Tests: inline, reference-style, image, angle-bracketed, with a title, a fragment-only link, an absolute URL, `../../docs/x.md`, one escaping the checkout, and links inside code spans and blocks (not links, left alone).

### The system prompt (`src/turn/history.rs`)

`PromptEnvironment` gets `agent: Option<AgentPrompt>` (parent id, the persona snapshot). For a child, the Environment section adds "- You are agent #N, started by conversation #P (your parent) with the brief that starts this conversation. Call finish with your report when your work is done; the user can also write to you." With a persona, a `# Persona` section goes before the Project instructions: a line saying what it is ("Your persona, `<dir>:<name>` from <path> at <commit7>, read when you started; a later change to the file doesn't change it"), then the body.

### The queue and its drain

`drain_agent_messages(pool, id, &mut pending_new_content, &mut persisted)` in `turn/notify.rs`, called in `run_turn_steps` after the two command drains, every iteration. For each undelivered row to `id` in `id` order, one transaction (`db::deliver_agent_message`): the recipient's row `FOR NO KEY UPDATE` (the lock `create_message_on`'s `updated_at` write takes anyway, taken first: lock table), `UPDATE agent_messages SET delivered_at = now() WHERE id = $1 AND delivered_at IS NULL` (0 rows → skip), the `user` message (`create_message_on`), `delivered_message_id` set. Text: a report is "Report from <from_label>:\n\n<body>"; a notice "Notice: <body>". `db::wake_has_work` adds `OR EXISTS (SELECT 1 FROM agent_messages WHERE to_conversation_id = $1 AND delivered_at IS NULL)`.

### Admission, Stop and the end of a turn

- `start_turn` and `answer_question` call `agents::admit_user_turn(pool, id)` before `TurnInFlight::start_by_user`: no `agents` row → on; `starting` → refused "This agent is still starting."; `failed` → "This agent's start failed; start a new one."; `stopped` with `started_at IS NULL` → "This agent was stopped while it was starting; start a new one."; `finished` or `stopped` (started) → `UPDATE … SET state = 'active' WHERE … AND state IN ('finished','stopped') AND started_at IS NOT NULL`, then on; `active` → on.
- `wake_conversation` and `deliver_notice`: for a `starting` child (`db::agent_state`), a wake returns without a turn and a delivered notice is only saved (`save_notice_between_turns`), checked before the admission. The only notice that can reach a starting child is the pod watch's (Docker restarting); saving it keeps it for the first turn.
- `stop_turn` (the user's Stop): a `starting` child → refused, "This agent is still starting: stop it with stop_agent from its parent, or delete it." Otherwise as today, and for an `active` child not already paused (`is_paused` read before the stop), `agents::user_stopped` queues a notice to the parent ("the user stopped agent #N; it carries on if the user writes to it, or call stop_agent to end it") and wakes it.
- **The end of a turn** (`run_turn_bounded`): after the turn's result, `drop(in_flight)`, then unless the result was `Stopped`, `if !turn_running(id)` spawn `agents::after_last_turn(pool, id, failure_text)`. It reads in one query: the child is `active`, no unanswered `pending_questions` row, no `instruction_requests` card, no `running` terminal command, no `starting`/`active` child of its own; and `!is_paused(id)`. All hold → a notice to the parent: "agent #N's turn ended without a report[ (it failed: <error>)]; its last message: <first 500 characters of its last assistant text>", and a wake. A user conversation (no `agents` row) does nothing.

### Deleting a subtree (`src/agents/delete.rs`)

`delete_and_forget` (still in its own task, SME-262) calls `agents::delete_subtree(pool, id)`:

1. Transaction A: the group's root (recursive CTE up `parent_id` from `id`), its row `FOR NO KEY UPDATE` (the lock `start_agent` takes); the subtree's ids (CTE down from `id`); `UPDATE conversations SET deleting_at = now() WHERE id = ANY($subtree)`; `UPDATE agents SET state = 'stopped' WHERE conversation_id = ANY($subtree) AND state IN ('starting','active','finished')`. Commit. A `start_agent` committed before A's lock is in the subtree; one after it is refused (`deleting_at`).
2. For every subtree id: `stop_turn_now`, `browsing::close_session`, and its pod ids listed (as today, best-effort).
3. Transaction B: the deleted conversation's parent's row (if any) `FOR KEY SHARE`, then the subtree's rows `FOR UPDATE`, all in ascending id order (a parent's id is always smaller than its children's); with a parent, insert the `notice` to it ("the user deleted agent #N"); `DELETE FROM conversations WHERE id = $id` (the cascade removes the subtree). Commit; wake the parent.
4. For every subtree id: `teardown_conversation(pool, id, &its_pod_ids)`, `events::forget`, `forget_conversation_lock`; then `PodsChanged` and `ConversationsChanged` once.

The sidebar: `Conversation.parent_id` comes with every listed conversation, so the sidebar counts a row's descendants from the list it already has; the Delete's armed label is "Confirm?" for none and "Delete + N agents?" otherwise. Where it sits: the same two-step button, same place; the label is at most "Delete + 99 agents?", which at the phone width (390px, the sidebar full-width) and at the laptop sidebar's width fits on one line beside the age (the browser scenario measures the row has no horizontal overflow at 390px and at 1400px with that label).
