## What, and why a counter

A turn compacts whenever the next request is projected past the trigger (`run.rs:326` → `CompactionProgress::step`). SME-386's machinery judges **what one compaction leaves**: `measured()` marks a result *tight* when it sits less than 4,096 under the trigger, two in a row move the trigger out to `limit`; `at_limit` and the refusal cap catch the rest. None of them counts **the pattern**. The surviving shape: each compaction leaves *just* enough room to clear `tight` (measured input ≤ trigger − 4,096 clears it, `compaction_progress.rs:265`), and every model step — a big tool result — pushes the projection back over the trigger. Compaction → step → compaction → step, bounded only by `MAX_TURNS` (`run.rs:13`, 10,000). Nothing on the `tight`/`at_limit`/`refusal` paths fires: no result is tight, none near `limit`, no refusal happens — the steps are accepted and the summaries are paid.

Raising `MIN_ROOM_TO_WORK` cannot fix this: no constant room bounds the next tool result — any room is smaller than a `cat` of a big enough file. The only actor who can shrink a step is the model, so the fix is the ticket's: **count the loop shape, tell the model, then stop** — and tell the model when a tool result was summarized before it ever read it (the loop's usual cause).

Main's own `test_compactions_that_leave_real_room_go_on_as_often_as_needed` (`src/turn/tests/compaction_progress.rs`) *is* this shape — eight compactions, one step between each — and must stay green: the fix bounds and warns, it does not forbid. (SME-386's worst real ask ran 11 compactions over 9 steps.)

## Mechanism — state model (all in `CompactionProgress`)

Conversation runtime, in-memory like every compaction fact today: survives turns and wakes (`with_compaction_progress`), gone on restart/delete, same lifetime and same readers as today's `stuck`. Nothing new is persisted; there is no DB change.

New fields: `steps_since_compaction: u32`, `thrash: u32`, `thrash_noticed: bool`, `thrashing: bool` (armed).

Transitions (writers are the existing call sites; `run.rs` and `reply.rs` call these already):

- `step_taken()` (accepted model call, `run.rs:375`): `steps_since_compaction += 1`.
- `compacted()` (any compaction ran — proactive, floor, refusal-answering): if `steps_since_compaction == 1` then `thrash += 1`; if `>= 2` then `thrash = 0` (two worked steps = the room is being used, the run starts over); if `== 0` leave `thrash` alone — refusal-answering and recovery chains are `MAX_REFUSAL_COMPACTIONS`' job, not this one. Reset `steps_since_compaction = 0`. No counting under a guess (`guess.is_some()`): nothing is learned against a guess.
- `step()` (the pre-call decision): after today's `stuck` short-circuit, before the trigger logic: if `thrashing` → `Stuck(why_armed())`; else if `thrash >= END_AT` → set `thrashing`, `Stuck(why_thrashed())` (skip under a guess, as `tight` is). No new `CompactionStep` variant — this keeps `tests/escape.rs` compiling and running **unchanged** (its `World` maps `Stuck` to a failed turn already, and a counter that only grows after an accepted step cannot fail a fitting send before `took` moves, so both invariants hold structurally).
- The notice: at the compaction event where `thrash == NOTICE_AT`, set `thrash_noticed`. `run.rs`, right after `p.compacted(...)` (the `CompactionStep::Compact` arm, and after the floor/refusal compactions likewise), reads `p.take_thrash_notice()` — an accessor mirroring how `carries_on` is read — and on `Some` saves a `mark_notice`-marked text into the transcript via `save_notice` (`reply.rs:552`, which also pushes it into `pending_new_content`, so the next request carries it). Marking it (SME-357) keeps a later compaction quoting it to the model as typed words.
- `is_stuck()` returns `stuck || thrashing`, so a root wake's failure is told once (`run_turn_body`'s `doesnt_fit`, and `already_said` dedupes on the identical text — `why_armed()` must therefore name **no numbers** that change).
- `why_stuck()` grows a `thrashing` branch with its own wording — it must not read like "too small" (the conversation *does* fit; the steps don't).
- Clears: `user_wrote()` → `thrash = 0`, `thrash_noticed = false`, `thrashing = false` (full clear, not the `at_limit` cap: thrash is not "doesn't fit"; the user's send gets fresh runway, and the escape property's sends-that-fit need it). Window change: `sync`'s whole-reset already clears everything. Entering a guess (`forget_measures`): clears `thrash`/`thrash_noticed`; `thrashing` survives, like `refused_out`. A message queued to the conversation by `message_agent` (either agent direction): clear via a new `turn::clear_compaction_thrash(id)` called from `agents/messages.rs` after `MessageOutcome::Queued`/`Answered` — an agent's operator is its parent, and an armed child must still read its parent (Q-D2 below; ordinary wakes, which don't call it, stay cheap-stopped).

Partials: `take_thrash_notice` is take-one-shot; a `save_notice` INSERT failure ends the turn like every other saved-message failure does. No other writer.

Constants: `NOTICE_AT = 12` (above the 8-step guard test and above F11's real 11), `END_AT` by the user's answer (below). Keep them `pub(super)` and re-export beside `MIN_USEFUL_REPLY` (`turn/mod.rs:39`) so turn tests read them instead of literals.

Draft texts (Developer may polish; tests pin the marked phrases, not whole sentences):

- Model notice (transcript, grey): "smelt notice: this turn has compacted {n} times in a row — each step is bigger than the room a compaction leaves. Keep the next steps small: read files with offset/limit, one at a time, and don't re-read whole files. Smelt stops the turn if the loop keeps up." (Marker phrase: `bigger than the room a compaction leaves`.)
- Turn-end (failure notice, user): "`{model}` was asked for work whose every step was bigger than the room a compaction left: {END_AT} compactions in a row, one step between each. The turn ends rather than keep paying for summaries — the conversation still fits; it is the steps that don't. Ask for the work in smaller pieces (read with offset/limit, one file at a time), give the model a larger context window, or start a fresh conversation." (Marker: `one step between each`.)
- Armed short-stop (wake): "`{model}`'s turn was stopped for compacting after every step and will not try again until someone writes to this conversation. Break the work into smaller steps or pick a larger window." (Number-free, so `already_said` dedupes.)

## At the threshold: end vs keep going (the user's question — one switch site)

All three answers land on the counter/notice core above. The switch is a single small function — `fn thrash_answer(count) -> EndAt | ClampAndEndAt` — plus whether the clamp is on:

| At `NOTICE_AT` (12) | A — end | B — keep going with smaller steps | **C — hybrid (recommended)** |
|---|---|---|---|
| model notice + transcript telling | yes | yes | yes |
| reply budget held to room (`room_only() ||` clamp, as `tight` does) | — | yes, from now on | one grace cycle |
| turn ends (`Stuck(why_thrashed)`) | at 12 | at 24 | at 13 (the grace cycle is the last compaction) |
| worst-case compactions per arming | 12 | 24 | 13 |

Worth saying plainly in the plan: smelt cannot cap **tool-result** sizes — the only size it controls is the reply budget. "Keep going with smaller steps" is the notice asking the model to shrink its calls (offset/limit), the clamped budget keeping its own writes inside the room, and the hard cap bounding the case where it doesn't listen. Truncating tool outputs globally is out of scope (different ticket, different blast radius).

Recommendation to the user: **C** — one grace cycle at 12 (notice + clamped budget), end at 13. It cannot stall (hard bound), preserves F11-scale real asks in full, and matches "keep going with smaller steps" for exactly the one step where the model's compliance is likeliest.

## Scenario 2 — a tool result compacted before it was read (decision: ships in this PR)

Confirmed in code: requests are built from the DB history alone (`reply.rs:18`); the result blocks `run_tools` saves (`run.rs:476`) are in the covered tail, and `compact` covers through the last message — so a compaction at the next iteration summarizes the results **before the model ever reads them**; the continuation quotes only text tails (`unanswered_user_text` "Tool results aren't included"), and `compaction_transcript` keeps the newest content when cutting, so the summary may only gesture at the result. The model re-runs the call, the loop repeats.

Fix: `continuation.rs` gains `unread_tool_results(messages)` — the `ToolResult` blocks in user messages after the last assistant message, each named by matching its `tool_use_id` to the tool_use block in that assistant reply — and `continuation_prompt` takes them and adds a capped section (first 8, then "(and N more)") between the pinned todos (SME-462) and the unanswered tail (which stays last): "These results from your own calls were summarized above before you read them: {names}. Don't assume you saw them; if you still need what's in one, re-run the call narrowly (an offset, a limit, a filter) rather than whole." The raw results are **not** quoted (that would undo the compaction). `compact` computes and passes them; existing call sites (`tests/history.rs`, `tests/transcript.rs`, `tests/compaction_honesty.rs`, `continuation_prompt` unit uses) gain the argument. `ask_user`/`ask_parent` answers are ToolResults in that tail too — they are listed like any other (the typed-quotes path excludes the tail, so no duplication). Ships here because it is one small function plus a section, and it's the same loop's other half; splitting it costs a second branch through review for a dozen lines. ## Trade-offs to flag

- A genuinely productive run whose every step compacts gets told to break its work after 12 in a row, and its turn ends at 12–24 by the user's answer (worst recorded real ask: 11 compactions / 9 steps — F11). The notice + grace exist to keep such asks moving; a reset happens naturally the moment a run puts two worked steps between compactions.
- After a thrash stop, wakes don't retry anything until someone writes or a message queues (the wake invariant says background loops stop paying; the parent-message clear keeps agents operable). A user's send always gets a fresh full try.
- Every continuation that follows a compaction covering unread results gains a short "you never read these" section — a few lines, capped at 8 names; conversations without that shape see no change.
