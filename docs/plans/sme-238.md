## What

Scope item 2 of the project, on SME-236's queue:

1. **`message_agent(to, text)`**: a parent and its child message each other at any time. Queued in `agent_messages` (kind `message`), woken with `Notice::Wake`, drained as `Message from agent #12 (smelt:developer):` / `Message from your parent:`. A message to a `finished` child makes it `active` in the same transaction.
2. **`ask_parent(question)`**: a child asks and its turn ends; the parent's next `message_agent` to it is the answer (the call's result), and wakes it. A child waiting for its parent is not "waiting for the user" anywhere.
3. **The stored pause**, `conversations.paused_at`: a Stop's pause survives a restart, for every conversation, and the startup sweep no longer wakes one the user paused.
4. **Restart notices**: a child cut off mid-turn gets `smelt restarted during your turn; carry on` and a wake. The user's Stop on a child already tells the parent (SME-236's `agents::user_stop`); this ticket makes that notice survive a restart only in that the pause does.

## How

### `message_agent(to, text)`

Input: `to` is `"parent"` or a child's id (a JSON string of digits or an integer); `text` is 1–30,000 characters. Offered (`Offer::Linked`) to a conversation with a parent or at least one child row; `execute` checks the same from the database.

`db::message_agent(pool, caller, to, label, text) -> MessageOutcome`, one transaction:

1. Resolve the recipient: `parent` is the caller's `parent_id` (none: refused, "you have no parent"); an id must be a conversation whose `parent_id` is the caller (else refused, "#N isn't one of your agents", the same as `stop_agent`'s, so a sibling or any other id is refused without saying whether it exists).
2. `lock_conversations([(caller, KeyShare), (recipient, KeyShare)])`, ascending id, as every agents transaction does. A gone row: refused, "agent #N was deleted".
3. The recipient's `deleting_at` set: refused as deleted.
4. The recipient's `agents` row, `SELECT state … FOR NO KEY UPDATE` (the design said `FOR SHARE`; `FOR SHARE` then the `finished → active` `UPDATE` would upgrade the lock, and two messages to one finished child would deadlock on it). A root parent has no row and is always a valid recipient.
   - `stopped`, `failed`: refused ("agent #N is stopped; it takes no messages unless the user writes to it" / "agent #N's start failed").
   - `finished`: `UPDATE agents SET state = 'active' … WHERE state = 'finished'` (SME-245 adds its "agents at once" check here, under the root's lock).
   - `starting`, `active`: as is.
5. A parent's message to a child waiting for it: `UPDATE pending_questions SET answer = $json WHERE conversation_id = child AND asked_of = 'parent' AND answer IS NULL`. One row: the answer is recorded, and nothing is queued. Zero rows (no question, already answered, or the user's message took it first): falls through.
6. Otherwise `queue_agent_message(recipient, Some(caller), label, KIND_MESSAGE, text)`. `label` is the caller's `label_of` for a message to the parent, `your parent` for one to a child.
7. Commit, then `turn::notify(recipient, [Wake])`.

The caller's own state isn't locked: its turn is running, and a `stop_agent` landing on it ends that turn; a message it queued just before is harmless. Results: `Sent to agent #12.`, `Sent to your parent.`, `Agent #12 was waiting for your answer: it has it now.`

**`finish` waits for its messages.** A child whose parent messaged it during its last turn and which then calls `finish` would be `finished` with the message still queued; the wake runs a turn on it, but `finish` would be refused (already finished), so its parent never hears. So `finish_agent` refuses, in its own transaction after its `UPDATE` holds the child's row, while an undelivered `message` or `question` row is queued to the child: `a message arrived since your last step; read it, then finish` (the turn goes on, and its next iteration drains it). The two writes serialize on the child's `agents` row (`message_agent`'s `FOR NO KEY UPDATE`, `finish`'s `UPDATE`).

### `ask_parent(question)`

Input: `question`, 1–30,000 characters. Offered to a child (`Offer::Child`). Handled in `run_tools`' first loop with `ask_user`: one question of either kind per reply (a second is refused, as a second `ask_user` is today). `db::ask_parent(pool, child, tool_use_id, question, label)`, one transaction: `lock_conversations([(parent, KeyShare), (child, KeyShare)])`; the child's `agents` row `FOR SHARE`, which must be `active` (else refused, so a stop that landed first wins); the parent mustn't be `deleting_at`, nor a `stopped` or `failed` agent; `pending_questions` upserted with `asked_of = 'parent'`, `questions = [{question, header: "Question for your parent"}]`; and `queue_agent_message(parent, Some(child), label, KIND_QUESTION, question)`. Commit, wake the parent. No `QuestionUpdate` is published (no card); `QuestionsChanged` isn't either. A refusal is the call's error result and the turn goes on.

The parent reads `Question from agent #12 (smelt:developer), which waits for your answer (reply with message_agent to 12):\n\n<question>`. Its `message_agent` records the answer (step 5 above) as `[{"selected": [], "other": text}]`; the child's wake takes it through the existing `take_answer_or_wait` → `create_message_taking_question`, and `question_result` words it by `asked_of`: `Your parent answered:\n\n<text>`; taken by the user's own message, `Your parent hasn't answered; the user wrote to you instead, and their message follows. A later reply from your parent arrives as a message.`

**Every reader that means "the user is asked" filters `asked_of = 'user'`:** `db::list_waiting_conversations` (`/api/questions/waiting`, the sidebar's "?"), `turn::pending_question` (`/api/conversations/{id}/question`, the card's snapshot), `answer_question` and `db::answer_pending_question` (the card can't answer a parent's question, even by a crafted request), and `list_child_agents`' `waiting_for_user`. Readers of any question, unchanged: `take_answer_or_wait`, `wake_has_work`, `idle_agent_without_report` (a child waiting for its parent ended its turn on purpose: no "ended without a report" notice).

### The stored pause

The in-memory `paused` stays the source of truth while smelt runs: it is decided in the same critical section as a turn's admission (SME-216, SME-217), which a database read can't join. `paused_at` mirrors it for the next start:

- **Written** by `turn::store_pause(pool, id)`: reads `is_paused(id)`, writes it (`UPDATE conversations SET paused_at = CASE WHEN $2 THEN COALESCE(paused_at, now()) END WHERE id = $1`), then reads `is_paused` again and repeats while it changed, up to 8 times (then a `warn`). The last writer's loop sees the last value, so a Stop and a send racing can't leave the row disagreeing with memory. Called by `stop_conversation` (the user's Stop through `agents::user_stop`, and `stop_agent`), after `stop_turn_now`; by `start_turn` and `answer_question`, after `TurnInFlight::start_by_user`. The delete's `stop_turn_now` doesn't need it (the row goes). A failed write is logged; memory is still right for this run.
- **Read** once, at startup: `turn::restore_pauses(pool)` sets `paused` for every `paused_at IS NOT NULL` row, awaited in `main.rs` before the pod watch, the idle-command watch and the agent sweep are spawned (the three things that can wake a conversation before a request does). The sweep's own queries also skip `paused_at IS NOT NULL`, so a failed restore can't make the sweep wake one. A failed restore is logged; the idle-command watch could then wake a paused conversation once (as before this ticket).

### Restart notices

In `agents::startup_sweep`, after failing the cut-off starts and before the wakes: `db::cut_off_agents(pool)` lists agents `active`, `paused_at IS NULL`, `deleting_at IS NULL`, whose last message is `role = 'user'`, with no unanswered question and no undelivered restart notice already queued (so two restarts in a row queue one). Each gets `queue_agent_message(child, None, "smelt", KIND_NOTICE, "smelt restarted during your turn; carry on")`. The wake step then wakes it, since it now has an undelivered row. The wake list (`conversations_with_queued_messages`) also includes agents with an answered question and no turn: the parent's answer recorded just before a restart would otherwise wait for good. A user's own conversation is left as today.

## State model

### State × event, for a conversation in a group

The design's table, finished. **New** marks what this ticket changes; everything else is SME-236's and is already tested.

| State ↓ / event → | Message from parent or child | Child's question (this is the parent) | Parent's reply to a question | User's Stop on this | `stop_agent` on this | User writes in this | smelt restarts | `finish` |
| -- | -- | -- | -- | -- | -- | -- | -- | -- |
| starting | **queued**; the start's done step wakes it | — | — | refused | stopped | refused | sweep fails it; the queued row stays, never drained | — |
| idle (active) | **queued, wakes, runs a turn** | **queued, wakes** | — | paused (**stored**); parent told | stopped (**stored pause**) | turn runs | **sweep wakes it if queued** | — |
| running | **taken at the next iteration** | **taken at the next iteration** | — | turn ends, paused; parent told | turn ends, stopped | queued behind the turn | **turn lost; restart notice and wake** | **refused while a message or answer is queued**; else finished |
| paused | **queued, no wake** (the paused finished child: **active, queued, no wake**) | **queued, no wake** | **recorded, no wake; the user's next message takes it first** | stays | stopped | pause ends (**stored**), turn drains | **stays paused (stored)** | — |
| waiting for the user | **queued; the woken turn saves it and waits on** | as left | — | paused | stopped | takes the question | unchanged | — |
| waiting for its parent | **the reply is the answer; wakes** | as left | **answer recorded, wakes, the turn takes it** | paused | stopped; the reply is **refused** | **takes it with `NOT_ANSWERED_BY_PARENT`; a later reply is a plain message** | **unchanged; an answer recorded before is woken by the sweep** | — |
| finished | **active, queued, wakes** | — | — | paused | stopped | active, turn runs | unchanged | refused |
| stopped | **refused** | **queued, no wake** | refused | stays | already | active (started) or refused (stopped while starting) | unchanged | refused |
| failed | **refused** | — | — | — | already ended | refused | unchanged | — |
| deleted | **refused** ("deleted") | rows cascade | refused | — | — | — | — | — |

"Its parent deleted" and "this deleted" are SME-236's (deleted with it; parent told) and unchanged. Waiting for a provider slot is unchanged (status running).

### What each writer does and what can change between its check and its act

| Writer | Locks, in order | Checked | Can change between check and act | Holds because |
| -- | -- | -- | -- | -- |
| `message_agent` | caller, recipient `conversations` `KEY SHARE` (ascending); recipient `agents` `NO KEY UPDATE`; `pending_questions` row (`UPDATE`); `agent_messages` insert | parent/child relation, `deleting_at`, state, a waiting question | `stop_agent` (`UPDATE agents`), a delete (A: `UPDATE agents`; B: `FOR UPDATE` on rows), `finish`, the child's user turn deleting the question | state is read under the row lock `stop_agent`/`finish`/delete A must take; delete B's `FOR UPDATE` waits on the `KEY SHARE`; the question `UPDATE … answer IS NULL` re-checks after a concurrent `DELETE` (0 rows → queued as a message) |
| `ask_parent` | parent, child `KEY SHARE`; child `agents` `FOR SHARE`; `pending_questions` upsert; insert | child `active`, parent live | `stop_agent` on the child | the `FOR SHARE` waits for / blocks the stop's `UPDATE`; a stop after commit ends the turn, and the parent's reply is then refused |
| `finish_agent` (changed) | parent, child `KEY SHARE`; `UPDATE agents` (child) | `active`, **no undelivered `message`/`question` row, no answered question** | `message_agent` queueing | `message_agent` holds the child's `agents` row while it inserts; `finish`'s check is a statement after its `UPDATE` got the row, so it sees a committed insert |
| drain (`deliver_agent_message`) | recipient `NO KEY UPDATE`; row mark | undelivered | a Stop | mark and save in one transaction (SME-91), unchanged |
| `store_pause` | `conversations` row (one `UPDATE`) | memory's value | a Stop or a send | re-read and repeat until unchanged |
| restart sweep | per row, one insert | cut off, no notice queued | nothing: runs before requests and watchers | runs once at startup |

**Deadlocks.** `message_agent` and `ask_parent` hold at most one `agents` row each, after `conversations` locks that are all `KEY SHARE`; `stop_subtree` and delete A update several `agents` rows but hold no lock either transaction waits on first except compatible `KEY SHARE`. Delete B takes `FOR UPDATE` on `conversations` rows in ascending id and waits behind `message_agent`'s `KEY SHARE` without holding an `agents` row `message_agent` wants. So no cycle; the tests below run each pair in both orders.

| -- | -- | -- | -- | -- |
