# SME-450: a wake waiting for a provider slot is lost when the server restarts

**Branch:** `sme-450-restart-lost-wake` (from `origin/main` `6befbe32`; in the one clone at `/workspace/smelt`, per rules.md's conversation-sandbox section).

## What, and the mechanism

The seat's conversation sat for hours with a "Terminal command … finished: exit code 0" notice saved and no turn after it. The ticket infers a **saved but undrained** notice that nothing re-woke. The code says otherwise: **the notice had already been drained, saved and marked, by the wake that then died waiting for the slot.** Traced:

1. The command's end calls `turn::notify(Wake)` (`src/sandbox/agent.rs:821`), which spawns a task: `wake_conversation` → `db::wake_has_work` (true: the command is `finished` and `notified_at IS NULL`) → `TurnInFlight::start_unless_paused` → `run_turn_bounded(None)` → takes the turn lock (the seat had no turn running).
2. `run_turn_steps` (`src/turn/run.rs:216–290`), first loop iteration: `take_answer_or_wait`, then the three drains. `drain_unnotified_terminal_commands` calls `db::save_command_notice`, which in **one transaction** sets `terminal_commands.notified_at` and inserts the `user` notice message (`src/db/sandbox.rs:777–799`). Committed.
3. Only then does it resolve the model and call `TurnSlot::acquire` (`run.rs:284–290`), which awaits the provider's semaphore (`providers/limiter.rs` `Pool::acquire`). Strata has one slot; the deployer seat's turn held it (SME-343 holds a slot for the whole turn). The wake parks here, holding the turn lock, with the notice saved and marked.
4. The restart drops that task. After it nothing owes anything that any startup path can see:
   - `db::wake_has_work` is false: the command is notified, no idle notice due, no answered question, no undelivered `agent_messages` row.
   - `startup_sweep` (`src/agents/sweep.rs`) wakes only `db::conversations_with_queued_messages`: undelivered `agent_messages`, or an agent's answered question.
   - `db::queue_restart_notices` (SME-238) covers an **active child** whose last message is a tool result, a *delivered `agent_messages` row* (matched through `delivered_message_id`), or a `tool_use` call. A command notice is none of these (a plain `user` text message with no link), so a turn parked on the slot after a command drain does **not** count as "mid-turn" there. It would count only if the drained notice were an agent message. And a root (non-agent) conversation is never covered: the query joins `agents`.
   - `reconnect_live_pods` (SME-359) wakes only for exits it delivers anew; this one was already recorded.
   - The ticket's own evidence agrees: a command's notice exists as a message only once a drain has saved it, so "the notice was saved, no turn followed" means it was drained.

**So the lost state is "saved and marked, never answered by a model turn".** The Driver's first trace was right. The fix below is for that mechanism.

The ticket's inferred state ("saved but undrained") is also reachable, through a narrower window: the restart lands after a command's end is recorded (`status = 'finished'`, `notified_at IS NULL`) but before its wake drains it. That covers a wake queued behind a running turn's lock, a turn in `wait_for_clones` (`run.rs:205`, before the drains), or the gap between the agent's frame and the spawned task. Nothing at startup wakes that one either. The startup sweep only looks at `agent_messages`, and `reconnect_live_pods` only at exits it hasn't recorded yet. The fix covers it too (part E).

## How

### A. A durable "answer owed" mark, set with each notice a turn takes

New column **`conversations.answer_owed_at TIMESTAMP NULL`**: *this conversation's turn has saved something for the model that the model hasn't answered yet.* It's durable, and it is set **in the same transaction** as the message it's for. That leaves no restart window between "saved and marked" and "owed".

- **Set** (`COALESCE(answer_owed_at, now())`) by one new helper, `db::create_owed_message_on(tx, conversation_id, content)`: `create_message_on` plus the update, in `src/db/owed.rs`. Its callers:
  - `db::save_command_notice` and `db::save_idle_notice` (`src/db/sandbox.rs`): their `create_message_on(&mut tx, …, "user", …)` becomes `create_owed_message_on(&mut tx, …)`. That's two one-line edits, about 30 bytes.
  - `db::deliver_agent_message` (`src/db/agents/mod.rs`): the same swap.
  - `db::create_message_taking_question` (`src/db/questions.rs`), when it takes an **answered** question and the message isn't the user's own (`from_user` false: the card's answer turn, a wake's `take_answer_or_wait`, a parent's reply). A user's own send dismissing or carrying the answer is not marked (D2).
- **Cleared** (`answer_owed_at = NULL`):
  - **in the transaction that saves the model's reply**: `save_reply`'s `db::create_message(…, "assistant", …)` (`src/turn/reply.rs:130`) becomes `db::save_reply_message(…)`, which inserts and clears together. Not in `create_message_on` generally: compaction re-saves assistant messages (`turn/compaction.rs:680`) before the model has answered anything, and tests fake replies through `create_message`.
  - **at every turn end, under the turn lock**: in `run_turn_body` once `run_turn_steps` returns, Ok or Err, before the failure note (`run.rs:102`); and in `run_turn_stoppable`'s stopped-mid-turn arm once it holds the lock again (`lifecycle.rs:324`). So a turn that tried and failed isn't retried by the next restart, nor by the next wake (D7). That keeps SME-386 L6's "a failing wake says nothing new" as it is. A failed clear only logs.
  - A panicking turn leaves the mark, and the next wake or restart answers it. That's the right recovery.

**Why this is "owed an answer", and safe.** Every setter holds the conversation's turn lock (the drains, the answer take and the save all run inside a turn). The turn-end clear also runs under the lock. So in a running server the mark is set only while the turn that set it is still in flight, and **a mark set with no turn running means a turn died without ending: a restart** (or a panic). The reply-transaction clear makes it exact: after a restart the mark is set only if something was saved after the model's last reply, so the history always ends in a `user` message the model hasn't seen. A restart between the final reply's insert and the turn's end leaves it cleared, never "owed" with an assistant message last.

- **Against the user's own message:** a user's send isn't marked (D2). A user's turn that *drained* a notice mid-turn is marked until the model's next reply. If a restart lands there, the notice is answered after the restart, which is the point.
- **Against SME-238's restart notice:** `queue_restart_notices` is unchanged. A child cut off mid-turn just after a drained agent message gets both the restart notice (queued) and the mark. The sweep wakes it once (deduped, part B). That wake drains the restart notice and calls the model once, and the reply clears the mark. A second wake for the same conversation finds the mark cleared under the lock (part C) and is a no-op. A restart notice that's queued and then delivered is itself an owed row (A sets the mark in `deliver_agent_message`), so two restarts in a row still answer once (`test_two_restarts_in_a_row_queue_one_notice` keeps passing).
- **No notice saved twice:** nothing re-saves anything. The startup wake drains only what's still unmarked; what was drained before the restart is already in the history, and the model reads it there.

### B. The startup sweep wakes what's owed

`startup_sweep` (`src/agents/sweep.rs`) wakes the **union** of `conversations_with_queued_messages` (as today), the new `db::conversations_owed_an_answer`, and the new `db::conversations_with_unnotified_ends` (part E). Each id is woken once (a `BTreeSet`), and every handle is returned, so `restart()` in the tests awaits them all. Both new queries live in `src/db/owed.rs`, with the same exclusions as the queued set: `paused_at IS NULL`, `deleting_at IS NULL`, and not an agent in `stopped`, `failed` or `starting` (the sweep fails `starting` ones before this runs; `admits_notices` re-checks at the wake). Both take root and agent conversations alike. The module doc of `sweep.rs` ("nothing wakes a conversation for what was queued to it before one") is rewritten.

### C. A wake runs for an owed answer, exactly once

- `wake_conversation` (`src/turn/notify.rs`): `db::wake_has_work` stays unchanged, keeping `src/db/sandbox.rs` edits minimal. When it returns `Ok(false)` and `!turn_running(id)`, the wake asks `db::answer_owed(pool, id)` and goes on if that's true. While a turn runs, the mark is that turn's own, so a spurious wake during it still isn't counted (SME-218 unchanged).
- `run_turn_steps` (`run.rs:260`): the early return `if is_wake && persisted.is_empty()` becomes `… && !db::answer_owed(pool, conversation_id).await?`. This check runs **under the turn lock** and is what makes a second wake for the same owed answer a no-op: the first wake's reply (or end) cleared the mark before the second could hold the lock. Errors propagate like the drains' do.
- The model is then called with the history as stored, which ends in the owed notice (or, after a cut-off tool call, in what `answer_unfinished_tool_calls` already handles). There's no new message to save, and `pending_new_content` is empty, so compaction's estimate uses the last real usage alone, as for any turn whose content is all in history.

### D. `Notice::Deliver` becomes durable: a queued row and a wake

`deliver_notice` (`notify.rs:44`):
- If the conversation doesn't admit notices (a starting, stopped or failed child) or is paused, it keeps today's immediate `save_notice_between_turns` (D4), so a stopped conversation still shows the notice in its transcript at once.
- Otherwise, `db::queue_server_notice(pool, conversation_id, &text)`: an `agent_messages` row with `from_label = 'smelt'`, `from_conversation_id NULL` and the new kind **`server_notice`**, whose body is the already-marked text, saved verbatim. Then `wake_conversation`, which `wake_has_work` already lets in for an undelivered row, and whose drain saves the row with the mark (A). If the insert fails, it falls back to today's path, so a database error costs only durability.
- `agent_message_text` gains `db::KIND_SERVER_NOTICE => row.body.clone()`, an arm before the `_` notice arm. The existing `notice` kind keeps its `Notice: {body}` wording, which `restart.rs`'s `NOTICE` pins.
- `unread_by` (the `finish` refusal) lists `message`, `question` and `report` only, so a queued server notice doesn't block a child's `finish`, the same as `notice` today.
- A restart while it waits for the lock: the row is undelivered, so the sweep's queued set wakes it.

### E. A recorded end whose wake never drained it

`db::conversations_with_unnotified_ends`: conversations with a `terminal_commands` row matching `UNNOTIFIED_END`, with B's exclusions. That predicate is made `pub(crate)` in `src/db/sandbox.rs`, a one-word edit, so the rule stays in one place. The startup wake drains it as any wake would.

## State model

**`conversations.answer_owed_at`**: `NULL` (nothing owed) ↔ set (owed).

| Transition | By | Under | If it fails partway |
|---|---|---|---|
| NULL → set | a drain's save (command, idle, agent message, server notice), or an answer taken for a non-user turn | the turn lock, in the save's own transaction | the transaction rolls back: neither the message nor the mark (the SME-91 discipline, unchanged) |
| set → NULL | the model's reply saved | the turn lock, in the reply's transaction | neither the reply nor the clear; the turn fails and the turn-end clear runs |
| set → NULL | the turn ends (Ok, Err, Stop) | the turn lock | logged; the mark stays, so the next restart, or the next wake, answers it once (a recovery, not a duplicate: nothing is re-saved) |
| stays set | a restart or a panic | — | that's the point: the startup sweep (B) or the next wake (C) answers it |

Readers: `wake_conversation` (only when no turn runs), `run_turn_steps`' empty-wake check (under the lock), and the startup sweep. No UI reads it, so SME-441's sidebar is untouched.

**What each caller does:**

| | Turn running in it | No turn, mark set | No turn, mark clear |
|---|---|---|---|
| A wake with pending work | queued behind it, drains | runs; drains, calls the model | runs |
| A wake with nothing pending | not counted (SME-218) | runs; calls the model on history | not counted |
| The startup sweep | — (nothing runs at startup) | wakes it | wakes it only if it's queued or has an unnotified end |
| A user's send | queued behind it | runs; its reply clears the mark | runs |
| Stop | ends it; clears | (no turn to stop); paused, so the sweep skips it; the user's next send answers it | — |

**A row for work already in flight:** a turn running when this ships ends under the old binary. The deploy that ships it is itself a restart, and conversations cut off by it have no mark (the column is new), so the first deploy can't rescue the turn it interrupts. Every later one can.

## Tests (TDD; each red first on unfixed code, red output recorded beside its prediction)

All of them go in **`src/agents/tests/restart_owed.rs`** (new; a `mod restart_owed;` line in `src/agents/tests/mod.rs`), using `setup`, `restart()`, `requests_for`, `transcript` and `active_child` from `mod.rs`. Each restart is `restart()`, which forgets turn state, restores pauses and **awaits every wake the sweep returns**, so the asserts after it need no waiting. Each in-memory wait is ended the way a process death ends it: `JoinHandle::abort()` on the `notify` task, awaited until it's cancelled. Pools are rebuilt as on a fresh process with `providers::limiter::forget(provider)`. There are no sleeps and no new timeouts: each step waits on a hook or a handle.

## Decided (Driver)

Recorded as the Planner's recommendation; the Ticket Driver may override.

- **D1, the mechanism:** "saved and marked, never answered", not the ticket's "saved but undrained". The ticket's state is real but narrower, and is fixed too (E).
- **D2, the user's own send isn't marked:** a send that a restart caught on the lock or the slot stays unanswered, as today and as SME-238 left a root. The user is there and sees no reply; a notice has no one watching. Marking it would cost one more call site (`save_turn_message`'s `from_user` branch); left out deliberately.
- **D3, `Deliver` rides the existing `agent_messages` queue** with a new `server_notice` kind (verbatim body), not a new table. The queue, its drain, its sweep and its SME-91 transaction already exist.
- **D4, a `Deliver` to a paused or not-admitted conversation is saved at once**, as today, not queued. A stopped child's transcript still shows "Docker restarted" when it happens.
- **D5, a `Deliver` that lands during a turn is now taken at that turn's next iteration**, like an agent message (the design's "a busy recipient takes them between a tool result and its next call"). Today it waits for the turn to end and then starts a turn of its own. The model learns sooner, and a turn is saved.
- **D6, `Notice::Save` and a root's untaken card answer are filed**, not fixed: one new Maintenance ticket, Low, related to SME-450.
- **D7, a turn's end clears the mark whatever its outcome**, so a restart answers only what a restart dropped, not every failed turn.
- **D9 (decided during implementation), a Stop that ends or refuses a queued `Deliver`'s wake still saves it at once:** `deliver_notice` saves that conversation's undelivered `server_notice` rows, and only those, under the turn lock through `deliver_agent_message`, with no model call. Without it SME-217 E2 (`turn::tests::stop_gaps::test_a_stop_as_a_delivery_is_let_in_ends_it`) went red; this keeps the behaviour from before D, as D4 does. Since review 1 (L1), those rows set no answer-owed mark: no turn follows.
- **D10 (review 1, L2), a `Deliver` whose wake stops at a question still waiting is saved at once too,** owing nothing, as before D; otherwise it stayed out of the transcript until the question resolved.
- **D11 (review 1, L5), E wakes only ends recorded in the last 24 hours** (`finished_at`): an older undrained end is a wake lost long before the restart, and the first deploy would otherwise run a turn in every such old conversation.
- **D8, T1's slot holder is a `Slot` taken from the pool** (what a turn's `TurnSlot` holds), not a gated real turn. If the Driver wants a real turn, `turn/tests/turn_slot.rs`'s `start_slot_gate` does it, at the cost of moving that helper to a shared test module.

## Trade-offs to flag

- **The deploy that ships this rescues only part of what it interrupts.** The mark is new, so a turn cut off after its drain has none; but E wakes a conversation whose command end, recorded in the last 24 hours, was never drained (D11). Every later restart is covered.
- **A root cut off mid-turn just after a drained notice is resumed** with no "smelt restarted" line (SME-238's notice is for children). It sees its history and the notice, and carries on. A root cut off mid-turn with nothing drained since its last reply is left as today.
- **Every restart wakes every owed conversation at once.** On a one-slot provider they queue for the slot, first come, first served, as live wakes do.
