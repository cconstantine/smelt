# SME-290 — a reply whose only text is leaked `<think>` reasoning gets SME-286's nudge

**Branch:** `sme-290-leaked-think-nudge` (cut from `origin/main` at `79c25f67`). Like SME-286's, this file is removed from the branch before the merge.

## What and why

SME-286 nudges a reply with no text and no tool call (thinking only, or empty) so the
turn doesn't end silently. `turn::reply::after_reply` decides "no text" at
`src/turn/reply.rs:410`:

```rust
let has_text = turn.content.iter().any(|b| matches!(b, anthropic::ContentBlock::Text { text } if !text.trim().is_empty()));
```

— any non-blank text block counts. A provider that leaks its reasoning into the text
channel (the ticket's `strata`; conversation 2294639357 is the evidence) can reply with
`<think>…</think>` as its only text. `has_text` is then true, and the turn ends silently
— exactly the thinking-only case SME-286 meant to cover. Review 2 of SME-286 accepted
that as by design for that ticket and filed this one (finding 4).

The fix: let `has_text` see the text with leaked reasoning masked — the *same* rule
`text_calls::mask_code` has used since 7235f27 (a `<think>` at a line's start, indent
≤ 3 spaces, up to the `</think>` that closes it; one elsewhere, or never closed, is
text, so prose can never blank the rest of a reply). The rule stays in one place.

## The fix

1. **`src/text_calls.rs`** — split the shared rule out of `mask_code`:
   - `fn think_ranges(text: &str) -> Vec<(usize, usize)>` — private, server-gated: the
     scan `mask_code` does today at `:294`–`:313`, returned as the byte ranges to blank
     (tags included).
   - `pub fn mask_think(text: &str) -> String` — server-gated like its neighbours:
     `text` with exactly those ranges blanked (spaces; newlines kept, same length), and
     nothing else masked.
   - `mask_code` blanks `think_ranges`' ranges through its existing `blank` closure,
     then runs its fence/paragraph passes over the raw `text` into the same buffer —
     the order it has today — so `find`'s behaviour is **byte-identical**. The existing
     think tests (`src/text_calls/tests.rs:241`, `:281`) guard this and must stay
     green with no change. One rule, two callers (the ticket's constraint).
2. **`src/turn/reply.rs`** — `has_text` becomes
   `!crate::text_calls::mask_think(text).trim().is_empty()` per text block, and
   `after_reply`'s doc comment gains the reasoning-only case next to "thinking only,
   or empty". Everything else in `after_reply` is as today: the reply is still saved
   verbatim (`save_reply`'s `without_blank_text` still sees the raw block), the nudge
   is the same marked `EMPTY_REPLY_NOTICE`, and a second such reply before a real
   call still ends the turn (`streak.nudged`).

Why `mask_think` and not `mask_code` for this decision: only leaked reasoning is
"not the reply". A reply that is only a fenced code block, an indented block or a
blockquote *is* an answer; `mask_code`'s other masks must not decide this.

## What this plan settles

- **Unclosed `<think>` (open, never closed): text — no nudge.** Explicit decision.
  The rule is reused whole, and that is its point: SME-286 review 2 narrowed it to
  closed ranges precisely so a `<think>` named in prose could not blank a real reply
  (finding 2, 7235f27). Blanking to the reply's end when no `</think>` exists would
  reopen that bug — prose starting with a quoted `<think>` would end the turn *with a
  nudge at the model for text it did write*. A genuinely truncated stream is caught
  by the cut-off path (`is_cut_off` ends the reply before `has_text` is consulted).
  The behaviour stays: such a reply ends the turn as text does today. Pinned by N4.
- **Real text after `</think>` is text — no nudge.** Masking covers the `<think>`…
  `</think>` range only, so `"<think>…</think>\n\nThe answer is 42."` keeps
  "The answer is 42." visible and `has_text` true. Pinned by N3 (turn) and by a unit
  test (unit).
- **The nudge's words stay.** `EMPTY_REPLY_NOTICE` ("Your last reply had no text and
  no tool call…") and the transcript line "The model's reply was empty; smelt asked
  it to carry on." (`frontend/.../transcript/text.rs:489`) are not re-worded. The
  model-facing sentence is an instruction that stays right for this case, and both
  strings are copied verbatim in docs and pinned through `const`-referencing tests;
  a re-word buys marginal accuracy on a rare provider quirk and churns SME-286's
  shipped surface. Flagged below for the user.

## State model

Nothing persists differently. `TextCallStreak` (`reply.rs:314`) is in-memory, one per
turn run: a reasoning-only reply now flips `nudged` false→true exactly as an empty
reply does today, and a real call or another such reply settles it as today; a
restart mid-turn loses it as today. The reply itself saves verbatim (part of the
audit); the nudge saves as a marked user notice the model reads on the next call, and
every tab sees it through the existing events. On the strata evidence: the turn ends
with a real answer instead of silence, costing one extra model call per nudge — the
same trade-off SME-286 already flagged for empty replies.
