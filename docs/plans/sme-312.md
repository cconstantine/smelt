# SME-312 plan — a fresh seat's offer holds only declared tools (pin, no fix)

**Branch:** `cconstan/sme-312-a-fresh-seats-offer-carried-an-undeclared` (from origin/main 87e020fd)

## What and why

SME-312 reports a seat's offered tool list carrying `mcp__code__handle`, described
plainly "placeholder" — an MCP entry from no configured server. The 2026-11-03
reproduction attempt (PM comment) found the name only in that seat's *thinking*,
nothing in code that could build such an entry, and a deleted server row (id 3,
name unrecoverable) as the only human check left. This plan pins the invariant
mechanically, per SME-310's lesson (a seat's self-audit is a report, not evidence):
**a fresh seat's offer holds only declared tools** — every entry is either a
`REGISTRY` native name or `mcp__<configured server>__<tool>` built from that
server's own `tools/list` reply with its `[server]`-labelled description — and
carries **nothing** from a server whose connect or listing didn't complete.

## Decision: pin, do not fix (the Driver's Q4, answered)

Read against origin/main 87e020fd, today's code cannot offer an undeclared entry,
and specifically a server whose `initialize` completes but whose `tools/list`
stalls or fails leaves **nothing** behind:

- `connect_unspanned` (src/mcp/mod.rs:485) builds a `Connection` only after
  `serve()` (initialize) **and** `service.list_all_tools()` both succeed
  (mod.rs:513–526), and one `tokio::time::timeout` wraps *both* steps
  (mod.rs:531–539). A failure at either records `lock_failures` and inserts
  nothing: `ensure_connected` inserts into `REGISTRY` on `Ok` only (mod.rs:641–645).
- The offer's MCP half is built only from `registry.get(&config.id)` entries —
  `offered_tools` (src/mcp/tools.rs:548–550) iterates each config's *listed*
  tools; `tool_definitions_for` (tools.rs:374–389) then keeps only entries
  `routable_offers` (tools.rs:409–425) confirms a call by that exact name
  reaches, and `mcp_tool_to_definition` (tools.rs:355–364) leads every
  description with `labelled_description`.
- A stale cached connection whose re-list fails is dropped before anything is
  offered from it (mod.rs:574–586); a deleted server row never reaches the
  offer at all (`list_mcp_server_configs` reads rows; `api/mcp.rs:219` evicts).

So the plan is a pin. No red-first exists: the defect does not reproduce on
origin/main (see the record below), and there is no gap to fix first.

## Record: what closed the shape, cited (the Driver's Q3)

- **The leading hypothesis — a half-initialized server leaving a stub tool
  list — was never true in the source record.** From the first MCP commit,
  `0ef51a00` (2026-08-16, "Add MCP … client support (#14)"), `Connection`
  carries `tools` only from a successful `list_all_tools()`, and
  `ensure_connected` has treated a failed list as "the connection is broken".
  `git log --all -S 'mcp__code'` finds nothing; `-S '"placeholder"'` under
  `src/mcp`/`src/anthropic` finds nothing, ever.
- **`labelled_description`, `3f92fdc9` (2026-10-28, SME-309):** every offered
  MCP description leads with `[server]` from that merge. It landed the day
  before this ticket was opened (2026-10-29); a re-probe seat on a pre-merge
  build is the one window in which an MCP entry could have read plainly
  "placeholder" — as a *declared* tool of a real configured server (say the
  deleted id 3, named `code`), never as an entry smelt invented. The reported
  shape (unlabelled) therefore cannot come from today's main at all.
- **`routable_offers`, `dca3ee66` (2026-11-04, SME-386 T7):** narrows the offer
  further — only tools a call by their exact name reaches are offered.
- **SME-365 (`c48cfd1f`, 2026-11-03):** safe namespaced names; orthogonal here
  (`mcp__code__handle` was already name-valid — the name alone never excluded it).
- **SME-430 (`5525d2c8`, 2026-11-06):** the Claude Code bridge (`--tools ""`,
  `--strict-mcp-config`, `--setting-sources ""`, src/claude_cli/process.rs:39–78)
  closes the analogous shape on the CLI line; that launch postdates the report,
  so it is not the source, only the same property on the other path.
- **The evidence itself:** the 2026-11-03 PM comment — the name appears only in
  seat 2294639428's thinking; no call, no tool result. A provider template
  injecting tools cannot be excluded from here (needs the request itself);
  smelt-side there is nothing to fix.

**What the new tests pin** is the assembled end result of all of that at the real
seam: the post-list-only cache (since 2026-08-16), the label (since 2026-10-28),
the `tool_definitions` assembly and name-dedup (src/anthropic/tools/mod.rs:487–519).
They deliberately do **not** re-pin `routable_offers` internals (SME-386's tests)

## The tests (exact)

Both in `src/mcp/tests/offer.rs`, `#[sqlx::test(migrator = "crate::test_lock::MIGRATOR")]`,
run under the cluster lock (`scripts/cluster-test cargo test --features server
offer`, and the full `scripts/check.sh` at push points — AGENTS.md). The seam is
the real offer path: `crate::anthropic::tools::tool_definitions(&pool, conversation_id)`
— the same call `turn::reply` puts in the provider request (src/turn/reply.rs:367)
— with a fresh conversation from `db::create_conversation(&pool)` (no parent, no
`agents` row ⇒ unruled chain, all natives except the `Child` pair offered).
Harness: `gated_http::spawn` (pub(crate) at src/mcp/tests/mod.rs:712), server
rows via `create_static_server`/`next_server_id` (process-unique ids because
`REGISTRY` is process-global), mock tool named **`handle`** to carry the bug's
name shape as a *declared* tool (the mock's fixed description "A tool" keeps
`labelled_description` from its skip branch; label logic doesn't depend on it).

1. `test_a_fresh_seats_offer_holds_only_declared_tools` — one healthy
   `gated_http::spawn("handle")` server configured. Assert over the assembled
   list: every entry's name is in `native_tool_definitions()`' names or equals
   `namespaced_tool_name(server.name, "handle")`; the MCP half is exactly
   **one** entry, its description exactly `labelled_description(&server.name,
   "A tool")` (i.e. `"[static-<id>] A tool"` — the bug shape, unlabelled,
   fails this); no name appears twice; `finish`/`ask_parent` (Child) absent,
   `notify_user` present (fresh root seat). A declared stub-like tool
   (`handle`) **is** offered, labelled — declared content is correct behavior
   and this test proves the pin doesn't chase it.

2. `test_the_offer_carries_nothing_from_a_server_that_never_fully_connects` —
   one healthy server (as above) plus three failing ones, each with its own
   `gated_http` mock and row: `refuses` (`hold("initialize").fail()`),
   `stalls` (`hold("tools/list")`, never released — initialize answers, listing
   stalls), `list_fails` (`hold("tools/list").fail()` — initialize answers,
   listing 500s). First `tool_definitions` call: the MCP half is exactly the
   healthy entry; **no** name from any of the three; and each failing mock's
   `initializes() >= 1` (so the green is never vacuous non-attempt). Then
   `sleep(CONNECT_TIMEOUT * 3 + 1s)` (1 s test budget; bounded ≤ ~5 s — a
   stalled connect is killed by its own timeout and records a failure) and call
   again: still exactly the healthy entry — a killed connect leaves no late stub.

**Prediction, marked as one (plan.md):** expected: both green as written on

## Trade-offs to flag

- The invariant is "description equals `labelled_description(server, listed)`",
  not literally "starts with `[server] `" — the label is *skipped* when the
  description already leads with the server's own name (src/mcp/tools.rs:344–353).
  The test asserts the equality (the mock's description avoids the edge); a
  future test must not "fix" that branch away.
- A configured server that declares a stub tool `handle` described "placeholder"
  **is and stays offered**, as `[code] placeholder` — declared by that server.
  The bug's shape is an entry from *no* declared source; the pin says nothing
  about filtering declared content.
- A merely-slow server legitimately appears on a *later* offer (its connect
  finishes past `TOOL_LIST_WAIT` in the background — documented at
  src/mcp/tools.rs:436–462). Test 2's stall mock never answers, so nothing can
  ever appear; it must not be read as "a slow server is never offered".
- The seat's self-report stands as the only evidence and points at a provider
  request smelt can no longer inspect; if the user wants that end ruled out
  mechanically, that is a Tempo/request-log check (human), not a code ticket.
