### Part 3: write-up, tickets, fixes

**Write-up:**

* One comment per part on SME-386, as SME-354 did. Part 1's comment holds the findings, numbered B1… in severity order across all four seats. Part 2's holds every row's mark and its new findings.
* Each finding carries:
  * its severity;
  * its evidence: confirmed in the UI, confirmed by code, or suspected;
  * `file:line`;
  * the steps that break it;
  * a recommendation and a size.

**From finding to ticket:**

1. **Triage first.** Search the Test reliability project (Backlog included) and every project's Backlog for the finding's function names, its message text and its mechanism. Check the don't-re-file list and the window's follow-ups too (381–384, 376, 380, 369, 374, 375, 358).
2. **A match** gets a comment with the new evidence and a related link to SME-386, and no new ticket. The write-up says `B7 → SME-374`.
3. **Otherwise,** a Backlog ticket in Bug bash 6, related to SME-386, with priority from severity (high → High, medium → Medium, low and docs → Low). Its title says what breaks for the user, and its body is the finding.
4. **A flaky test met in a gate** goes to Test reliability instead, related to SME-386.
5. **The driver files;** the sweep seats don't.

**Fix batching:**

1. **The stop:** after the write-up, the bash stops for the user to pick (sweeps.md). See Q3 for the shape.
2. **High findings:** each one is its own Todo and PR, fixed first and alone.
3. **Picked Mediums and Lows:** batched by area, one fix ticket per area in Bug bash 6, with its finding tickets as sub-issues. The areas are notifications, script MCP, and the rest. Each batch is one branch and PR: one commit per finding, test-first, with each red recorded, in severity order. UI-visible fixes get before/after re-shoots from one driver script (testing/browser.md).
4. **More than about six fixes in a batch** splits into two Developer runs on the same branch (sweeps.md): first the fixes and re-shoots, then the close-out, the PR and two review rounds.
5. **Batches run under the PM's two-at-a-time rule.** The areas don't share files: N's are `src/turn/state.rs` and the notifiers; M's are `src/sandbox/script_mcp/` and `src/mcp/call.rs`. Each batch's plan still checks overlap with whatever is open then.
6. **The last batch to merge** adds the `SME-386 | Bug bash 6 fixes` row to `docs/feature-checklist/sweeps.md`. Unpicked findings stay in Backlog.

**Seats and cost:**

* Part 1: four read-only reviewer seats, run once.
* Part 2: the driver's own container. It takes no cluster lock (rules.md: check servers take a port lock).
* Image builds and gates run under the scripts' own locks.
* No Anthropic spend.

**Files changed by this ticket:** none in Parts 1 and 2. The `sweeps.md` row comes with the last fix batch. `docs/feature-checklist/sweeps.md` is 2,933 bytes, far under the ceiling.
