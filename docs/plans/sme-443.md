# SME-443 plan — a compaction summary cut off at its 2,048-token budget is saved as it is, replacing the history (HTTP kinds)

**Branch:** `cconstan/sme-443-a-compaction-summary-cut-off-at-its-2048` (from `origin/main` at f999a7c7; this file lives on it).

## What

On HTTP kinds (Anthropic, Ollama, llama.cpp, Other), `summarize` gives the summary call a
fixed `max_tokens = SUMMARY_MAX_TOKENS = 2_048` (`src/turn/compaction.rs:583,748`) whatever
the model, its window or the request's room. A summary stopped at that cap
(`stop_reason: max_tokens`) is saved as it is, marked with `SUMMARY_CUT_OFF_MARKER`
(SME-393); an empty one is saved unmarked. Either replaces the history — silently losing
context — and a cut-off narration gets acted on as a record (SME-447: a seat acted on a
review nobody sent; its Driver's next summary was empty and saved too).

The ticket's order, and this plan's commit order: **1 measure** how often that happens per
model; **2 give the summary room** (a derived budget, and one continuation when still cut
off); **3 then refuse** what's still unusable — empty, or still cut off after the
continuation — failing the compaction and keeping the history, in the shape SME-431 shipped
for Claude Code (`src/claude_cli/summary::checked`: fail, keep history, one clear notice),
with no loop: `src/turn/tests/escape.rs`'s invariant must keep holding.

PR #291's decision ("failing every cut-off summary would fail every send of a long
conversation") is respected: failing only happens *after* the request has had room.
Nothing here changes how often or when conversations compact — the trigger,
`CompactionProgress` and the transcript budget are untouched.

## 1. Measure first

The production (strata) database is not reachable from a conversation sandbox, and the dev
DB is off-limits for measurement. The measurement is therefore a **SQL script the Developer
carries in `<scratchpad>/sme-443/cap-report.sql`**, run against a recorded extract if one
is supplied (Question 2) — and otherwise posted to the ticket for the user to run on
strata's Postgres. The fix does not wait on the number; the ceiling value does (Question 1).

`model_call_usage` has one row per call that streamed anything: `kind` (`turn`/
`compaction`), `model`, four token counts, `created_at`
(migrations/20261005130000_create_model_call_usage.sql). There is **no reasoning column**,
and `summarize` keeps only the first text block — thinking is never persisted. The saved
summary lives in the messages' blocks (`compaction_summary`, field `summary`).

```sql
-- Q1: how often compaction calls end at the budget, per model
SELECT model,
       count(*)                                      AS compactions,
       count(*) FILTER (WHERE output_tokens  = 2048) AS at_budget,
       count(*) FILTER (WHERE output_tokens >= 2000) AS near_budget,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY output_tokens) AS median_output
FROM model_call_usage
WHERE kind = 'compaction' AND created_at >= '2026-11-01'
GROUP BY model ORDER BY compactions DESC;

-- Q2: the shortfall — at-budget calls whose saved summary is short
WITH calls AS (
  SELECT conversation_id, model, output_tokens, created_at
  FROM model_call_usage
  WHERE kind = 'compaction' AND created_at >= '2026-11-01' AND output_tokens >= 2000
), sums AS (
  SELECT m.conversation_id, m.created_at, b->>'summary' AS summary
  FROM messages m, jsonb_array_elements(m.content::jsonb) b
  WHERE b->>'type' = 'compaction_summary'
)
SELECT c.model, c.output_tokens, length(s.summary) AS saved_chars,
       s.summary LIKE '%cut off mid-sentence%' AS marked_cut_off
FROM calls c
JOIN LATERAL (
  SELECT summary FROM sums
  WHERE conversation_id = c.conversation_id AND created_at >= c.created_at
  ORDER BY created_at LIMIT 1) s ON true
ORDER BY c.created_at DESC;
```

**What it can show:** how often per model a compaction call ends at the cap (which models,
how urgent); and the shortfall — `output_tokens = 2048` with `saved_chars` around 1,800–2,100
(≈500 text tokens) means roughly three quarters of the budget bought text that was never
returned, which on llama.cpp and Anthropic can only be reasoning, since both count thinking
in the output (citations below). `marked_cut_off` gives the per-window count of cut-off
summaries saved — the SME-447 incident count.

**What it cannot show:** the per-call reasoning/text split (no column; thinking discarded
by `summarize`); whether the provider honoured `enable_thinking: false` (not recorded);
whether turning reasoning off would fully fix strata (a replay, not a query, shows that).
Caveats: rows for stopped/failed calls carry `output_tokens` *estimated from streamed
bytes* (SME-178), so `near_budget` is noisy — `at_budget` (exact 2048) is the clean
signal; and after this change a continued compaction is **two** `compaction` rows, so the
post-deploy re-run reads `at_budget ≈ 0` (a row at 2048 after deploy means a refusal,
which is now loud in the transcript).

## 2. Give the summary room

### 2a. A derived budget

`summarize` sends `max_tokens` derived from the model's window and the request's own size,
instead of the constant:

```rust
pub(super) const SUMMARY_MAX_TOKENS: u32 = 2_048;          // floor — today's value
pub(super) const SUMMARY_MAX_TOKENS_CEILING: u32 = 8_192;  // new

/// The room estimate uses 3 chars/token — `compaction_transcript_budget`'s own
/// conservative rate — so transcript size and budget stay consistent.
/// `request_chars` is the built summarization request's text length, so it
/// grows for the continuation request.
fn summary_max_tokens(turn_model: &TurnModel, request_chars: usize) -> u32 {
    let room = (i64::from(turn_model.context_window)
        - (request_chars as i64) / 3
        - i64::from(COMPACTION_SAFETY_BUFFER))             // 4,096 margin
        .max(1) as u32;
    let mut tokens = room.min(SUMMARY_MAX_TOKENS_CEILING).max(SUMMARY_MAX_TOKENS);
    // A model's own output cap is a hard 400 on Anthropic above its limit;
    // the user's "Max reply tokens" (a *turn reply* cap, SME-111) deliberately
    // does not apply — the summary is not a reply.
    if turn_model.output_cap_is_models_own
        && let Some(cap) = turn_model.output_cap { tokens = tokens.min(cap); }
    tokens
}
```

(The 2,048 floor wins over a stingy `room`: a request the provider then refuses as too
big is exactly what the existing overflow arm in `compact` already answers — learn the
window, retry with half the transcript. Unit test A8 pins the formula's numbers.)

Why 3 chars/token: `compaction_transcript_budget` already sizes the transcript at
(window − 8,192 tokens) × 3 chars, so with the same rate `room ≥ 8192 − 4096 = 4096` for
every transcript that fits — the derived value sits in [4096, 8192] for a roomy model and
shrinks with the transcript for tight ones, which is the ticket's "derive the budget from
the model's window and the summary's input size".

### 2b. Continue a cut-off summary once

`summarize` currently ends (HTTP kinds) with "cut off → append the marker, save". New HTTP
decision, in place of that tail (Claude Code keeps going through
`claude_cli::summary::checked`, unchanged, first):

| summary text | stop_reason | today | new |
|---|---|---|---|
| non-empty | end_turn (or any other) | save | save |
| non-empty | model_context_window_exceeded | save + marker | save + marker — **unchanged** (SME-73's overflow recovery and SME-393's honesty own this stop; the cap is not the cause, more budget wouldn't help, and failing it would regress `test_a_window_stopped_cut_off_marker_blames_no_cause`) |
| empty (any stop) | | save | **fail the compaction: empty** |
| non-empty | max_tokens | save + marker | **continue once** → below |
| continuation ends end_turn, non-empty | | — | save `part1 + continuation` — whole, **no marker** |
| continuation ends end_turn, empty | | — | save `part1` + marker (it stopped mid-sentence; the model says it's done; honest save) |
| continuation ends max_tokens | | — | **fail the compaction: still cut off** |
| continuation ends model_context_window_exceeded | | — | save + marker (same as the window row above) |

The continuation is one more `summarize`-shaped call, its own recorder (its own
`compaction` usage row — cost is recorded as always): same system prompt, same
thinking-off flags (`thinking: None`, `chat_template_kwargs(false)`, `output_config:
None`), messages `[user(prompt), assistant(part1), user(CONDITION_PROMPT)]` with
`CONDITION_PROMPT` = "Continue the summary exactly where it stopped. Write only what
follows the text above, never repeat it; keep the same record and the Done/Planned
rule." and the freshly derived `max_tokens`. The request ends with `user`, so no
provider needs prefill support (Anthropic's docs: a request *ending* on a partial
assistant is the prefill case; continuing on a trailing assistant message is the
normal shape).

Failure messages keep SME-431's wording shape, which its tests pin:

* empty: `Couldn't compact the conversation: its summary came back empty, so the history
  was kept as it is. Send another message to try again.`
* still cut off: `Couldn't compact the conversation: its summary was cut off again after
  one continuation, so the history was kept as it is. Send another message to try again;
  if it keeps happening, give the model a larger window or pick one that writes whole
  summaries.`

Both return `Err` from `summarize` → `compact` → `compact_conversation` exactly as
SME-431's CLI failure does: **no divider is written, history stands, the turn ends with
the notice.**

### 2c. Why it can't loop

The continuation is `if cut_off { one_call() }` — no loop variable exists. A refusal fails
the turn; `CompactionProgress::compacted`/`refusal_compacted` are only marked when
`compact_conversation` returns `Ok` (`src/turn/run.rs:336-337`, `src/turn/overflow.rs:76-80`),
so a refusal adds nothing to the progress state machine `escape.rs` simulates — that test
and `compaction_progress.rs` are the regression net, unchanged. Per *send*, the cost of a
persistently-refused compaction is bounded: at most 2 model calls, then the user's turn
fails with the notice; the next send pays the same at most-2. That is the shape SME-431
shipped for Claude Code and the ticket's step 3 asks for. (Trade-off 1.)

## State model

No new columns, no new rows kinds, no new writers. States of one compaction pass, inside
`summarize` (transient; nothing persists until the save):

* `Complete` (end_turn, non-empty) → saved (3 messages, `record_saved` per message as
  now); `clear_conversation_usage` runs; usage rows already exist for the calls made.
* `WindowStopped` (non-empty, window stop) → saved **marked** — today's behavior.
* `Empty` (trim empty, any stop) → Err; nothing written; usage rows exist for the calls
  that streamed (SME-106: tokens spent whether saved or not).
* `CutOff` (max_tokens) → `Continued(part1)`; the continuation call then lands in one of
  the four rows of the table: whole save, marked save, or Err. If the continuation call
  itself errors (overflow, network) the error propagates as today — the overflow arm in
  `compact` only wraps the *first* call; a mid-continuation failure fails the turn
  (history intact, one partial summary never saved — recorded tokens notwithstanding).
* Who else sees each: only the save path publishes events; Err emits nothing (same as
  any compaction error today). `session::reset` and `clear_conversation_usage` are
  reached only on a save.

Callers of a refused compaction, unchanged by this plan: `run.rs`'s
`CompactionStep::Compact` arm propagates (`?`) and the turn ends; `overflow::recover`
propagates and the turn ends. Both show the typed message as the turn's error — the one
UI surface here, and it exists already (SME-431's message rides the same path).

## Outside-service claims this rests on (checked 2026-11-09)

* **Anthropic Messages API** (platform.claude.com/docs/en/api/messages): "Different models
  have different maximum values for `max_tokens`" — over the model's cap is a 400, hence
  the model's-own-cap clamp; "**Thinking tokens count toward your `max_tokens` limit**" —
  the reasoning hypothesis is provider-documented on this kind too; a trailing assistant
  message *is* prefill, so ending the continuation on `user` avoids it. Reachable
  stop_reasons for a summary: end_turn, max_tokens, model_context_window_exceeded, refusal
  — the derived value only makes a *larger* max_tokens cut-off reachable; no new stop
  reason is introduced (8,192 is far below current models' 64k–128k sync caps).
* **llama.cpp server** (HEAD tools/server README; server-schema.cpp; PR #19831, closes
  #13700): `max_tokens` aliases `n_predict` and "sets the upper bound for
  **reasoning+output** token" — reasoning shares the cap and defaults unlimited
  (`--reasoning-budget` −1); `enable_thinking:false` is only a *request hint* — a template
  free of `preserve_thinking` support keeps thinking; a request whose tokens reach `n_ctx`
  is refused with `exceed_context_size_error` (server-context.cpp — the shape
  `src/turn/tests/overflow.rs`'s `llama_refused` replays), which is why `room` keeps the
  4,096 margin. The 11-08/09 window evidence (1.8–2k-char strata summaries at
  `output=2048`) matches this failure mode exactly.
* **Ollama** (docs.ollama.com/api/chat, /capabilities/thinking): `num_predict` (mapped
  from `max_tokens`) caps generation and thinking shares it (ollama/ollama#14793 — "a
  thinking trace consuming all of num_predict"; #16583 same with the default on);
  `think:false` is a **top-level** field smelt never sends (chat_template_kwargs is
  llama.cpp-only), so Ollama summaries reason by default and hit the same cut.
* Gateway note: LiteLLM's Anthropic adapter clamps `max_tokens` to the backend model's
  cap (BerriAI/litellm #22480) — a derived 8,192 stays inside what gateways pass.

## Trade-offs to flag (→ ticket)

1. A model that can't produce a whole summary under (derived room + one continuation) now
   **fails every send** of a long conversation with a loud notice instead of saving
   truncations. That is the ticket's step-3 direction and SME-431's accepted shape; the
   notice names the way out (larger window, or a model that writes whole summaries).
2. Cost: a summary call may now spend up to 8,192 output tokens (was 2,048), and a
   continued compaction makes two calls; only when the first was cut off. Measured first
   (section 1) to keep the ceiling honest.
3. The marker still saves on HTTP kinds in two honest cases (window stop; continuation
   declares itself done) — SME-393's honesty is kept, only budget cut-offs stop saving.
