# SME-409 plan: a wake never consumes a notice into a turn that stops at a waiting question

**Branch:** `sme-409-notice-wake-race` (off `origin/main` at `74a48dda`, pushed; this file is its first commit)

## What and why

A "Terminal command finished" notice can end up saved as a conversation's last message with the seat sitting idle — until a plain message wakes it (SME-389's Developer, 2026-11-05 09:01:57; SME-384's fixer, 2026-11-04 ~21:30). Bug bash 6 Part 2b sent 13 notices on strata and 3 on hosted, several landing in the same second as the model's final reply, and every one was answered — because the window is not timing, it's a **state**: the conversation is waiting on an unanswered question when the notice is drained.

The mechanism (traced at 74a48dda below): a turn's every-iteration drains save each notice and mark its queue row consumed **in one transaction** — but `take_answer_or_wait`, which runs *after* the drains in the same iteration (`src/turn/run.rs:194-217`), returns "a question still waits" and ends the turn **before that iteration's model call**. The saved notice is now invisible to every re-wake rule (`db::wake_has_work`, `src/db/sandbox.rs:824-834`, counts only *un*notified ends, due idles, answered-untaken questions, undelivered agent messages — a consumed notice is none of these), so nothing ever tells the model: not the idle watch (the command finished, so it is no longer due-able), not a later wake, not the startup sweep (`db::conversations_with_queued_messages` likewise checks only *queued* rows). The seat resumes exactly when the question resolves — a card answer, a parent's `message_agent` reply, or the user's plain message, which dismisses the question (`src/turn/lifecycle.rs:297-317`) — matching the sightings' "idle … until a plain message". For `ask_parent` there is **no card in the seat's own UI at all** (`turn::pending_question` filters `ASKED_OF_USER`, `src/turn/questions.rs:138-144`; `docs/api/agents.md` records it), so the transcript really does look like a saved-into-nothing notice and an idle seat. Both sighted seats are agent seats for whom waiting on a parent is routine.

The fix is a reorder, not a new mechanism: **run `take_answer_or_wait` before the drains, so a question-blocked iteration stops before consuming anything.** Every unconsumed state stays visible to a re-wake rule and is told by the turn that resolves the question. It fixes the same window on all three queued notice kinds at once (finish notices, idle notices, agent reports/messages — audited below).

## State model

The wake path's shared state, its writers/readers, and where each races:

| State (one row per conversation/command) | Writers | Readers | Race in this bug |
|---|---|---|---|
| `terminal_commands.notified_at` | `save_command_notice` (turn, under lock, atomic with the save) | `wake_has_work` (wake gate), `{UNNOTIFIED_END}` drains | **The bug:** the mark commits at iteration top; the iteration then stops at the question → consumed, frozen, invisible to every reader. F1: never consumed while blocked. |
| `terminal_commands.idle_notice_at` / `touched_at` | `save_idle_notice` (same atomic-with-save shape), `touch_terminal_command` (tools, running rows only) | `{IDLE_NOTICE_DUE}`: the 60 s watch, the wake gate, the drain | Same window; self-heals next interval only if some wake comes — silent ≥ one interval in a seat that never wakes again. F1 covers. |
| `agent_messages.delivered_at` | `deliver_agent_message` (atomic with the save; `docs/design/personas/agents.md`) | `wake_has_work`, `undelivered_agent_messages` drain, startup sweep | Same window, permanent (no re-queue rule at all). F1 covers. |
| `pending_questions.answer` | `answer_question` (card), `message_agent` reply (parent), dismissal in `save_turn_message` (user message) | `wake_has_work` (answered clause), `take_answer_or_wait`, `save_turn_message` | The stopper. Its consume (take) and stop are the same call — no window. |
| in-memory turn runtime: `turns_in_flight`, `paused`, lock queue (`src/turn/state.rs`) | `admit`, Stop, delete's forget; `is_paused` read by the idle watch (watch.rs:348) | `admit`, `turn_running` | SME-216/217 serialization holds (✔ above). No window. |
| `agents.state` | start/stop/finish paths | `admits_notices` early return | Saves nothing → stays queued. Cleared. |

Invariant the fix restores: **no drain consumes a queue row unless the model call that consumes it is reachable from the same iteration.** Everything not consumed stays visible to `wake_has_work` or to its own producer (finish → the Exit wake and every later event; idle → the 60 s watch; agent messages → each queueing call wakes, and the startup sweep re-wakes undelivered rows).

## How (the fix)

**F1 — run.rs loop reorder.** Move the `take_answer_or_wait` block (run.rs:209-217) above the three drains (run.rs:194-207), and rewrite its comment to the new promise:

```rust
for _ in 0..max_turns {
    // A question the conversation waits on stops this iteration *before*
    // it consumes anything: a notice saved and marked here could never be
    // re-woken (wake_has_work sees consumed as done), so it stays queued
    // and the turn that resolves the question — a card answer, the
    // parent's reply, or the user's dismissive message — tells it. (SME-409)
    if take_answer_or_wait(pool, conversation_id, &mut pending_new_content, &mut persisted).await? {
        return Ok(persisted);
    }
    drain_unnotified_terminal_commands(...).await?;
    drain_idle_command_notices(...).await?;
    drain_agent_messages(...).await?;
    if is_wake && persisted.is_empty() { return Ok(persisted); }   // unchanged, still after
    ...
```

Ordering notes checked: on an answer turn the answer's tool-result now saves *before* the iteration's notices instead of after — `test_a_wake_takes_an_answer_no_turn_took` asserts the answer is `woke[0]` and still passes (it has no notices in the flow; no test pins the mixed order). The empty-wake return stays where it is (after the drains): a wake that took an answer has non-empty `persisted`; a wake that found nothing has taken and drained nothing. A mid-iteration question can only exist from an earlier turn's `ask_user`/`ask_parent` (a turn that asks ends in `run_tools`), so "stop before consuming" never hides a same-turn ask. A question answered *between* `take` and the drains costs one extra iteration — same as today's answer arriving between iterations.

The blocked wake still runs a counted turn (`wake_has_work` was true — there *is* work, the wake just can't spend it): tabs flap `running` true→false, as they do today for the same wake. Accepted (Decided 4).

**F2 — `deliver_notice`: no code change.** Its text is the turn's own message, saved by `save_turn_message` at `lifecycle.rs:305` before the loop, so a blocked delivery turn saves the text and stops — the same save-only class as an SME-236 save to a non-admitting seat, told by the resolving turn. Routing it around admission instead would add a pre-admit question read and a new branch for no behavioral difference (Decided 3).

**F3 — cleared, not fixed (each with reasons, per the brief):**
- *Wake turn's model call fails after a drain saved* (no model, provider down, compaction stuck): consumed-and-failed, but loud (`NotificationDeliveryFailed` + warn + kept error where kept), self-heals on the next user message whose turn carries the notice in history. This is provider-failure territory, not the sightings' silent transcript (the sighted seats' model worked minutes later). If it ever bites, the right follow-up is a re-queue rule on failed wakes — deliberately not this ticket (Decided 5).
- *Stop between drain and call*: paused by design (SME-40 F4); the resume message reads history. Not silent (the stop's own notice lands).
- *`admits_notices` false early-return* and *`save_notice_between_turns`*: consume nothing / consume no queue — recovered by design (✔ table above).

## The other notice kinds (the sweep the brief asks for)

- **Idle notice (SME-79):** same window (same drain shape; `save_idle_notice` marks `idle_notice_at` atomically with the save). Partially self-healing (re-due after the interval, if a wake ever comes), still silent for ≥ one interval in a seat that waits on a never-answering question. **Fix: yes — F1 covers it.**
- **Child report / `finish` reports / pod-stop notices / startup-sweep wakes (SME-236 `agent_messages`):** same window (`deliver_agent_message` marks `delivered_at` atomically); **permanent** — no re-queue rule; the startup sweep only re-wakes `delivered_at IS NULL` rows. **Fix: yes — F1.**
- **`message_agent` messages to a question-waiting child:** same queue, same window, same fix — and note the ordering interaction SME-238 relies on (an answer recorded on a `pending_questions` row is *also* what unblocks the drain; `take` runs first and takes it, so the resolving turn tells answer + queued rows in one call). Cleared of new issues, covered by F1.
- **Question answers themselves:** consume+stop is atomic in `take_answer_or_wait` — no window. Cleared.
- **`Notice::Deliver` texts (Docker restart, trust decision):** F2 above — save-only class when blocked, told next turn. Cleared with the decision.

## Decided (Driver)

1. **The named window is the question-blocked iteration**, not a same-moment race: with no waiting question and no error/Stop, a saving iteration always reaches its model call or waits on it (✔ enumeration), which is why 16 bug-bash notices answered and both sightings are agent seats with a parent to wait on.
2. **No new test hook.** The window is a DB state (`waiting_question` + queued rows), constructible in the fixture; determinism comes from calling `wake_conversation` inline as `src/turn/tests/wake.rs` already does 14 times. `test_hooks::pause_after_notice_admitted` stays as it is — it exists for Stop-vs-admission timing, which this ticket neither changes nor needs to land a race in. A hook that faked a timing race would be the wrong artifact for a state window.
3. **`deliver_notice` gets no branch** for a question-waiting seat: its text joins the save-only class and is told by the resolving turn; a pre-admit question read would add a branch and a race for no observable change.
4. **A blocked wake stays a counted turn** (brief tab flap, no saved message — same as today, SME-71's Finished suppression keeps it silent). An uncounted pre-admit skip would duplicate the question read into the admission path's critical section for cosmetics.
5. **Wake-turn model-call failure after a save is cleared, not fixed** (loud, self-heals on the next message); a failed-wake re-queue (un-marking on failure) is a separate, riskier mechanism — if it ever earns a ticket, that ticket owns the duplication rules.
6. **`wake_has_work` and the startup sweep stay as they are.** Adding "question-blocked with queued work" clauses would wake conversations only to stop at the question again; the fix's guarantee is that nothing is frozen while blocked, so the existing clauses are exactly the recoverable set.
7. **Idle notices and agent messages are *fixed* by F1, not merely cleared** — one shared reorder covers all three queue kinds; T1 asserts all three in one fixture rather than three tests (the reorder is one line-movement; three fixtures would test the same line thrice).
8. **The plan lives in this file on the branch** (~long-form per the brief), with summary, Trade-offs and Questions in the ticket.

## Trade-offs (also in the ticket)

- **For:** removes the whole "consumed while unable to tell it" class in one move; queue-only states are exactly the set every wake rule already re-checks, so recovery needs no new rule. No migration, no new state, no lock-protocol change; SME-216/217/218 guarantees are untouched.
- **Against / costs:** the blocked wake's turn now saves *nothing* — a seat waiting on a never-answered question shows no sign of the finished command in its transcript until the question resolves (today it shows the notice, ignored — arguably the more honest display, but it is the state that strands work). Notice order inside one turn shifts to [answer, notices…] — nothing pins it. The reorder moves a question read ahead of up to four cheap queries on the common (no-question) path — no measurable wake cost.
