# SME-439 plan — a Context window smelt learns from one ambiguous stop must not stick silently

**Branch:** `cconstan/sme-439-a-context-window-smelt-learns-from-one` (PR 1, from `origin/main` `d816dae`, plan on it already). PR 2 continues the ticket on a later branch cut from `main` once PR 1 merges — proposed `cconstan/sme-439-b-learned-window-on-the-provider-page`.

## What

Hosted strata (llama.cpp kind) had its Context window at 160,799 instead of the server's 262,144, learned silently by SME-73's window-stop learner. The event (ticket's Finding comment): a repetition-loop reply stopped `max_tokens` at 355 output tokens — far under budget, so `window_stop` read the stop as "the window filled" — and the call's measured size (input 1 + output 355 + cache write 679 + cache read 159,764 = 160,799) was saved as the model's window: a number that just says how big the conversation was. Nothing logged or traced the learning, and it stuck until the user raised it by hand.

Two PRs, as the Driver's split decides:

- **PR 1** (this branch) — Expected **5 + 6**: stop learning windows from one ambiguous llama.cpp `max_tokens` stop; learn only against what the server itself reports (`reported_context_window`, per-request), or when a like-sized stop repeats, never from a degenerate or near-empty reply; with nothing reported, one stop is evidence for its turn only and saves nothing. And: log and trace every learning decision. Plus the one thing the brief requires here too: **the learner must never write the user's own `context_window` value** — which needs a second column, so PR 1 ships it.
- **PR 2** (later branch) — Expected **1–3**: show the learned window on the provider page with when/why/source and a one-click reset; drop it when a later listing reports a larger window or a bigger request succeeds.
- Expected **4** (time expiry) is out of scope — Decided (Driver): PR 2's clear-on-larger-report covers staleness.

Everything below is this Planner's decision within the brief; the Decided notes mark the ones the Driver already made.

## Why the learned column goes in PR 1 (decision)

"With one column, never let learning overwrite the user's setting" is not satisfiable: a learner that must not write `context_window` has nowhere to write, and today's learners settle on the smaller of several learnings (SME-73's `lower_model_context_window` guard), which a plain "only where `context_window` IS NULL" would break — the first learning would fence off every later one. So PR 1 adds `learned_context_window` (+ when/why/source columns, recorded at write time because PR 2 cannot recover them later), writes all four learners to it, and reads it *below* the user's override. PR 2 is then display, reset, and clearing — no second migration. This is the minimal honest form of "PR 1 already: the learner must not stomp a value the user set" (Decided (Driver)) with the column itself as its mechanism; PR 2 "separates the columns for good" by making the separation visible and reversible.

## The learning rules (PR 1)

`window_stop()` (`src/turn/overflow.rs:164`) keeps its exact semantics: it is also the transcript's tell (`reply.rs:202` picks the `RoomLeft` notice wording from it). Everything new lives inside `learn_window_stop`. Its input gains the reply content: `run.rs:364-366` passes `&turn.content` (one call-site change; `StreamedTurn.content` exists).

New constants in `overflow.rs`:

- `WINDOW_STOP_MARGIN: i64 = 4_096` — how close to the per-request reported window a measured size must come to be plausible. Equal to `COMPACTION_SAFETY_BUFFER` by taste, its own named constant; it absorbs llama.cpp's per-slot rounding and usage-count jitter, and it is small next to any real window.
- `MIN_WINDOW_STOP_OUTPUT: i64 = 32` — a stop that wrote less than this is "very short": it measured almost nothing of the room (below the 64-token slack usage rounding lives under). 32 and not 355 on purpose: a genuine fill can stop with only a little room left (SME-73's W1 story — input nearly fills the real window); the floor only rejects near-empty replies. (Decision.)

New pure helpers in `overflow.rs`, each with unit tests in the style of `test_the_ollama_tell_reads_only_requests_worth_reading` (`src/turn/tests/window_stop.rs:304`):

- `fn reported_per_request(reported: Option<i32>, kind: ProviderKind, total_slots: Option<u32>) -> Option<i64>` — a llama.cpp server's `n_ctx` is its **total** context split across its slots: `n_ctx_slot = n_ctx / total_slots` (llama.cpp's own: server code quoted in ggml-org/llama.cpp#11681; docs clarification PR #17767 "each slot gets ctx-size / parallel"; the auto/`-np`-omitted unified-KV default divides too — PR #23694). Divide when `kind == LlamaCpp` and `total_slots > 1`; for other kinds the reported window is per model — pass it whole. `total_slots` comes from `providers::server_caps(&provider)` (the provider's stored `/props` info). An uneven split (`--slot-context`, proposed upstream PR #23340) breaks the even division — the margin and the repeat rule are the guard; note it here so review sees it.
- `fn stop_reads_plausible(measured: i64, reported: Option<i64>) -> bool` — `Some(w) => measured.abs_diff(w) <= WINDOW_STOP_MARGIN`, `None => false`.
- `fn looks_degenerate(text: &str) -> bool` — repetition-loop tell: take the reply's last 40 whitespace-or-punctuation-delimited tokens; degenerate when one token appears ≥ 24 times (60%). Catches the incident's `…finish.finish.finish.finish…` (a token scan, not a word scan, so periods split it). Documented misses: unspaced CJK loops, whole repeated code lines with distinct content, loops shorter than 40 tokens — acceptable because the *primary* guard is the proximity rule; this only vetoes. (Decision.)

The decision tree in `learn_window_stop(pool, conversation_id, turn_model, usage, content)`:

1. `measured` = input + output + cache creation + cache read, as today (`overflow.rs:185-189`).
2. `usage.output_tokens < MIN_WINDOW_STOP_OUTPUT` → trace `ignored_short`, return.
3. `looks_degenerate(joined text blocks of content)` → trace `ignored_degenerate`, return.
4. The stop is **unambiguous** when `stop_reason == "model_context_window_exceeded"` — the server's own claim the window filled (Claude 4.5+ / gateways); it skips step 5's requirement and saves directly. `MIN_PLAUSIBLE_WINDOW` (1,024) keeps the existing floor on what is saved at all.
5. Look up what the server reports (two queries, rare path: `db::get_provider_model(pool, provider_id, model)` for `reported_context_window`, `db::get_inference_provider` + `providers::server_caps` for slots) → `reported_per_request(...)`. Unambiguous, or `stop_reads_plausible(measured, reported)` → **save**: update the turn copy and persist through the shared funnel (below) with source `window_stop`.
6. Ambiguous and not plausible: consult the repeat map (below). Second like-sized candidate (`(previous - measured).abs() <= WINDOW_STOP_MARGIN`) → **save** `measured` (Expected 5's "or when it repeats" — two independent fills at one size are the evidence). Otherwise:
   - reported **known** → record the candidate, trace `candidate`, and return **without touching `turn_model.context_window`**: the server said what it has; a measurement far from it measured the conversation, not the window. This is the incident — and unlike today the turn's belief (and the meter, and the next compaction check) stays put. The transcript notice is unaffected (step: `window_stop()` unchanged).
   - reported **unknown** → treat as evidence for this turn only (Decided (Driver)): `turn_model.context_window = min(believed, measured)` so the meter and this turn's compaction read it, record the candidate, trace `turn_only`, **save nothing** (Decided (Driver): one stop, no reported window → turn-only).

Repeat state: `static WINDOW_STOP_CANDIDATES: LazyLock<Mutex<HashMap<(i64, String), (i64 /* measured */, i64 /* conversation */)>>` keyed `(provider_id, model)` — the codebase's global-map pattern (`limiter::LIMITS`, `turn/state.rs::RUNTIMES`). Process-local: a restart drops repeat evidence, which errs toward never learning (Trade-offs). Never held across an await. `#[cfg(test)] pub(super) fn forget_window_stop_candidates()` to clear it — `#[sqlx::test]` databases each hand out the same provider ids while tests run in one binary, so tests that read or write candidates call `forget_window_stop_candidates()` right after taking `lock_turn_tests()` (which serialises the turn tests anyway); a save deletes its entry.

## State model (PR 1)

Record: `provider_models` for `(provider_id, model)`; the window a turn believes is `COALESCE(user, learned, reported, claude-*, assumed)` (`providers::context_window`, the one reader); `learned_context_window` is a record of the last learning with `…_at/_reason/_conversation` — a triple written together, one writer per statement, never partially.

Writers of `learned_context_window`: refusal learner (`recover`, both first attempt and retry-refused), compaction-refusal learner (via unchanged `learn()`), window-stop learner (gated, new), Ollama `/api/ps` learner, all through `db::save_learned_context_window` — one statement each, committed or not, either is right; a failed write traces `write_failed`, warns, and the turn proceeds on its copy (as today). Plus: provider deletion (cascade), the user's model form **never** (that's the point), listings never.
Writers of `context_window` after PR 1: the user's form (`set_provider_model_overrides`, `api/providers.rs:97` route) only.
Writers of `reported_context_window`: `store_details` (`providers/server.rs:612`) only — verified at `d816dae` the single production caller of `set_provider_model_reported`; re-grep after merges (SME-111's lesson: every listing path is a writer).

Readers of the believed window and what they do: `resolve_turn_model` (next turn starts right); an in-flight turn (keeps the window it read; on its own overflow recovers on its copy — SME-72's rule, unchanged); the meter (`recorder.finish` publishes the turn's copy — this is how `turn_only` evidence reaches the meter for exactly one turn); provider page and pickers (read `ModelInfo.context_window`; `context_window_override` still shows the user's own field only — PR 2 adds the learned line); `db::save_learned_context_window`'s own guard.

| state | user sets value | learner saves | listing refreshes reported | conversation deleted | pod restart |
| --- | --- | --- | --- | --- | --- |
| user+learned+reported any mix | wins the read; never written by a learner | lowers learned or no-op | reported changes under them | learned's conversation ref dangles (PR 2 shows it plainly) | learned stands; candidates lost |

Races: the user form and the learners now write **different columns** — SME-73's "a form loaded before a learned write puts the old value back" race dies with the split. Learners vs learners: single statements, lowers-only guard, last smaller wins. Check-then-act (turn sends at a belief someone lowers meanwhile) is unchanged: refused → `recover`. Work in flight: `learn_as` moves the *turn's copy* only when smaller; a model switched mid-turn applies next turn (unchanged). A save racing a Stop: same one-statement window SME-73's plan's table already reasons about; no new pauses. `test_hooks` gains nothing.
