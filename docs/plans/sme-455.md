# SME-455 plan: a live seat that owes an answer, with nothing running — visible, and nudged

**Branch:** `cconstan/sme-455-the-tree-api-and-the-sidebar-show-a-live` (cut from `origin/main` = `73d6a1a20ad441c501973d5ab8271acea3bd4b8f`; this file lives on that branch).
**Remove `docs/plans/sme-455.md` before the PR merges** (SME-129 rule: plan files are not shipped).

## What

A live seat (an `active` agent with a parent) can end its turn owing its parent a report while nothing runs in it: no turn, no terminal command, no child, no pending wake, no question waiting. Today smelt tells the *parent* on the first such end (SME-236, `agents::after_last_turn`). Four people found these seats late (SME-384's Driver 42 min, SME-395's Developer 37 min, SME-441's Developer ~4 h, SME-462's Developer 27 min).

Per the user's decision (SME-455 comment, 2026-11-10T15:22Z — wording and escalation are the user's, both kept here unchanged):

- **Part 1:** `/api/conversations/tree` and the sidebar mark a live seat in that state and show how long it has been in it (following SME-441's sidebar-mark pattern).
- **Part 2:** the first such turn-end sends the **seat** one notice — verbatim: `you ended your turn owing your parent a report, and nothing is running that will wake you; check your state` — and if the seat ends its turn the same way **again**, smelt tells its **parent** instead (today's SME-236 notice). It must never loop; the escape property (`src/turn/tests/escape.rs`: wakes never keep spending) stays true, and a seat gets at most one nudge per owed spell.

**One state, one signal** (the user's "same signal"): a new durable column `agents.report_owed_at`. It means *"this seat was already nudged for owing a report and still owes it"* — set at the first such turn-end (atomically with queuing the nudge), read by the tree query, cleared when the seat reports to its parent or the user engages it. This replaces the ticket's guess that SME-450's `conversations.answer_owed_at` is the signal: it can't be — `answer_owed_at` is **cleared at every turn end** (SME-450 D7), so a seat that ended its turn stuck has it NULL; on a running server it is set only while a turn runs or right after a restart dropped one. The plan uses the state SME-236's `db::idle_agent_without_report` already computes, timestamped with the new column, and extends that predicate with the user's "no wake pending" clause. Marked **Decided (Driver)** (delegated).

The parent-facing behaviour changes in exactly one place, the user's: a **plain model-ended** turn ending without a report reaches the parent on the *second* such end, not the first. Turn ends that something *else* caused — a failure, a cut-off, a provider refusal (SME-386 F6), or a Stop — keep telling the parent immediately, unchanged; a Stop already ends the check. **Decided (Driver):** the nudge is for the incident class in the ticket ("it said *waiting on CI* and sat"); a failure reaching the parent through the seat's report is an SME-386 N6 guarantee we do not delay.

## State model — `agents.report_owed_at TIMESTAMP NULL` (new migration)

Migration `migrations/20261110120000_report_owed.sql` (sorts after `20261108120000_answer_owed.sql`, the newest on main): `ALTER TABLE agents ADD COLUMN report_owed_at TIMESTAMP NULL;`. On `agents`, not `conversations`: every reader of the mark is about an agent seat, the tree query already `LEFT JOIN`s `agents` and reads `a.state`, and no non-agent can owe a parent a report. NULL = never nudged (or already satisfied); set = nudged at that timestamp and still owing.

**The predicate** ("owes with nothing running", the *stuck predicate*): the seat is `active`, has a parent, is not paused (checked in memory at the turn-end path), and has none of — a question to the user or its parent awaiting an answer (`pending_questions.answer IS NULL`), an AGENTS.md trust card (`instruction_requests`), a running terminal command, a `starting`/`active` child of its own, **and (new) none of a pending wake**: an undelivered `agent_messages` row, a command end recorded but never drained (`sandbox::UNNOTIFIED_END`), or an answer to its own question not yet taken (`pending_questions.answer IS NOT NULL`). The first five clauses are today's `IDLE_AGENT_WITHOUT_REPORT_SQL`; the last three are the user's "no wake pending". The whole predicate becomes **one shared SQL fragment** in `src/db/agents/mod.rs` (pattern: the existing `WAITS_FOR_USER` const), used by `idle_agent_without_report`, the new tree CASE, and nothing else; both existing queries alias `conversations` as `c`, so the fragment references `c.id`. `agents.state`/`starting` appear as inline literals in the fragment with a comment naming the `AGENT_ACTIVE`/`AGENT_STARTING` consts (the two host queries bind different parameter lists; SME-389's R1-1 note about EXPLAIN-testing the clause **as written** stands — keep the existing `pub(crate) const` so an EXPLAIN test can quote it).

**Writers (every path that writes the record):**

| transition | who | how | if it fails partway |
|---|---|---|---|
| NULL → set, **with the nudge row queued in the same transaction** | `db::queue_report_owed_nudge(pool, seat, text)` — called only from `after_last_turn`'s first branch | tx: `lock_conversations([(seat, KeyShare)])` (documented order: conversations rows, then the rest — a bare `UPDATE agents` then INSERT could cross a subtree stop's `FOR NO KEY UPDATE` into a deadlock), then `UPDATE agents SET report_owed_at = now() WHERE conversation_id = $1 AND report_owed_at IS NULL AND state = 'active' RETURNING conversation_id`; no row → rollback, `false`; else `INSERT INTO agent_messages (to=seat, from NULL, 'smelt', kind server_notice, body = mark_notice(text))` (the `db::queue_server_notice` shape) | the transaction is atomic, so *nudge queued* and *owed recorded* cannot split — a restart lands before or after both; the caller then `turn::notify(seat, [Notice::Wake])` outside the tx — a crash after commit, before wake, loses nothing: the undelivered row is on the startup sweep's list already (`conversations_with_queued_messages`) |
| set → NULL | `finish_agent` success path — add `report_owed_at = NULL` to its existing `UPDATE agents SET state = finished` (refusals — `CommandsRunning`, `AgentsRunning`, `MessageWaiting` — touch nothing) | same tx as the finish | — |
| set → NULL | `db::message_agent`, only when it commits `Queued` **to the parent** (`Recipient::Parent`) — not to its own child, not a parent-side `Answered(child)` (the child still owes its report) | add one `UPDATE agents SET report_owed_at = NULL WHERE conversation_id = caller` before that commit | — |
| set → NULL | `db::ask_parent` success (`Asked`) — the seat is in contact with its parent; while its question waits, the predicate excludes it anyway | one UPDATE in that tx | — |
| set → NULL | the user's send or answer **in the seat** (`turn::lifecycle::start_turn` and the card-answer path in `turn/questions.rs` at its `start_by_user`): the user is there; a later stuck end starts a fresh spell | new `db::clear_report_owed(pool, id)`, warn-only, like `clear_answer_owed`'s call sites | losing it costs one redundant escalation at the next stuck end |

`report_after_finish` touches nothing (a finished seat cannot hold the column: `finish` cleared it and the turn-end early-return never reaches the branch). A Stop/`stop_agent`/failure does **not** clear: the seat still owes; the sidebar shows its `stopped` status and the mark beside it (the parent heard about the stop anyway); the user writing clears.

**Readers, and what each reads:**

| reader | what it does |
|---|---|
| `/api/conversations/tree` (`db::agents::tree::conversation_tree`) | `CASE WHEN {stuck predicate} THEN a.report_owed_at END AS report_owed_at` — the gate re-evaluates the predicate live, so the mark self-hides while the seat runs a command, gains a child, awaits a wake, or awaits the user, and reappears when those go, with the age of the *original* owed moment (it never stopped owing; only "nothing running" flickered). `state = 'active'` inside the fragment hides it from stopped/failed/finished seats. A tree fetch costs three extra indexed EXISTS probes per row on tables that already have the indexes the idle query uses (`agent_messages_undelivered` partial, `idx_terminal_commands_conversation_running`, `pending_questions.conversation_id`); the tree is every conversation and is refetched on `ConversationsChanged`/`TurnsChanged`/`QuestionsChanged` — small in practice; check an `EXPLAIN` while implementing (SME-389 R1-1's habit) |
| the sidebar row | renders the mark when the node carries a timestamp and `!busy` (the busy spinner wins — the SME-441 rule) |
| `after_last_turn` | the CAS itself distinguishes first (queued nudge) from second (tell parent) — the only first/second decider |
| startup sweep | reads nothing new: a queued-but-undelivered nudge rides the existing `conversations_with_queued_messages` wake |

No other reader. `list_agents`/`status()` are unchanged (the seat still reads `idle`; the mark is the tree row's).

**Races (the ones between writers):**
- *finish racing the nudge CAS:* both serialize on the `agents` row; `finish` runs inside the turn, `after_last_turn` runs after the turn's `TurnInFlight` drops, and a seat that finished mid-turn takes the `AGENT_FINISHED` early return before the branch. A finish committing between the idle read and the CAS makes the CAS's `AND state = 'active'` fail → escalation proceeds and the parent hears about a just-finished seat — today's check-then-act exposure, unchanged (agents.md documents it as accepted: "the notice says the turn ended, not the work").
- *Stop landing mid-branch:* wake refused while paused; the nudge row stays queued and the user's next message drains it (the standing pause rule).
- *A message arriving after the predicate check:* an undelivered row now blocks future stuck-ends (the new clause), and today's accepted benign-notice window stands for the one already in flight.
- *Two turns ending:* turn ends serialize on the turn lock (`after_last_turn` runs once per end, after the last turn dropped — agents.md's "check after `TurnInFlight` is dropped"), so no two firsts.
- *A crash between the turn's last write and the CAS commit:* that end is simply never recorded (no column, no nudge) and the next end re-detects. This sub-millisecond window is the one SME-450's own plan reviewed for this exact check and left **not filed** ("a sub-millisecond window with no wait in it", docs/plans/sme-450.md row 35); the same reasoning holds. In the ticket's Trade-offs.

**No loop (the escape property).** The nudge is a queued row + `Notice::Wake` — an ordinary SME-450 server notice, so `wake_has_work` refuses empty wakes and the compaction escape property (`escape.rs`, untouched by this plan) still governs its wake. The one-notice rule is enforced by the CAS, not by counting: first stuck end → nudge; every later stuck end → parent. The nudge's own wake is a turn; if it ends stuck again the parent is told and **nothing wakes the seat again** — parents' wakes never reach the child. So the chain from one stuck end is: nudge → at most one extra seat turn → parent notice → silence. If the parent (or user) then wakes the seat, each further stuck end tells the parent — every notice traces to a real wake, never to smelt waking itself. Test `test_second_and_later_stuck_ends_tell_the_parent_and_never_loop` asserts the bounded request count.

**Restarts (SME-450 paths):** the nudge row survives (queue + wake, D5/D9 machinery); the sweep delivers it, and its delivery reuses the drain (the delivered message carries `answer_owed_at`, so a second restart re-answers per SME-450, exactly once — test 7 asserts one copy either way). A restart after a *delivered* nudge with the seat quiet wakes no one new (nothing queued, nothing owed, no undrained end) — no double-send, and Part 1's mark still reads from the durable column, so the stuck seat stays visible across restarts.

## How it will be checked by hand (also the What-shipped hands-on steps)

On a check server (`CHECK_SCRATCH_DB=1 scripts/check-server start`, a mock or real provider):
1. Start an agent with the brief *"say 'still waiting on CI' and end your turn"*; when its turn ends: its sidebar row gains `!` (hover: *owes its parent a report for now* → `1m`…); its transcript shows the nudge; the parent shows **no** notice yet. It ends its nudge-woken turn → the parent shows *"turn ended without a report; its last message: …"*; the mark stays, age counting.
2. Same brief but the agent starts `sleep 300` first → no nudge, no parent notice, no mark.
3. Ask it to `message_agent` its parent, then end a turn owing again → nudges once afresh (column cleared).
4. Restart smelt between the stuck end and the nudge landing is not reproducible on demand; the nudge-queued-then-restart path is test 7's (server tests cover it; no provider needed).
