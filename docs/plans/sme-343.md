# SME-343 plan: a running turn keeps its provider's request slot

**Branch:** `cconstan/sme-343-a-running-turn-keeps-its-providers-request-slot-so-a-one` (off `origin/main` at `9420f4a`, pushed; this file is its first commit)

## What and why

`SME-162`'s limiter (`src/providers/limiter.rs`) caps a provider's concurrent model requests with a pool of `limiter::Slot`s, but today each **model call** takes a slot at `stream_message` (`src/anthropic/stream.rs:577`, `endpoint.slot()`) and frees it when the call ends. On a one-slot llama.cpp server, live conversations interleave on every call and the server re-prefills each time it switches prompt (ticket Evidence: ~30% of GPU time; 37 full misses ≈ 40 min in a 6-hour window).

The fix: on a provider with a limit, a turn takes **one** slot for its provider at its first model call and holds it until the turn ends; the turn's own calls — turn calls and compaction's summarization call — reuse it instead of acquiring per call. A turn's other turns, Stop, errors, `ask_user`/`ask_parent`/`finish` all end the turn, and `Slot` frees on drop.

**Drift the ticket's Shape has from the code:**

1. *"Take the provider's slot at the start of the turn body (`run_turn_body`)"* — at that point the turn **doesn't know its provider yet**: `resolve_turn_model` runs lazily on the first loop iteration (run.rs:566–571), deliberately after the turn's message and drained notices are saved ("so they survive a turn that can't run", and `docs/api/model.md:5` records it), and an empty wake returns before any resolution (run.rs:556–558). Acquiring at `run_turn_body` entry would mean resolving the model earlier (changing that documented behavior) and making no-work wakes queue on a slot. **The plan acquires at the turn's first model call** — once per loop iteration, right after `resolve_turn_model` and **before** the `should_compact` check, so compaction always finds the slot held — and holds it to the end of the turn. Effect: same holding, minus the two regressions.
2. *"A limit change mid-turn still applies"* — kept, but its SME-162 wording narrows honestly (see "SME-162 semantics" below): a held slot is not re-examined when the limit is **resized** (same pool); it is released/re-taken when the pool is **replaced or closed** (cleared, deleted, re-set), and a running turn with no slot acquires at its next call when a limit appears. `limiter.rs`'s doc comment and the docs listed below carry the new wording.

## How

### The slot the turn holds (`turn/call.rs`)

A new `TurnSlot` type (lives in `call.rs` next to `call_model`, which takes it as an argument):

```rust
pub(super) struct TurnSlot {
    /// The held slot while the provider's pool is one; None while the
    /// provider has no limit (nothing to hold, nothing to wait on).
    slot: Option<limiter::Slot>,
}
```

- **Refresh once per loop iteration**, in `run_turn_steps` (run.rs), right after the `resolved_model` block and **before** `should_compact`. Pseudocode:

  ```rust
  let pool_now = limiter::current(turn_model.provider_id);
  match (slot.as_mut(), pool_now) {
      (Some(held), Some(pool)) if held.from_pool(&pool) => {}   // keep holding
      (Some(_), _) => slot = None,     // cleared, forgotten-replaced, resized-into-new-pool: give it up
      (None, None) => {}               // unlimited: nothing to do
  }
  if slot.is_none() && limiter::current(turn_model.provider_id).is_some() {
      // Endpoint::slot(): the existing SME-162 acquire — SLOW_SLOT_WAIT
      // warning, re-look-up when the pool closes while waiting, None when
      // the provider has no limit. Records `smelt.slot_wait_ms` on the
      // turn span (new field next to `turn.steps`).
      slot = Some(TurnSlot::acquire(&turn_model.endpoint).await);
  }
  ```

  `Slot` gains a small `from_pool(&self, &Arc<Pool>) -> bool` (`Arc::ptr_eq` on its pool) so a refresh can tell a **resized** pool (same `Arc`, resized in place — keep holding; SME-162 review 2's math: a lowered pool marks held slots `owed` and takes them back at turn end, so never more than the new limit run) from a **closed-then-replaced** pool (new `Arc` — give up the old slot, take the new pool's; a Stop during the wait drops the body, so the re-acquire is interruptible like the first one).
- A turn that never calls the model (empty wake, answer taken before any call) never acquires; a turn whose model fails to resolve fails the way it does today with no slot held.
- The `TurnSlot` lives inside the `run_turn_steps` future, so every turn end — `Ok` return, `Err`, a Stop dropping the body at run.rs:302, a panic — drops the `Slot` exactly like today's per-call hold, and `Slot::drop` keeps the `owed` (lowered-limit) behavior.
- `call_model` (call.rs) and `compact_conversation` (compaction.rs) take `&TurnSlot` and pass it down; their retry loops (`TOOL_CALL_PARSE_RETRIES` in `call_model`) reuse it across attempts, so another conversation can no longer slip between an attempt and its retry — the same intent as SME-162's existing `test_the_slot_is_held_across_transient_retries`, one layer up.

### The stream layer (`anthropic/stream.rs`, `stream/endpoint.rs`)

`stream_anthropic_message_metered` and `stream_message` take a slot argument replacing the unconditional `endpoint.slot().await` at stream.rs:577:

```rust
pub enum SlotPolicy<'a> {
    /// Take and hold a slot for this call (today's SME-162 behavior).
    PerCall,
    /// The caller already holds the turn's slot for this endpoint's
    /// provider (None when that provider has no limit): send without
    /// acquiring, and don't record `smelt.slot_wait_ms` (the wait, if
    /// any, was the turn's, recorded on the turn span).
    Held(Option<&'a limiter::Slot>),
}
```

The `#[cfg(test)]` wrapper passes `PerCall`. `Endpoint::slot()` stays as-is (its slow-wait warning and pool-re-look-up are what `TurnSlot::acquire` reuses; visibility grows from `pub(super)` to the crate or module as needed). `PerCall` keeps raw calls — probes, tests, any future out-of-turn caller — behaving exactly as SME-162 built them. **Every-caller rule:** a turn's model calls pass `Held`; a future in-turn call to a *different* provider takes that provider's own per-call slot (different pool, no interaction), and a future second in-turn call site on the *same* provider passes the same held `&TurnSlot` rather than releasing and re-acquiring. The enum makes the choice explicit at every call site; grep `SlotPolicy::` finds them all. (Today only the two sites exist — verified above.)

### SME-162 semantics, kept as literally as holding allows

- A limit change applies to a **waiting** acquire at once (unchanged — `endpoint.slot()` re-looks the pool up when the one it waits on closes; `test_a_waiting_call_takes_a_raised_limit_at_once` stays green).
- A change applies to a **running turn at its next call** for: a newly-set limit (it acquires then), a cleared one (it gives its slot up at the refresh and goes), a replaced pool (drops and re-takes). It does **not** apply within a call, and a same-pool resize does not evict a held slot — the lowered limit takes it back as it frees, which for a turn-held slot means **at the turn's end** (drop, `owed`-forgotten). Where SME-162's limiter comment says "from each running turn's next model call", the new text says what is true; docs updated (below). Worst case a lowered limit overshoots: one pre-lowering turn holding 1 slot until it ends (Stop/`finish`/`ask_user` end it).
- A cleared limit closes the pool and lets waiters go (unchanged); a running turn's held permit on the closed pool is released at the next refresh.
- A mid-turn provider or model change applies from the next turn (SME-72) — the held slot is always `turn_model.provider_id`'s, the resolved snapshot, never the current pick.
- Deleting the provider (`limiter::forget`) leaves holders and waiters as today; the turn fails at its next DB write and drops its slot.
- Agents: unchanged and re-verified — "a parent never waits holding a provider slot" still holds (parental waiting happens between turns), so no parent/child slot deadlock. The rule that becomes load-bearing and is stated in `call.rs`'s doc: **no tool may block on a model call to a limited provider while its turn holds a slot** (no such tool exists today — every inter-conversation tool is a row write or a spawn; compaction is the only in-turn extra call and it reuses the slot).

### What a turn's slot wait looks like now (per-caller × state)

| Caller | provider unlimited | pool has a free slot | pool full | limit cleared while waiting | provider deleted mid-turn |
|---|---|---|---|---|---|
| Turn's first call (refresh) | goes, holds nothing | acquires, holds to turn end | waits in smelt (Stop drops the body; a `>30s` wait logs one line, host only — existing) | goes (existing `Endpoint::slot` None path), holds nothing | turn fails at next DB write; no slot held |
| Turn's later calls | — | reuse (no acquire) | reuse — cannot be blocked by *other* conversations once held | refresh drops the held slot, next call acquires from the new pool or goes | as above |
| Compaction in the turn | — | reuse | reuse (this is the deadlock fix) | — | — |
| Another conversation's turn | goes | acquires | **waits until the holding turn ends** (was: until the holding *call* ends) — see Trade-offs / Questions | goes | — |
| Raw call (`PerCall`) | goes | per-call acquire (unchanged) | unchanged | unchanged | unchanged |
| Probes (`slots_of: None`), provider pages | never touch a pool | | | | |

Turn queue order per conversation (turn lock, `TurnPlace`) is unchanged; slot waits happen while holding one's own conversation's turn lock, as SME-162 calls already did; Stop during a slot wait is the run.rs:302 select dropping the body (existing `test_a_cancelled_waiter_takes_no_slot` shape at the call level; a turn-level test is added).

State model, briefly: the slot record **is** the semaphore permit — process-memory, no DB rows, no files, nothing survives (or needs to survive) a server restart (pools rebuild from the column on endpoint builds, SME-162, unchanged). Transitions and failure cells: acquire cancelled (Stop) → no slot taken; acquire returns after its pool closed → treated as no-slot (existing loop); refresh release can't fail (drop); turn end (return/`Err`/Stop/panic) → drop, `owed` debt paid by forgetting. Readers of shared state: every turn refresh and every raw `PerCall` call reads `limiter::current(provider_id)`; writers are the four existing `limiter::set` sites (`providers::endpoint` build, create, update, `/props`-bumped reload — `providers/server.rs:165/475/516/702`) and `forget` (delete); the race between a refresh's `current()` and a `set` landing is bounded by `Endpoint::slot`'s existing re-look-up loop. Work already in flight: a `save_limit` mid-turn resizes the pool the turn waits on and the wait completes against it (SME-162, green suite); a turn that holds keeps `TurnSlot`'s recorded slot until the refresh or turn end.

## Decisions the ticket left open

- **Yield rule (waited-past-a-bound): not planned in this ticket — Question 1**, recommendation defer to a follow-up. Reasons: it needs machinery the pool doesn't have (wait-age tracking per waiter, a policy bound, a yield check at iteration boundaries); it rests on the semaphore handing freed permits strictly oldest-first — the ticket's "the semaphore is FIFO" claim, which I did not verify and deliberately do not build on here (plan.md's outside-tool-claim rule); and the ticket's Done-when marks it conditional. Its cost is real (below) and bounded, and the follow-up can tune the bound against real Tempo data this ticket produces.
- **Prefer-the-recent-holder scheduling: deferred, follow-up filed** (Backlog, this project, linked related) — it changes *who* wins a freed slot (heuristic + scheduler), not what this ticket holds; the ticket itself marks it "possibly a follow-up".
