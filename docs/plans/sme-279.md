### What

`start_agent` with a `repo` requires the checkout's remote trusted (`repo_trust.trusted`). Trust arrives only by the user opening the repo ("Work on a repo") or by the model's `load_instructions` on an AGENTS.md — and a repo without an AGENTS.md can never take that second path. From a conversation where the model cloned such a repo itself there is no door: the user can't trust it and `start_agent` on it is refused for good; SME-236's review only reworded the refusal to point at the detour.

The fix: `create_child`'s undecided arm — which already holds the remote's trust lock — records a trust card for the repo itself and the refusal tells the model the user is being asked. The card is one `instruction_requests` row with sentinel path `''`: one per checkout row, no migration. On Trust, `settle` loads no file; the notices say agents can now be started. The chat card shows repo-level copy with no file preview.

### State model

Record: the one `instruction_requests` row with `path = ''` per checkout row.

- **States:** absent → pending (a refused `start_agent` inserts, or re-upserts on repeat) → decided-trust (row deleted, `repo_trust.trusted = true`) | decided-decline (row deleted, `trusted = false`) | gone (conversation or checkout deleted; FK cascades).
- **Writers:** `create_child`'s undecided arm (insert/re-upsert); `settle` (`take_instruction_request` for the answered card, `drop_cards_for_remote` for the rest); `trust_named_remote` via the same drop; deletes cascade. Not writers: `request_or_load`'s `delete_instruction_request_for` (`src/git/server/instructions.rs:213`) matches only a real `AGENTS.md` path — `resolve_instructions_path` (`:171,175`) can't produce `''`; `end_start` deletes the child's cards, never the parent's; the Git page's Forget (`delete_repo_trust`) can't race a pending card (only a decision makes cards, and it drops them in the same transaction) — Forget then asks again next refusal.
- **Readers:** `repo_summary`/`list_repos` (the card UI, `publish_repos` payloads); `decide_trust` (any tab, any conversation's card for that remote); `WAITS_FOR_USER` — sidebar mark, tree, banner, `list_agents` `waiting_for_user`; `idle_agent_without_report`; the notices builders. No reader caches the row's meaning beyond `path == ''`.
- **Transitions, each one transaction under `lock_remote_trust`:** the refused `start_agent` commits the card with the refusal (any SQL error rolls the whole thing back: no child, no card, the tool says "couldn't start the agent"); a decision takes/drops/sets/unloads all-or-nothing (SME-181); a conversation delete racing a decision either finishes first — `share_lock_conversations_for` then says the conversation is gone and the decision refuses, as today — or waits.
- **Races between writers:** `start_agent` vs a decision: the advisory lock orders them — decision first → the child is created, no card; card first → the decision answers it. Two conversations, one remote: one card per conversation's own checkout row; whichever decision lands drops both and tells both, wording per card kind. Two tabs, one card: `take_instruction_request` answers once; the second answer gets today's "it may have been answered already". Repeated refused `start_agent` while pending: one row, same id.
- **In flight:** the refusal is a tool error — the turn keeps running; the card shows at once via `publish_repos`. A decision taken during the parent's running turn queues its notice, delivered after the turn (today's `decide_trust` path, unchanged). A child mid-start whose remote is Forgotten mid-clone still fails (`prepare`'s re-read, `src/agents/start.rs:218`), unchanged.
- **Restarts:** the row is Postgres state; a reconnecting tab refetches repos; the model's memory of the refusal is its transcript only, and the decision's queued notice is what reaches it.

What each caller does in each state:

| Caller | undecided, no card | card pending | trusted | declined |
| -- | -- | -- | -- | -- |
| model's `start_agent(repo)` | insert card, refuse ("a card is asking them now") | re-upsert same row, refuse same | create the child (today) | refuse "the user declined…" (today) |
| the user's card | — | Trust / Don't trust | gone | gone |
| "Work on a repo" | trust, no card (today) | drop the card, tell with agent wording | re-trust (today) | re-trust |
| open tabs | — | card appears (`publish_repos`) | card disappears | disappears |
| sidebar / tree / banner / `list_agents` | not waiting | waiting — already counts cards | not | not |
