## What and why

The user (2026-11-11): filter out conversations that are no longer relevant, so the PM's live sub-agents are easy to find among many finished Ticket Drivers. A top-level conversation gets an `archived_at` mark. The sidebar hides archived trees by default, a "Show archived" toggle brings them back marked as archived, and `POST /api/conversations/{id}/archive` / `/unarchive` let a PM archive a Driver's tree once its ticket is Done. Archiving changes nothing else: messages, pods, storage, turns, agents and URLs are untouched.

## Decisions to settle (Planner's recommendation; the Driver decides)

- **D1. An owed answer is never hidden.** An archived tree is still shown in the default sidebar while **any** conversation in it (root or agent, any depth) has `waiting_for_user` (an `ask_user` card or a trust card, `db::WAITS_FOR_USER`) or a gated `report_owed_at` (the `!` mark). It shows with its normal marks and an "archived" tag, and drops out again on the next refetch once nothing is owed. On top of that, nothing that tells the user something is waiting reads the sidebar's filter: the phone's folded-list count (`waiting_total`) counts the **unfiltered** list, and the desktop notifier, the `(N) smelt` title count, the attention API and the "agents waiting" banner over a parent's chat read the server, never the filter, so they are unchanged. Tested: unit tests on the filter (below, T6 in particular) and the browser scenario's owed step (T11 step 3, which also reads the phone button's count).
- **D2. Archiving a running conversation is allowed.** It's a view mark only; refusing would make a PM poll for idleness first and buys nothing. A running (busy) archived tree with nothing owed stays hidden: working isn't owing, and a Driver's last turn ending after the PM archived it shouldn't make it flicker back. If that turn ends owing something (a question, a report), D1 brings it back.
- **D3. A user's send unarchives the tree.** `send_message` (`start_turn`, the user-turn path only) to any conversation in an archived tree clears its root's `archived_at`, after the turn is admitted (`confirm_user_turn`), next to `clear_report_owed`, and publishes `ConversationsChanged`. Someone writing to it means it's in use again; without this, the row would vanish as soon as the user navigates away mid-conversation. Not unarchived by: an agent's wake, a delivered report/notice/`message_agent`, answering a question card (`/question/answer`), a trust decision, or `stop`. A PM's own `POST .../messages` to an archived Driver does unarchive it (same endpoint, same meaning). If the unarchive write fails, the turn still runs; the failure is logged (`tracing::warn!`), as `clear_report_owed` does.
- **D4. Only top-level conversations are archived; a child follows its root.** `archive`/`unarchive` on a child id is refused with **409** and the message `only a top-level conversation is archived: archive its root, conversation {root_id}` (the root from `agents.root_id`, falling back to walking `parent_id`). A missing id is the usual 404 (`conversation_not_found`). The tree API reports each node's **effective** state, its root's `archived_at`, so a PM listing the tree sees a Driver's whole subtree as archived.
- **D5. Idempotent, and `updated_at` untouched.** Archiving an archived root returns 200 and keeps the first `archived_at` (`COALESCE`); unarchiving an unarchived one returns 200. Neither bumps `updated_at`, so the list order (most recently active first) doesn't change; there is no trigger on `conversations` (checked: no `TRIGGER` in `migrations/`).
- **D6. The control is in the conversation header**, an Archive / Unarchive button in `.conversation-header-top` next to "Show thinking", shown for a top-level conversation only. Not the row: a row already holds Delete's two-step button, and SME-481 is changing the row; the header is this ticket's own. The row change is only the "archived" tag.
- **D7. The open conversation's tree stays listed** even when archived and hidden, so a conversation opened by URL, or archived from its header, keeps its highlighted row until the user moves away.
- **D8. "Show archived" is per tab, not stored**: a `GlobalSignal<bool>` like `FOLDED`, off on every load. Shown only when the list has at least one archived root, labelled `Show archived (N)` / `Hide archived`, N the number of archived roots. No search box (optional in the ticket; not cheap enough to add here).
- **D9. `GET /api/conversations` carries the row's own `archived_at`** (`Conversation` gains the field): set on roots only, always null on a child. The tree is the API that answers "is this conversation archived" for every node; docs say so.

## How

**Data.** `conversations.archived_at TIMESTAMP NULL`, null = in use. Written only on rows with `parent_id IS NULL`.

**API.** `POST /api/conversations/{id}/archive` and `/unarchive`, no body, return the updated `Conversation` (with `archived_at`). Errors: 404 `conversation not found`; 409 for a child (D4). `GET /api/conversations/tree` nodes carry `archived_at` (effective, the root's). `GET /api/conversations` carries the row's own (D9). A PM's flow: list the tree, find the Driver's root id, `POST .../archive`.

**UI flow.**
1. The tree fetch brings `archived_at` on every node.
2. `archive::visible` drops each archived root's tree unless the toggle is on, something in it is owed (D1), or it holds the open conversation (D7). `build_tree` runs on what's left, unchanged.
3. Above the list, when `archived_roots > 0`: `button.show-archived` with `aria-pressed`, `Show archived (N)` / `Hide archived`.
4. A row whose node has `archived_at` (shown by the toggle, D1 or D7) gets `span.conversation-archived "archived"` after its marks and before the age; a child row in an archived tree doesn't repeat it (only the root carries the tag).
5. The header of a top-level conversation shows `button.conversation-archive` "Archive" or "Unarchive".

**Where new UI goes.**
- *Toggle:* in the sidebar body, between the error lines and `.conversation-list`, full sidebar width, one line. Laptop: the sidebar's fixed width; phone: inside the opened drawer only. It covers nothing; it pushes the list down one line.
- *Tag:* inline in the row's mark strip. The narrowest row is a depth-3 agent in the sidebar at its narrowest; but the tag is on roots only (depth 0), where the title already ellipsizes; check at the sidebar's narrowest width with a long title, the `?N` count, the pod dot, the `!` and the age all present, that the tag and Delete stay inside the row.
- *Header button:* in `.conversation-header-top` after "Show thinking". The title (`h1`, already ellipsized) gives way. Check at a phone width (360px) and at the narrowest laptop layout with both side panels open (the todo list and the sandbox panel), with a 60-character title: both buttons stay on one line and the title shortens.

**What's not done:** archiving a child (D4), a search box, a remembered toggle, bulk archive, an "archived" filter on `get_conversations`.

## State model

`conversations.archived_at` on a root: **in use** (null) ⇄ **archived** (a time).

| Transition | Who | What else sees it |
|---|---|---|
| in use → archived | the header button; `POST .../archive` (a PM, curl) | `ConversationsChanged` → every tab's sidebar and header refetch the tree |
| archived → in use | the header button; `POST .../unarchive`; a user/PM `send_message` to any conversation in the tree (D3) | same event |
| archived → archived / in use → in use | the same calls again | nothing changes (D5); no event needed, one is harmless |
| row deleted | Delete (cascade) | as today |

Writers: `db::set_archived` (both endpoints) and `db::unarchive_root_of` (`start_turn`). Each is one `UPDATE`, so there's no partial state: the event is published only after the write returns, and a failed write publishes nothing (the endpoint returns 500; `start_turn` logs and runs the turn). Racing writers (a PM's archive and a user's send in the same instant): last write wins, both are a full statement of the user's intent at their moment, and the next tree fetch shows the result everywhere; a send that loses to an archive leaves an archived tree the user is looking at, still listed by D7.

Readers: `get_conversation_tree` (sidebar, header, any API client) and `get_conversations`. The sidebar's filter is client state per tab. A restart loses nothing (database column); the pod is never involved.

**Work in flight:** a running turn never reads `archived_at`; archiving mid-turn changes nothing about it (D2). A turn that ends owing the user something makes D1 show the tree on the refetch that turn end already causes (`QuestionsChanged` / `TurnsChanged`).

**What each sidebar reader does per state:**

| Tree's state | default sidebar | toggle on | phone count / notifier / banner |
|---|---|---|---|
| in use | shown | shown | unchanged |
| archived, nothing owed, not open | hidden | shown, tagged | unchanged (nothing to count) |
| archived, something owed | shown, tagged, with its `?`/`!` | shown, tagged | counted / notified as today |
| archived, holds the open conversation | shown, tagged | shown, tagged | unchanged |
| archived, busy, nothing owed | hidden (D2) | shown, tagged | unchanged |

## Trade-offs to flag

- An archived tree that is **running** stays hidden (D2): its "Working" spinner doesn't show in the default sidebar. Only an owed answer or report brings it back.
- A user's or PM's send unarchives (D3): a PM that messages a Done Driver un-archives it, and must archive it again if it wants it hidden.
- `get_conversations` reports a child's own `archived_at` (always null); only the tree reports a child's effective state (D9).
- The toggle isn't remembered across reloads (D8).
