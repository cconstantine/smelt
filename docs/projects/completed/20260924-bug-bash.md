# Bug bash

**Branch:** `bug-bash` · **Plan:** `projects/plans/bug-bash.md` (removed)

## What shipped

A deliberate hunt for bugs, done 2026-09-24. There were two code sweeps (the chat turn loop and streaming, the chat UI's state, background tasks, the event bus, sandbox volumes) and three hands-on sweeps against a real dev server with a real model (core chat flows, reloads, a second tab, the settings pages). They found 15 issues. 13 are fixed here, one commit each, each starting from a test that failed on the unfixed code (the one exception is noted under #11).

### High

1. **New messages only reached the tab that sent them.** `ConversationEvent::MessagesAppended(Vec<Message>)` was a tuple variant in an internally tagged enum, which serde can't serialize, and the send error was discarded. So no other tab, and no page after a reload, ever got a message live. That covered every reply the model makes without a live send: after a background task finishes, after a terminal command finishes. Now a struct variant, with a JSON round trip test for every variant and a browser scenario where a watching tab sees a reply it didn't ask for.
2. **One volume with a missing claim stopped every new sandbox, reported only as "Timeout".** Every volume is mounted into every pod, so a claim missing from the namespace (after a cluster rebuild, or a volume created from another namespace) left every pod `Pending` until the timeout. `SandboxManager::create` now recreates missing claims first (proven against the real cluster). The timeout carries the pod's own reason. A container stuck in a state that won't recover (an image pull failure, a crash loop) fails at once. Mount paths must be absolute, as the form already said. This was misdiagnosed at first; see the retrospective.
3. **Compaction re-summarized the whole history every time.** Each compaction's input included everything earlier compactions had already replaced, so it grew until the summarization call no longer fit, and then every turn failed. It now summarizes the previous summary plus what came after its boundary, capped to fit the window.

### Medium

4. **A missing conversation looked usable**, and sending there showed a raw foreign-key error. It now says "This conversation doesn't exist" with no message box. The server returns `conversation not found`.
5. **Model-provider errors showed raw, with no retry.** A 429/503/529 now gets two more attempts (1s, then 3s), and a failure shows the provider's own message, not nested JSON with "(details: None)".
6. **The sidebar never refreshed a title.** A shared counter now makes the sidebar refetch when messages arrive or a send finishes.
7. **Every live event subscription leaked** when its tab went away (`ServerEvents::new` never notices a disconnect). It now uses `ServerEvents::from_stream`, the same fix #22 made for the browsing frame stream.
8. **A failed background-task notification disappeared silently.** It now publishes `NotificationDeliveryFailed` like the terminal-command path, with readable error text on both.
9. **Deleting a conversation left its background tasks running.** They're now stopped and forgotten on delete.

### Low

10. **A background-notification error followed you to every conversation.** It's now cleared on a switch.
11. **The context meter briefly showed the previous conversation's numbers after a switch.** It's now cleared on a switch. No failing test first: the stale value only showed until the new conversation's snapshot arrived, too brief for a browser test to catch reliably.
12. **In-memory registries only grew.** Deleting a conversation now drops its tasks, event channel and turn lock.
13. **With no credentials configured, a sent message vanished on reload.** It's now saved before the credential check.

Also: the proxy's request counter is built only for the browser tier that reads it, which removes a dead-code warning from `cargo test --features server`.

### Not done

- **#14, a multi-step reply streams as one merged bubble.** `send_message` sends its `Done` events only after the whole tool-use loop, so the text from several rounds runs together while it streams, and the tool calls appear at the end. This is a UX change, not a defect with a clear right answer. Worth its own small project if it bothers in practice.
- **#15, `dx`'s "Your app is being rebuilt" overlay with no rebuild.** Dev-only and harmless; already noted in testing.md as a red herring.
- **Finished tasks in live conversations still stay in memory** (with their full output) until the conversation is deleted or the server restarts. That's fine at single-user scale; a time-based sweep can come later if it matters.
- **The hands-on sweeps left about ten conversations in the dev database**, mostly titled "New Conversation". Delete them from the sidebar if they're in the way.

## Retrospective

**What worked:**
- **Running the app, not just reading it.** The worst bug (#1) was invisible to the test suite and to a code read that trusted the tests. It showed up as soon as a second tab was open. Running things found #1, #2, #4, #5 and #6; the code sweeps found the rest.
- **Marking every finding confirmed, confirmed-by-code, or suspected.** It kept the plan honest about what had actually been seen, and it pointed to where the misdiagnosis (#2) could hide: the finding was "confirmed", but only its symptom was.
- **Watching each test fail first, including tightened checks.** This caught a partial fix for #6 (refreshing the sidebar only on `MessagesAppended` missed the tab that had switched away) and proved #8's readable-message check was really exercised.
- **Grouping by root cause, not symptom.** #1 alone explained four symptoms from the sweeps (the second tab, the reload, background replies, terminal-command replies), so fixing it first shrank the list.

**What caused friction, surprise, or rework:**
- **#1 existed because the tests checked the event before it crossed the wire.** Every event test inspected the value inside the server; none serialized it. A type that crosses the server/browser boundary needs a test at that boundary. `wire_tests` does that for `ConversationEvent` now, but the gap is general.
- **#2 was first blamed on the wrong cause.** The relative mount path was the obvious suspect, and removing the volume made the symptom go away, which looked like proof. A real-cluster probe showed a pod with a relative path starting in 5 seconds; a second probe found the missing claim. The first diagnosis would have shipped a validation that fixed nothing. This is the development-process rule about real-environment failures again, and it also applies to a diagnosis written into a plan, not just to a fix attempt.
- **A timeout that says only "Timeout" cost most of that time.** The pod had been reporting the real cause (`persistentvolumeclaim … not found`) the whole time; nothing surfaced it. Now it does.
- **One finding couldn't be tested first (#11).** A stale value that lasts only until a fetch returns can't be caught reliably from a browser test without a way to delay that fetch. It was fixed anyway and said so, rather than writing a flaky test.

**Process changes (confirmed and applied to development-process.md):**
- A type that crosses the server/browser boundary gets a serialization round-trip test for every variant (under Rules). #1 is the example.
- A bug bash every three projects or so, with at least one hands-on sweep using two tabs and a reload (a new "Bug bash" section). Each close-out says whether one is due. Most of what this one found sat in flows no single project owned.
