# Child agents

Part of [api.md](../api.md). How a conversation's model starts agents, hears from them, writes to them and stops them (SME-236, SME-238). The design is [docs/design/personas/agents.md](../design/personas/agents.md); the code is `src/agents/` (the lifecycle), `src/anthropic/tools/agents.rs` (the tools), `src/db/agents/` (the rows) and `src/git/server/child_ref.rs` (the child's checkout).

A child agent is a whole conversation with a `parent_id`: its own transcript, model, streaming, Stop, usage and sandbox, which the user can open and write in. Its lifecycle is `agents.state`: `starting`, `active`, `finished`, `stopped` or `failed` (see [database.md](../database.md)).

## The tools

Six tools, at the end of the registry so every older tool keeps its place in the request. A tool's `Offer` says who is given it (`tool_definitions(pool, conversation_id)` leaves the others out) and `execute` checks it again from the database, so a call from an older history is refused too.

| Tool | Offered to | What it does |
| -- | -- | -- |
| `start_agent(brief, repo?, ref?, persona?)` | a conversation without a parent (so agents are one level deep until SME-245) | Records the child (`starting`), its brief as its first message and, with `repo`, its copy of that checkout as `cloning`, in one transaction; spawns its start and returns the child's id at once. |
| `list_agents()` | every conversation | Its own children only, newest first: id, title, persona (`<dir>:<name>`), status, when it started, its last message, how many agents it started. Status is the first that holds of `starting`, `failed`, `stopped`, `running` (a turn in flight), `waiting for the user` (an unanswered `ask_user` question or an AGENTS.md card), `waiting for its parent` (an unanswered `ask_parent`, SME-238), `finished`, `idle`. |
| `stop_agent(id)` | every conversation | One of its own children and its whole subtree set `stopped` (state first), then each one's turns stopped (`turn::stop_conversation`). Pods and terminals are left alone. Any other id is refused. |
| `finish(report)` | an agent | The child `finished` and its report queued to its parent in one transaction, then the parent woken. A successful `finish` ends the child's turn as `ask_user` does (`run_tools`). A second one is refused, and so is one while a message to the child is unread or an answer to its question untaken (SME-238): it reads that first. |
| `message_agent(to, text)` | a conversation with a parent or agents of its own (`Offer::Linked`) | SME-238: `text` (1–30,000 characters) queued to the caller's parent (`to: "parent"`) or one of its own children (its id), and the recipient woken. See [Messages and questions](#messages-and-questions). |
| `ask_parent(question)` | an agent | SME-238: handled by `run_tools` with `ask_user` (one question of either kind per reply); the question recorded and queued to the parent, and the child's turn ends waiting. |

**`start_agent`'s checks**, all before anything is written: `brief` 1–30,000 characters; `repo` a `/workspace/<dir>` that is one of the caller's `ready` checkouts; `ref` a plain ref (`git::validate_ref`: no whitespace or control characters, no `..` or `@{`, not starting with `-`, not ending in `/` or `.lock`); `persona` a valid persona name, needing `repo`. Without `ref`, the parent's checkout must be on a commit its upstream has (after a `git fetch` in the parent's pod), the upstream a branch on `origin`, with no uncommitted changes to tracked files (`git::parent_commit`; a detached HEAD, no upstream or one that isn't on origin, unpushed commits or a dirty tree is refused, saying what to do; the commit and branch it reports are checked as a commit id and a plain ref), and the persona must be in it now. In the transaction: the remote's trust lock, then the caller's row `FOR NO KEY UPDATE`; the caller must exist, not be `deleting_at`, not be an agent itself, and the remote must be trusted (`repo_trust.trusted`; undecided or declined is refused).

## The start

A spawned task (`agents::run_start`) per child, holding `StartExit`, whose cleanup runs on every way out (done, failed, stopped, deleted, the task dropped): it runs the credentials exit SME-242 fills and, unless the start is done, deletes any AGENTS.md trust card in the child (a done start's load made none, and its first turn may already have asked about another file). With a repo, its pod work goes through `ChildCheckout` (`PodCheckout` in production; tests register a fake per parent):

1. **Clone** (`git::clone_child_repo`): the default branch into the child's pod, then `checkout_ref`: a branch is checked out tracking the remote's, a tag or a commit id detached, a commit no ref reaches fetched by id; without a `ref`, the parent's commit on a branch named as its upstream.
2. **Trust again**, under the trust lock: a remote forgotten while it cloned fails the start.
3. **AGENTS.md**: the checkout's top-level one is loaded (`request_or_load`); a card instead (the remote forgotten since step 2) fails the start.
4. **Persona**: `.agents/personas/<name>.md` read in the child's checkout (symlink-safe), parsed, its relative links made absolute (`personas::links::absolute`), and kept as a snapshot.
5. **Model**: the persona's `smelt.model` on the first provider that has it (the parent's, the default's, then by name); none has it, the child keeps its parent's model and the parent is told.
6. **Done** (`db::complete_start`): `active`, `started_at`, the snapshot and the model, and a notice to the child itself, which its first turn drains; then `Notice::Wake`. A child no longer `starting` (stopped or deleted meanwhile) is left alone.

A step that fails ends the start through `fail_start`: the child `failed`, the error queued to the parent as its report and saved in the child's own transcript. Nothing makes a failed child `active` again.

No turn runs in a child while it's `starting`: the user's send or answer is refused ("This agent is still starting."), a wake is a no-op and a delivered notice is only saved (`admits_notices`). A `stopped` or `failed` child is treated the same way for wakes and notices, so it stays quiet even after a restart loses the Stop's pause (review 1). The user's send or answer in a `finished` or `stopped` child that had started makes it `active` (`admit_user_turn`); one in a `failed` child, or one stopped during its start, is refused (an answer before it's recorded). Once the turn is counted the state is read again (`confirm_user_turn`), so a parent's `stop_agent` landing in between refuses the send; and a user's turn that queued behind a turn which called `finish` makes the child `active` again once it holds the turn lock (`resume_finished`), so it can report again.

## The queue

Reports and notices reach a conversation through `agent_messages`, never `Notice::Deliver`: `drain_agent_messages` runs beside the two command drains at every iteration of `run_turn_steps`, so a busy parent takes a report between a tool result and its next call, and several arrive in one model call, in the order they were queued. Each row is saved as one `user` message (`Report from agent #12 (smelt:developer):` + the report, `Message from agent #12 (smelt:developer):` or `Message from your parent:` + a message, `Question from agent #12 (…), which waits for your answer (reply with message_agent to 12):` + a question, or `Notice: …`) and marked delivered in one transaction (`db::deliver_agent_message`). `db::wake_has_work` counts undelivered rows. Every writer queues in the transaction of the state change it reports, then wakes the recipient (`Notice::Wake`):

- `finish` (report), a failed start (report), the start's done step (a notice to the child itself; and to the parent when the persona's model wasn't found);
- the user's Stop on an `active` child not already paused (`agents::user_stop`, a notice to its parent); a Stop on a `starting` child is refused;
- a child's last turn ending while it's `active` with nothing to wait on (no unanswered question, card, running command or live agent of its own) and not paused (`agents::after_last_turn`, a notice with the first 500 characters of its last reply, and the failure when the turn failed); not after a stop, nor a wake that did nothing;
- deleting a child (a notice to its parent, in the delete's own transaction);
- `message_agent` and `ask_parent` (SME-238, below).

**At startup** (`agents::startup_sweep`, after the clones a restart cut off are failed): every child still `starting` fails with "smelt restarted during the start", every agent `active` and not paused whose last message is a turn's with no reply after it (a tool result, or a row the queue delivered; not a notice saved while it was idle, nor the user's own message) and which isn't waiting on a question is queued `smelt restarted during your turn; carry on` (once, however many restarts), and every conversation with undelivered rows, or an agent with an answer it hasn't taken, that isn't a `stopped` agent nor paused is woken. The pause after a Stop is stored (`conversations.paused_at`, SME-238) and restored by `turn::restore_pauses` in `main` before the pod watch, the idle-command watch and this sweep start, so a conversation the user stopped stays quiet across a restart.

## Messages and questions

SME-238. **`message_agent`** resolves `to` (`parent`, or an id that must be one of the caller's children; anyone else is refused as `stop_agent` refuses one, without saying whether it exists), then in one transaction (`db::message_agent`): both `conversations` rows `KEY SHARE` in ascending id; the recipient's `agents` row `FOR NO KEY UPDATE` (a root parent has none), so a `stop_agent`, a `finish` or a delete's marking lands wholly before it or waits; refused if the recipient is `deleting_at`, `stopped` or `failed`; a `finished` child made `active`; then, for a child waiting on its parent whose question the parent has read (its `question` row, which shares the question's `created_at`, is delivered), the reply is written as the question's answer (`UPDATE … WHERE asked_of = 'parent' AND answer IS NULL`) and nothing is queued; else a `message` row is, so a message the parent sent before reading the question isn't taken as the answer (review 1). After the commit the recipient is woken: an idle one runs a turn, a busy one reads it at its next step, a paused one (the user's Stop) waits for the user, and a `starting` one reads it in its first turn. A message to a child that was `finished` is read by the woken child, which can `finish` again.

**`ask_parent`** (`db::ask_parent`): the child's `agents` row `FOR SHARE` must be `active`, and the parent neither being deleted nor a `stopped` or `failed` agent; then a `pending_questions` row `asked_of = 'parent'` (header "Question for your parent") and a `question` row to the parent, in one transaction, and the parent woken. No question card or sidebar mark appears. The child's woken turn takes the answer through `take_answer_or_wait`, and the call's result is `Your parent answered:` + the reply. If the user writes in the child first, their message takes the question with `questions::NOT_ANSWERED_BY_PARENT`, and the parent's later reply arrives as a plain message; the parent isn't told the user stepped in. A child waiting on its parent gets no "ended without a report" notice.

## Deleting

`delete_conversation` deletes the whole subtree (`agents::delete_subtree`): transaction A locks the group root's row (the lock `start_agent` takes) and marks the subtree `deleting_at` and its agents `stopped`, so a `start_agent` after it is refused; every turn and browsing session in the subtree is stopped and its pods listed; transaction B locks the deleted conversation's parent (shared) and the subtree (for update) in ascending id, queues the notice to the parent, and deletes, the cascade removing the subtree; then each conversation's pods are torn down and its turn state and event channel forgotten. The sidebar's armed Delete says how many agents go with it ("Delete + 2 agents?").
