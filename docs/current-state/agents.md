# Child agents

Part of the [Current state](index.md). What a conversation's model can hand off to agents of its own (SME-236, the first ticket of "Personas and sub-agents"; the design is [docs/design/personas/](<https://github.com/cconstantine/smelt/blob/main/docs/design/personas/index.md>), the mechanics [docs/api/agents.md](<https://github.com/cconstantine/smelt/blob/main/docs/api/agents.md>)).

* **Starting one.** Any conversation — the user's own or an agent's — can call `start_agent` with a brief, up to `SMELT_AGENT_DEPTH` levels deep (5 by default; per-persona limits wait on SME-245). The agent is a new conversation, listed in the sidebar like any other and titled by its brief, with its own sandbox; the brief is its first message and the call returns its id at once, so the parent carries on.
* **On a repo, at a ref, as a persona.** With `repo` (one of the parent's checkouts), the agent gets its own clone, at `ref` or, without one, at the exact commit the parent's checkout is on, which must be pushed and clean (otherwise the call says what to do). The remote must be trusted — ask for the first agent on a repo the user hasn't decided about and a trust card for the repo itself shows in the conversation, so the next try works once they decide (SME-279) — and the agent's top-level AGENTS.md is loaded for it. With `persona`, the agent runs under that persona file (`.agents/personas/<name>.md`) as it is at the agent's ref: its instructions go in the agent's system prompt under Persona, links made absolute, and its `smelt.model` picks the agent's model when a provider has it. Editing the file afterwards changes nothing for a running agent. smelt's own repo carries one for every persona in `docs/personas/` (SME-247): its nine process seats run from those files, `.claude/agents` links the directory so the same files are Claude Code subagents, and `repo_lints::personas` keeps them parseable and honest about the tool registry.
* **Hearing back.** The agent ends its work with `finish(report)`; the report arrives in the parent's transcript as "Report from agent #12 (smelt:developer):" and wakes it. A busy parent takes it at its next step; several at once arrive together. The parent is also told when an agent's turn ends without a report (with the start of its last reply), when its start fails (with why), when the user stops it, and when the user deletes it. Reports wait in the database, so a restart doesn't lose them.
* **Talking at any time** (SME-238). A parent and its agent write to each other with `message_agent`: the message arrives as "Message from agent #12 (smelt:developer):" or "Message from your parent:", waking an idle conversation or reaching a busy one at its next step. An agent can `ask_parent` a question and wait: the parent's next message to it, once the parent has read the question, is the answer. Siblings don't write to each other; they go through the parent.
* **Keeping track.** `list_agents` shows the parent's own agents with their status: starting, running, waiting for the user, waiting for its parent, idle, finished, stopped or failed. `stop_agent` stops one and everything under it, leaving its sandbox as it is.
* **Cost.** Each context detail view's "Spent so far" shows the whole group's spend next to the conversation's own (SME-244): the group's root shows "With its agents: …" once an agent's call has landed, and each agent's shows "In <group root title>'s group: …", the same number for every member. A deleted agent's calls keep counting in that number — its usage rows hold the group's root even after its conversation is gone. It's keyed on the tree's root, so a mid-tree parent shows its root's whole-tree figure, not its own subtree's (subtree totals wait on SME-245's nesting).
* **In the sidebar** (SME-246). An agent is listed under its parent, indented, with its status and persona (`idle · smelt:developer`) on a second line; a caret folds a parent's agents away in that tab, and opening an agent inside a folded parent unfolds it. An agent waiting for the user (a question, or an AGENTS.md trust card, which now counts as waiting everywhere) shows "?", every row above it shows how many under it wait ("?2"), folded or not, and the parent's chat has a banner linking each one. On a phone the folded list's button shows the count too. A paused agent reads "idle".
* **The user's part.** The user can open an agent and watch or write to it like any conversation; writing to a finished or stopped agent wakes it again, and their Stop on it tells its parent. Deleting a conversation deletes its agents too, and the Delete button says how many ("Delete + 2 agents?").
* **Restarts.** A conversation the user stopped stays paused across a restart, for every conversation, not only agents. An agent whose turn a restart cut off is told "smelt restarted during your turn; carry on" and carries on.
* **Tool classes** (SME-237). Every tool, smelt's own and every MCP server's, has a class: read-only, writing or destructive, an MCP tool's from its server's annotations (unannotated is destructive) and `http_request`'s by its method. It shows on each call's trace span, and the rules below decide by it.
* **Tool rules** (SME-241). A persona's `smelt.tools` (grammar: [design/personas/tool-rules.md](<https://github.com/cconstantine/smelt/blob/main/docs/design/personas/tool-rules.md#the-grammar>)) says which tools its conversation is offered and which it may call: a class ceiling plus allow/deny patterns over smelt tools and `<server>/<tool>` MCP names. One evaluation decides both, server-side — a refused call comes back as a tool error naming the rule, before the tool runs or the MCP request is sent, so a `read-only` persona is offered `http_request` and its `POST` is refused. What a conversation is judged by is the **chain** stored on its agent row at start — its parent's chain, then its own persona's rules — so nothing re-reads persona files, and editing one changes nothing for a running agent. A pattern that names no configured MCP server is reported, not fatal (`list_personas` says it, as does `start_agent` to the parent), and naming a new MCP server with `/` or `*` in it is refused — a server already named that way is reported on its own page, which says its tools can only be ruled on by class.
* **Credentials** (SME-242). A persona's `smelt.credentials` names what its pod holds: the built-in `git-ssh` (the user's git key, following the parent chain — a child never gets more than its parent) and names of the user's named secrets from the Secrets page (`/secrets`, granted by the persona alone, exempt from the chain); absent is none. `credentials::for_conversation` decides once per install — pod start, a live change, and a child's start reconciled before its first turn, key removed on every way out of `starting` a child didn't complete. Files land at `/etc/smelt/keys/` and `/etc/smelt/secrets/` mode 600; secrets are write-only — the page shows a computed display prefix of at most four characters with at least eight bytes always hidden, and the value's line count read-time beside it (SME-334) — and the environment section names paths, never values. ([tool-rules.md#credentials](<https://github.com/cconstantine/smelt/blob/main/docs/design/personas/tool-rules.md#credentials>))
* **Not yet:** volumes shared with an agent (SME-239), the persona-file field `egress` (SME-243), per-persona depth limits and limits on agents at once (SME-245), a button that stops a whole group (the user's Stop stops one conversation), and messages, reports and notices styled apart from the user's own in the transcript (SME-280).
