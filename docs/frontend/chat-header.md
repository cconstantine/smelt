# The sidebar's tree and the conversation header

Part of [Frontend](<../frontend.md>). How the sidebar lays out the conversation tree, hides archived trees and opens rows from the keyboard, and the conversation header's ☰ menu.

**The sidebar is a tree** (SME-246, `chat/sidebar/`). `tree.rs`'s `build_tree` lays the server's flat list out as rows: roots in its order (most recently active first), each followed depth first by its agents in the order they started, indented 14px a level up to three (`--depth`; deeper rows share the cap). A parent's caret (`.tree-caret`, `aria-expanded`) folds its agents away; which are folded is per tab (a `HashSet` in a `GlobalSignal`, since Home and a conversation's page each mount their own `Chat`) and a reload shows them all. Opening a conversation inside a folded parent (the banner's link, a URL) unfolds its ancestors (`unfold_to`), so its row always shows. A node whose parent isn't in the list (a refetch racing a delete) shows as a root. Each row is a `ConversationRow`; an agent's second line (`.conversation-agent-meta`) is its status, then its persona, which the row's ellipsis cuts first, and a row with agents waiting for the user anywhere under it, folded or not, shows their count (`.agents-waiting-count`, "?2"). On a phone the folded list's button shows how many conversations wait. Over the open conversation's chat, `AgentsWaitingBanner` (`chat/agents_waiting.rs`, from `get_agents_waiting`, refetched on `conversations_changed` and `questions_changed`) links each agent under it that waits for the user; it renders nothing when none does.

**Archived trees are hidden** (SME-480, `sidebar/archive.rs`). Before `build_tree`, `archive::visible` drops each tree whose root has `archived_at`, whole, unless "Show archived" is on, anything in it waits for the user or owes a report (an owed answer is never hidden), or it holds the open conversation, so a conversation opened by URL or archived from its header keeps its row until the user moves away. A listed archived root's row says `archived` (`.conversation-archived`). The toggle (`.show-archived`, `aria-pressed`) shows over the list only when something is archived, reading `Show archived (N)` / `Hide archived`; it's per tab (`SHOW_ARCHIVED`, a `GlobalSignal`) and off on every load. The phone's folded count, the notifier, the title count and the banner read the whole list or the server, never the filter. A top-level conversation's ☰ menu has Archive / Unarchive (`.conversation-menu-archive`); an agent's has neither.

**The conversation menu** (SME-513, `chat/conversation_menu.rs`). The header's row is the title, then one ☰ button (`.conversation-menu-button`, `aria-haspopup="menu"`, `aria-expanded`), which opens `.conversation-menu[role=menu]` holding the conversation's actions in order: Show/Hide thinking (a `menuitemcheckbox`), Compact (it opens Compact's popover, `compact_control.rs`), Archive/Unarchive and Delete, last, in `--danger`. `menu_items` gives each header shape its items: Show thinking and Compact always, even before the tree has the row (SME-354 B18); Archive for a listed top-level conversation; Delete for any listed one, since its confirm counts the subtree. The menu follows the APG menu button pattern: Enter, Space or ArrowDown on ☰ opens it on the first item and ArrowUp on the last; the arrows, Home and End move inside it; Escape closes it back onto ☰, Tab closes it and moves on, and a click outside lands on a backdrop that only closes it. An unavailable item is `aria-disabled`, still focusable, and says why on a second line (Compact "once the turn ends"). The header owns `menu_open` and `delete_armed`, and every change goes through the pure `menu_after(event)` (`apply`): Delete's first click arms it in place with the menu left open, its second deletes; a list refetch is no event and changes neither (an armed Delete vanishing under one was SME-505's signature). Deleting the open conversation lands on its parent when it's a listed agent, else Home (`after_delete`). While a compaction runs, a muted "Compacting…" (`.conversation-compacting`) sits beside ☰. The header's root names its conversation (`data-conversation-id`) for the browser tier. Browser scenario `conversation_menu`.

**The sidebar's rows open from the keyboard** (SME-58): each row's title is its link and a tab stop (`role="link"`, `aria-current="page"` on the open one) that Enter or Space opens, with its caret beside the link rather than inside it. A row has no Delete of its own any more: it's the header's ☰ menu's (SME-513), which Enter on ☰ opens on its first item, End reaches and Enter arms without leaving the page (browser scenario `conversation_rows_by_keyboard`). The message box has a label for a screen reader (`.visually-hidden`), since its placeholder goes as soon as anything is typed.
