# Feature checklist: MCP, git and language servers
Part of the [Feature checklist](index.md).

MCP servers and their sign-in, git keys and repos, AGENTS.md, language servers.

| Ticket | Feature | How to check in the browser |
| -- | -- | -- |
| SME-15 | MCP servers | `/mcp-servers`: status badge; create a server with a header (value never shown again); edit; delete; an MCP tool used in chat. An unreachable server shows Unreachable and doesn't slow turns |
| SME-16 | MCP OAuth | New-server form: OAuth fields render; an OAuth server's page shows Connect (the full consent flow is the SME-65 row) |
| SME-65 | MCP OAuth with a real provider | On `/mcp-servers`, add `https://mcp.linear.app/mcp` with OAuth and no client ID, click Connect and approve in Linear: you land back on the server's page, Connected with its tool count. Connect again and deny consent instead: the page shows Linear's own "denied" message, not "smelt couldn't verify the authorization provider's response". GitHub (`https://api.githubcopilot.com/mcp/`) works the same with a pre-registered OAuth App's client ID and secret, provided the app's callback URL covers `/oauth/mcp-callback/<id>` |
| SME-32 | Git: keys, repos, AGENTS.md | On "Git" (sidebar): set a name and email, generate a key (its public key copies); with a key there, there's no form to add another; delete it, then import a pasted private key (a passphrase-protected one is refused with how to fix it). In a new conversation, "Work on a repo" with a public repo that has an `AGENTS.md` (e.g. `https://github.com/agentsmd/agents.md`): the sandbox starts and the panel shows the checkout (branch · commit) and "AGENTS.md not loaded"; ask the model to load its instructions: no trust card (you picked the repo), the panel says "Loaded AGENTS.md", and the context view lists it under Project instructions with its repo and commit. Ask the model to clone a different repo with an `AGENTS.md` and load it: a trust card shows exactly that file; Don't trust (the model is told it isn't loaded), then Forget it on the Git page, ask again, and Trust: the card goes, the model is told, and Git lists it as Trusted. Ask the model to edit that `AGENTS.md` and load it again: the context view shows the new version. With the key added to your GitHub account, ask the model to commit and push a change to a test repo: it lands. Stop the sandbox and start another: the checkout and any uncommitted file are still in `/workspace`. Dev: run `scripts/build-sandbox-image.sh` after pulling |
| SME-35 | Language servers | On "Language servers" (sidebar), "+ Add a language server": look up `no-such-server` (says the registry has no such package), then `rust-analyzer` (the form fills: `rust:1`, `.rs`), and add it; add `pyright` the same way; a second `pyright` is refused by name. Edit one's memory limit ("Saved.", still there after a reload); a name with capitals is refused; delete one with the two-step button. In a conversation, ask the model to make a small Cargo crate with two files in `/workspace`, start rust-analyzer, find a struct's definition and a method's callers with the `lsp` tool, then introduce a type error with `edit_file`: the edit's result lists `error[E0308]` with its line, and the fix's says no errors. Rows read "Started rust-analyzer", "Looked up … at path:line". `/pods` shows "Language servers: rust-analyzer ready, … of 2Gi" under the pod. Stopping the sandbox removes the server with it |
| SME-70 | Empty catalog URL settings | Start a check server with `-- SMELT_MASON_REGISTRY_URL= SMELT_HELIX_LANGUAGES_URL=`; on "+ Add a language server", look up `rust-analyzer`: the form fills (`rust:1`, `rs = rust`) instead of "Couldn't reach mason's registry: builder error" |
| SME-49 | Cloning without a sandbox first | In a new conversation (no sandbox), ask the model to clone a public repo (e.g. `https://github.com/agentsmd/agents.md`): its first `clone_repo` call succeeds, the sandbox panel shows the sandbox starting and then the checkout, with no `create_pod` call and no "no sandbox yet" error |
| SME-113 | OAuth MCP servers stay signed in | With GitHub and Linear connected on `/mcp-servers`, leave smelt running past a token's life (GitHub 8 hours, Linear about 24) and ask the model to use a tool from each, e.g. list open PRs on a repo and list Linear tickets: both work with no Reconnect, and both badges still read Connected. Then revoke smelt's app at [github.com/settings/applications](<http://github.com/settings/applications>) and restart smelt: on `/mcp-servers` GitHub reads "Sign-in expired" in amber; its page says "Sign-in expired — use Reconnect below." and offers Reconnect and Disconnect; Reconnect brings back Connected |
| SME-166 | A sign-in started before a URL edit isn't saved onto the new URL | On `/mcp-servers`, add `https://mcp.linear.app/mcp` with OAuth (the SME-65 row) and click Connect. Before approving in Linear, open the server's page in another tab, change its URL (e.g. add `?x=1`) and Save; then approve in the first tab: you land on the server's page with "This MCP server's address was changed, or the server deleted, while you were signing in, so the sign-in wasn't saved. Click Connect to sign in to its current address.", and it isn't Connected. Click Connect again and approve: Connected. Automated: `mcp_oauth` tests, including one with the URL changed while the code exchange is in flight |
| SME-171 | A language server whose install dies ends its start at once | On "Language servers", add a server with image `debian:trixie-slim`, install `head -c 1G /dev/zero \| tail`, command `cat`, memory limit `128Mi`. In a conversation with a sandbox, ask the model to start it: within about a minute (not 10) the tool result says it stopped during its install, OOMKilled, and to raise its memory limit; `/pods` shows no server left. Delete the server afterwards. Automated: `lsp::pods::tests::cluster::test_an_install_that_runs_out_of_memory_says_so_at_once` and `test_a_server_pod_deleted_during_its_install_ends_the_start` |
| SME-172 | A file changed in a terminal doesn't stop an `lsp` rename | In a conversation with a sandbox and the SME-35 crate (`main.rs` using `Square` from `shapes.rs`), start rust-analyzer and ask for references on `area` in `shapes.rs` (that opens it in the server). In the terminal run `echo '// appended' >> src/shapes.rs`, then ask the model to rename `Square` to `Tile` from `main.rs` with the `lsp` tool: the first call says "Renamed to Tile in 2 files" (not "changed since the server last saw it … Try again", every time), and `shapes.rs` still ends with `// appended`. Delete the conversation afterwards. Automated: `lsp::manager::cluster::test_rust_analyzer_from_the_catalog_answers_across_files` (also stale positions after a line is added above, and a deleted open file) |
| SME-168 | No text in a link shows as an MCP sign-in error | On `/mcp-servers`, add a server with OAuth (any URL, e.g. `http://127.0.0.1:9/mcp`). Open `/mcp-servers/<id>?oauth_error=hello`: no error shows, only "Not connected". Open `/oauth/mcp-callback/<id>?error=access_denied&error_description=hello&state=forged`: you land on `/mcp-servers/<id>` with nothing after it in the address bar, showing "smelt couldn't verify the authorization provider's response…" and no "hello"; reload: the error is gone. Delete the server afterwards. Automated: `mcp_oauth::tests::callback_errors` and the browser scenario `oauth_callback_error_link` |
| SME-177 | A forged callback can't cancel an MCP sign-in or replace its error | On `/mcp-servers`, open an OAuth server (Linear, `https://mcp.linear.app/mcp`) and click Connect. Before approving at Linear, open `/oauth/mcp-callback/<id>?code=x&state=forged` in another tab: it lands on the edit page with smelt's "couldn't verify" message. Back in the first tab, approve: the server shows Connected. (Before SME-177 the approval landed on "no OAuth authorization attempt in progress".) The refresh-versus-Reconnect race (a refresh saved only over the grant it refreshed) isn't web-checkable; automated: `db::tests::mcp::test_a_refresh_racing_a_reconnect_keeps_the_new_grant` and `mcp::tests::oauth::test_a_refresh_finishing_after_a_same_client_reconnect_keeps_the_new_grant` |
| SME-181 | A trust card answered twice at once settles once | Open one conversation in two tabs, with the SME-32 row's trust card showing in both. Click Trust in one tab: the card goes from both tabs and the file loads. Clicking Don't trust in the other tab before its card goes shows "it may have been answered already", and the Git page still says trusted. The millisecond race itself isn't web-checkable. Automated: `git::server::trust_race_tests` (Trust and Decline on one card, on two conversations' cards, and a card asked for while a Decline waits; SME-224: a card asked for while "Work on a repo" waits, a conversation deleted while it drops that conversation's card, and it racing a delete of a conversation with two cards); `api::git::tests` (SME-225: a decision and a "Work on a repo" whose request is dropped mid-way still commit and tell the models, and an attach failure nobody waits for shows in the conversation) |
| SME-182 | Catalog values go into the install command as single shell words | On "Language servers", "+ Add a language server", look up `actionlint`: the install command has the release URL in single quotes (`curl -fsSL 'https://github.com/rhysd/actionlint/…{{ version \| strip_prefix "v" }}…tar.gz'`), and a note says the asset's name has a template smelt doesn't fill in. Look up `commitlint`: the command reads unquoted as before (`npm install --prefix /tmp/home/lsp @commitlint/cli@… @commitlint/config-conventional commitlint-format-json`). A registry value that is empty, starts with `-` or holds a control character isn't web-checkable (the real registry has none). Automated: `lsp::catalog::tests` (`test_catalog_values_reach_the_shell_as_single_words`, `test_a_value_quoting_cant_make_safe_leaves_the_install_to_the_user`) |
