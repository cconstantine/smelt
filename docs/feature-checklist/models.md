# Feature checklist: Models and providers
Part of the [Feature checklist](index.md).

Model providers, a model per conversation, budgets, caching and costs.

| Ticket | Feature | How to check in the browser |
| -- | -- | -- |
| SME-93 | Replayed thinking a newer Anthropic account refuses | Not web-checkable without an Anthropic account created on or after 2026-08-31 (none is available to the project): on one, start a conversation with thinking on, then change the system prompt mid-conversation (Work on a repo and let the clone finish, or add a sandbox volume) and send again; the reply comes instead of "bound to a different conversation", and the server log says the provider refused the replayed thinking and that it retried. Automated: `anthropic::stream` tests against a mock upstream |
| SME-72 | Model providers, a model per conversation | With no provider (a fresh database, e.g. a check server's scratch one — the default since SME-226 — from a ref with SME-115's fix: `check-server` refuses an older one), a conversation says "No model provider is set up" above the message box with a link, and Send is disabled. On "Model providers" (sidebar), add one: pick a kind (Other fills in bearer auth), a name, the base URL and a key; the edit page never shows the key, only its last four characters (or "Key set" for a short one), and lists the provider's models with a context window read from the provider where it reports one (llama.cpp's `n_ctx`, an Ollama Modelfile's `num_ctx`, Anthropic's `max_input_tokens`) or "unknown, assuming 200,000". Set a model's context window and thinking (provider's default / on / off): "Saved.", still there after a reload. Change the provider's base URL with the key left blank: refused, asking for the key again. Back on the list, make a model the default. The conversation's picker now says "Default: provider · model"; send a message: the reply comes from that model and the picker drops "Default:". With the conversation open in two tabs, Change the model in one (type an id the list doesn't have): both tabs show it without a reload, with a "Context window unknown, assuming 200,000." warning. Delete the provider (two-step): the open conversation's picker goes back to "No model provider is set up" |
| SME-106 | Prompt caching, cost per call, effort | On "Model providers", "+ Add a provider": with the kind Anthropic and the base URL `https://api.anthropic.com`, "Prompt caching" is checked and "Prices from" shows Anthropic (anthropic); switch the kind to Other and type `https://api.deepseek.com/anthropic`: caching unchecks and Prices from follows to DeepSeek. On an Anthropic provider's page, set a model's Effort to low and Save ("Saved.", still there after a reload). Make that model the conversation's and send a message; open the context view: "Spent so far" shows dollars, "1 model call" with its uncached, cache-write, cache-read and output tokens, and "Prices as of" a recent time. Send again: cache read is now most of the input. Back on "Model providers", "Last 30 days" lists the provider and model with the same totals. Delete the provider: its row stays, as "(deleted provider)". At phone width nothing on either page scrolls sideways. Not web-checkable: the request carries both `cache_control` markers, `output_config.effort` and `User-Agent: smelt/<version>` (tests in `anthropic::stream` and `turn`, and SME-106's hands-on check against a mock) |
| SME-112 | Commentary between tool calls stays (llama.cpp) | Needs a llama.cpp `llama-server` provider. In a conversation on its model with thinking on, ask "Say in one sentence what you're about to do, then read my todo list, then tell me what's on it": the sentence before the "Checked the todo list" row is still there after the row appears, after the reply finishes and after a reload, with a Thinking disclosure ahead of it. Send a second message: the reply comes with no provider error (llama.cpp takes the replayed thinking). Automated: `anthropic::stream` and `turn` tests against a llama.cpp-shaped stream |
| SME-111 | A llama.cpp provider kind, a reply budget, a reasoning budget, a cut-off notice | Needs a llama.cpp `llama-server`. On "Model providers", "+ Add a provider", type its address as the Base URL and Tab out: "This looks like a llama.cpp server" appears and the kind doesn't change until you click "Use the llama.cpp kind" (bearer token, caching off, "Keep earlier reasoning" checked). Its page shows a line under Models with the build, model, slots, window and what the template supports; the model's row has Max reply tokens, Reasoning budget and, when the template supports effort, Effort (template's default, low, medium, high). Set Effort low and Reasoning budget 2000 and Save (still there after a reload): a reply's Thinking is short and the answer comes. Set Max reply tokens 1024 and ask for a long essay: a notice line, in every tab and after a reload, says the reply was cut off at its limit of 1,024 tokens (the model's maximum reply length) and to raise Max reply tokens. On an Anthropic provider's page each model's Max reply tokens placeholder shows its listed cap. Not web-checkable: the request's `max_tokens`, `thinking.budget_tokens` and `chat_template_kwargs` (tests in `turn` and `providers`) |
| SME-126 | A reply cut off in the middle of a tool call | Needs a llama.cpp `llama-server`. On its provider's page set the model's Max reply tokens to 1024 and Thinking off, and Save. In a new conversation on it, ask "Don't start a sandbox. First say in one short sentence what you will do, then call todowrite once with 150 pending todos, each one line of a poem about rivers.": the sentence stays, no row appears for the call, the todo list stays empty, and a notice line (live, in a second tab and after a reload) says the reply was cut off at its limit of 1,024 tokens "in the middle of a `todowrite` call, which didn't run", with what to change. Ask what happened to its last reply: it answers (no provider error) that the call was dropped. Set Max reply tokens back afterwards. Automated: `anthropic::stream` tests against a real llama.cpp capture, `turn` tests, and the browser tier's `cut_off_in_a_call` scenario (a real turn on that capture) |
| SME-169 | A character split across two network chunks of a reply stays whole | Not web-checkable on demand (a provider can't be made to split a character between reads). A web-checkable shadow: ask the model for a reply full of non-ASCII characters (e.g. "Write three lines of Chinese poetry with an emoji at the end of each, and save them to `/workspace/poem.txt` with write_file"): the reply and the file hold no `�`. Automated: `anthropic::stream::lines` unit tests and `anthropic::stream::tests::assembly::test_a_character_split_across_two_chunks_is_decoded_whole` (a mock upstream sending the body in chunks cut inside characters) |
| SME-162 | A provider's max concurrent requests | Needs a slow provider; a llama.cpp `llama-server` with one slot (`-np 1`) is the real case. On the provider's edit page set **Max concurrent requests** to 1 and Save (it loads back as 1). Open two conversations on one of its models and send in both within a second: the second stays on "Working…" without reaching the server until the first reply ends, then answers; neither times out. Set it to 0 (automatic): the models section shows the server's "N slots", and that's the limit; blank sends both at once. A wait over 30 s logs one "waiting for a free request slot" line, host only. Automated: `anthropic::stream::tests::limiter`, `providers::tests::server_tests::limiter`, `turn::tests::providers::test_two_conversations_on_a_one_request_provider_take_turns` |
| SME-178 | A stopped or failed call's usage is recorded; Ollama's and LiteLLM's real input counts | Start a check server on a scratch database (the default since SME-226, and the rules' template) with a provider for any real model. In a new conversation ask for a long essay and press Stop mid-reply; open the context view: "1 model call" with non-zero input and output tokens (the output estimated from what streamed). On "Model providers", "Last 30 days" counts it too. On an Ollama provider, a finished reply's input in the context view is Ollama's own count rather than its estimate. Not web-checkable: a call stopped after its reply is saved, a failed retry attempt, a call on a conversation deleted mid-turn, LiteLLM's and Anthropic's server-tool counts. Automated: `turn::tests::usage`, `anthropic::stream::tests::meter`, `anthropic::stream::tests::assembly::test_ollamas_input_and_cache_counts_come_from_its_message_delta`, `db::tests::usage::test_a_call_recorded_while_its_conversation_is_being_deleted_is_recorded_without_it` |
