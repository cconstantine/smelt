# Modules: the app, chat, models and turns

Part of [architecture.md](../architecture.md)'s module map. The entry point, the database, the model client and tools, turns, events, MCP, markdown and the pages.

| Module | Feature-gated? | Purpose |
|---|---|---|
| `src/main.rs` | — | Entry point. Server build, in order: load `.env` (a parse error is logged once logging is up, not swallowed), install rustls's `ring` crypto provider, `telemetry::init` (the console log, and the OTLP export when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; SME-137), then the rest of startup in a `startup` span: warn if `SMELT_ALLOWED_HOSTS` is unset, `db::init` (connect), `sqlx::migrate!()`, `db::start_ids_clear_if_fresh` (SME-115), `mcp::ensure_default_servers`, `sandbox::init`, `sandbox::adopt_unlabelled_objects` (awaited), spawn `sandbox::watch_pods`, spawn `sandbox::watch_idle_commands` (a 60 s pass that wakes a conversation whose terminal command has gone untouched, SME-79), `db::fail_unfinished_clones`, spawn `sandbox::sweep_orphaned_conversation_claims` (in a `claim_sweep` span), `preview::start`, then `build_router()` bound on `0.0.0.0:$PORT` (default 8080). `build_router()` is shared with `src/browser_tests/`. Web build: `dioxus::launch` boots the hydrated client. |
| `src/models.rs` | no | `Conversation`, `Message`, `LanguageServer`, `LanguageServerConfig`, `LanguageServerSuggestion` — shared wire/row types, `sqlx::FromRow` derived only under `server`. `Message::blocks()` parses the stored JSON `content` column into `Vec<ContentBlock>` — see [models.md](../models.md). |
| `src/db/` | `server` only | CRUD functions, in a module per group of tables that `mod.rs` re-exports (SME-163), taking `pool: &PgPool` explicitly, plus a global `OnceLock<PgPool>` (`init`/`get`) for production wiring — `send_message` calls `db::get()` once and passes the pool through everything else, including `anthropic::tools::execute` (see below). |
| `src/anthropic/mod.rs` | mixed | Re-exports the shared types (`ContentBlock`, `TokenUsage`, `ToolDefinition`; the request-only ones under `server`), `context_window_for` (the known context window of a `claude-*` model id). |
| `src/anthropic/models.rs` | `server` only | Lists a provider's models and what each can do, per kind: Anthropic's `/v1/models`, Ollama's `/api/tags` + `/api/show` + `/api/ps`, llama.cpp's `/v1/models` + `/props` (SME-111), another server's `/v1/models` (SME-72). Every request bounded at 10 s. |
| `src/providers.rs` | mixed | Model providers (SME-72). `providers/limiter.rs` keeps each limited provider's request slots by id (SME-162), set from `resolved_max` by `providers::endpoint`, the provider form's saves and a `/props` read; a new count resizes the pool in place (a lowered one takes back free slots and then the next ones given back, `limiter::Slot`), clearing it closes the pool so its waiters go, deleting the provider forgets the pool without closing it, and a set from an older row (its `updated_at`, which a `/props` write bumps too) than the last is ignored. Wire types (`ProviderSummary`, `ProviderInput`, `ModelInfo`, `ConversationModel`, `NO_MODEL_CONFIGURED`) ungated; the server half resolves a turn's `TurnModel`, the picker's `ConversationModel`, and the providers pages' create/update/delete, model listing and settings. |
| `src/anthropic/types.rs` | no | Rust mirror of the Anthropic Messages API wire shapes: `ContentBlock` (`Text`/`ToolUse`/`ToolResult`/`Thinking`, plus smelt's own `CompactionSummary`/`CompactionPlaceholder`, replayed to Anthropic as plain text), `TokenUsage`, `AnthropicMessage`, `ToolDefinition`, `ThinkingConfig` (adaptive, or a `budget_tokens` sent only to llama.cpp, SME-111), `ChatTemplateKwargs` (llama.cpp only, SME-111), `CreateMessageRequest` (carries `tools` and, when enabled, `thinking`). There is no response type: replies are only ever streamed (`stream.rs`). |
| `src/anthropic/stream.rs` | `server` only | `stream_anthropic_message_metered(endpoint, request, on_delta, meter)`: calls a provider's `/v1/messages` (an `Endpoint`, `stream/endpoint.rs`: base URL, `Auth::ApiKey`/`Auth::Bearer`, whose `Debug` hides the secret, and `slots_of`, the provider whose request slots, a `Semaphore` in `providers::limiter` looked up at each call, the call waits on and holds from before its first send to the stream's end, retries included, the wait recorded as `smelt.slot_wait_ms` on its `chat` span, SME-162) with `stream: true`, parses its SSE event stream (text/thinking deltas, `tool_use` blocks, kept by each event's `index` since llama.cpp overlaps them, SME-112), and returns a `StreamedTurn { content: Vec<ContentBlock>, stop_reason: String, usage: TokenUsage }`. Its usage is kept in the caller's `UsageMeter` (`stream/meter.rs`) as events arrive, so a call that ends early can be recorded with what it used (SME-178); the events are read in `stream/interpret.rs`. A `thinking` delta never reaches `on_delta` (no live-typing effect for it) — the full `Thinking` block only shows up once persisted, same as a `ToolUse`/`ToolResult` block. |
| `src/anthropic/tools/` | mixed (see below) | Tool implementations dispatched by name (`execute`), one module per domain: `pods.rs` (sandbox pods and terminals: `create_pod`/`create_terminal`/`run_terminal_command`/... — see `src/sandbox.rs` below), `files.rs` (`read_file`/`write_file`/`edit_file`/`list_directory`/`glob`/`grep`), `todos.rs` (`todowrite`/`todoread`), `git.rs` (`clone_repo`/`load_instructions`/`list_personas`), `web.rs` (`webfetch`/`http_request`/`sandbox_preview_url`), `browser.rs` (`open_browser_session`/`browser_navigate`/...), `lsp.rs` (`lsp_servers`/`start_language_server`/`lsp`), `questions.rs` (`ask_user`'s definition only: the turn loop handles the call, see `src/turn/`) and `agents.rs` (`start_agent`/`list_agents`/`stop_agent`/`finish`, SME-236, and `message_agent`/`ask_parent`, SME-238, see `src/agents/`). Each module's `tools()` lists its `Tool { def, run, class }`s, a tool's definition beside its dispatch and its class (`class.rs`: `ToolClass`, read-only < writing < destructive, fixed per tool except `http_request`'s, which is by the method it sends; SME-237, see [mcp.md](../mcp.md#tool-classes)), and `class::tests` holds every tool's class as the design writes it; `mod.rs` collects them into `REGISTRY` in a fixed order (the order is part of what the model sees), each with its `Offer` (every conversation, only one without a parent, only an agent, or every conversation but callable only by one with a parent or agents of its own), which `tool_definitions(pool, conversation_id)` and `execute` both apply and also dispatches every configured MCP server's tools as `mcp__<server>__<tool>` (see [mcp.md](../mcp.md)). `TodoItem` (a plain data type that crosses to the browser) is not feature-gated; the tools and `execute` itself are `server`-only (SME-54). |
| `src/events/` (`mod.rs`, `server.rs`) | mixed (see below) | The live event buses. `ConversationEvent` (not gated, crosses the boundary as `subscribe_conversation_events`'s payload — `MessagesAppended`/`SandboxPodUpdate`/`SandboxTerminalUpdate`/`SandboxCommandUpdate`/`ReplyReset`/`ReplyDelta`/`TurnError` and more — see [api.md](../api.md)) plus `server`-only `publish`/`subscribe`/`forget` backed by a `LazyLock<Mutex<HashMap<i64, broadcast::Sender<ConversationEvent>>>>`. `AppEvent` (`PodsChanged`/`TurnsChanged`/`QuestionsChanged`/`ConversationsChanged`/`ProvidersChanged`) is the app-wide bus behind `publish_app`/`subscribe_app`. Both enums decode a type they don't know as `Unknown` (`#[serde(other)]`, never published), so a tab on an older bundle skips an event type added since (SME-43). |
| `src/api/mod.rs` | no | Declares the server-function modules below. |
| `src/api/chat.rs` | no (functions are isomorphic; only their bodies differ per build) | The chat's server functions: `get_conversations`, `create_conversation`, `delete_conversation`, `get_messages`, `send_message`, `stop_turn`, `get_busy_conversations`, `get_turn_state`, `get_turn_error`, `get_reply_in_progress`, `get_todos`, `get_context_usage`, `get_context_detail`, `get_conversation_model`, `set_conversation_model`, `subscribe_conversation_events`. They call into `src/turn/` for the turn itself (SME-52). |
| `src/turn/` | `server` only | The turn engine (SME-52), in modules: `run` (`start_turn`, what `send_message` calls; `run_turn_bounded`, the turn loop a send, an answer and a notice all go through once their caller has admitted the turn, `TurnInFlight::start_by_user` or `start_unless_paused` in `state`, SME-216; `run_turn`, its test-only wrapper; the retry ladder for a local model's tool-call-JSON corruption, `is_ollama_thinking_tool_call_corruption`/`TOOL_CALL_PARSE_RETRIES`), `state` (each conversation's turn lock, reply so far, stops, pause and kept error), `history` (the request's history and the system prompt), `compaction`, `notify` (notices between turns and waking the model), `questions` (the model's `ask_user`: recording the question, the waiting check, taking the answer into the next turn's message, SME-34). The base system prompt is `src/turn/system_prompt.md`, compiled in with `include_str!`. |
| `src/agents/` | `server` only | Child agents (SME-236, [api/agents.md](../api/agents.md)): `start` (`start_agent`'s checks, the start task with its `StartExit` cleanup, `fail_start`), `checkout` (the `ChildCheckout` seam: `PodCheckout` does the start's pod work, tests register fakes), `persona` (the persona checked in the parent, read at the child's ref and snapshotted, its model), `queue` (`finish`, `stop_agent`, the user's Stop on a child, the "ended without a report" notice), `delete` (the subtree delete), `messages` (`message_agent` and `ask_parent`, SME-238), `sweep` (the startup sweep, with its restart notices); `mod.rs` holds labels, statuses, `list_agents` and the turn admissions (`admit_user_turn`, `admits_notices`). Its rows are `src/db/agents/`; the clone at a ref is `src/git/server/child_ref.rs`. |
| `src/turn/system_prompt.md` | — | The base system prompt text (who smelt is, the sandbox, how to use the tools). `turn::system_prompt` appends the per-conversation sections, such as loaded project instructions. |
| `src/api/providers.rs` | no | The `/providers` pages' server functions (SME-72); the logic is in `src/providers.rs`. |
| `src/personas/` | `server` only | Persona files (SME-235): the only code that knows their format ([design](../design/personas/persona-files.md)). `links::absolute` rewrites a persona's relative links to absolute paths in a child's checkout (SME-236). `parse` reads `.agents/personas/<name>.md`: YAML frontmatter with exactly `name` (equal to the file's name), `description` and an optional `smelt` map (only `model` so far), into structs with `deny_unknown_fields`, so any other key, Claude Code's own included, is an error naming the file, the field and the file's line; the body is the instructions, and a file over 32 KiB is refused. `frontmatter::split` is the frontmatter split, for skills (SME-37) too. Finding and listing them is `git.rs`'s (`list_personas`). |
| `src/questions.rs` | mixed | The model's questions (SME-34). Wire types (`Question`, `QuestionOption`, `PendingQuestion`, `QuestionAnswer`, `ASK_USER`) ungated; the server half parses `ask_user`'s input against its limits, checks an answer, and words the call's result. |
| `src/api/questions.rs` | no | The question card's server functions: `get_pending_question`, `answer_question`, `get_waiting_conversations`; the logic is in `src/turn/questions.rs`. |
| `src/api/mcp.rs` | no (server functions are isomorphic) | The `/mcp-servers` pages' server functions: list/get/create/update/delete a server, `mcp_server_status`, and `start_mcp_server_oauth`/`disconnect_mcp_server_oauth`. See [mcp.md](../mcp.md). |
| `src/frontend/mod.rs` | no | `App` (router root) and the `Route` enum: `Home` (`/`), `ConversationRoute` (`/conversation/:id`), `McpServersRoute`/`McpServerNewRoute`/`McpServerEditRoute` (`/mcp-servers`, `/new`, `/:id`), `SandboxVolumesRoute`/`SandboxVolumeNewRoute` (`/sandbox-volumes`, `/new`), `PodsRoute` (`/pods`), `GitRoute` (`/git`), `LanguageServersRoute`/`LanguageServerNewRoute`/`LanguageServerEditRoute` (`/language-servers`, `/new`, `/:id`), and `NotFound` (`/:..segments`). `App` also renders `StaleBundleBanner`, shown once `STALE_BUNDLE` is set (see [Live channels](../architecture.md#live-channels)). See [frontend.md](../frontend.md). |
| `src/frontend/clipboard.rs` | no | Copying text from a click (SME-105): `copy_text` uses `navigator.clipboard` in a secure context and a hidden `textarea` with `execCommand('copy')` over plain HTTP, starting inside the click so it keeps the user's gesture; `CopyButton` shows "Copied" or "Couldn't copy" for a moment. Used by the transcript's Copy reply button. See [frontend/markdown.md](../frontend/markdown.md). |
| `src/frontend/pages/` | no | One file per page, apart from the chat page's folder. `chat/` (SME-57): `Chat` (`ConversationSidebar` + `ChatPanel`), one file per component; `ChatPanel` (`chat/mod.rs`) owns the page's state (the open conversation's in one `ConversationState` store, `chat/state.rs`) and opens a live `subscribe_conversation_events` stream (web-only), each event applied by `apply_event`, and renders, alongside the transcript, the context-usage indicator, todos, the browsing panel and a sandbox panel for the conversation's one pod (repos, previews, terminals, commands). `mcp_servers.rs` (`McpServersIndex`/`McpServerNew`/`McpServerEdit`), `sandbox_volumes.rs` (`SandboxVolumesIndex`/`SandboxVolumeNew`), `pods.rs` (`PodsIndex`, titled "Sandboxes"), `git.rs` (`GitSettingsPage`), `language_servers.rs` (`LanguageServersIndex`/`LanguageServerNew`/`LanguageServerEdit`). `mod.rs` has `TwoStepLabel`, the label of a click-to-arm, click-again-to-confirm button. |
| `src/markdown.rs` | both | The model's replies as markdown (SME-30): `parse` turns a reply into smelt's own node tree with pulldown-cmark (tables, strikethrough, task lists; raw HTML kept as text; links only for `http`/`https`/`mailto`, images only for `http`/`https`; bare URLs, `www.` addresses and email addresses outside code and allowed links linked by `linkify` (SME-104), each link's words its text; quotes and lists, and emphasis, strong, strikethrough and links, past `MAX_DEPTH` flattened), and the `Markdown` component renders that tree as Dioxus elements, never an HTML string. Saved replies and the streaming one both use it. See [frontend/markdown.md](../frontend/markdown.md). |
| `src/highlight.rs` | both | Code-block highlighting for `markdown.rs`: syntect (pure-Rust regex) with two-face's grammar set, loaded once on first use, producing nested spans with `hl-`-prefixed scope classes. `assets/highlight.css` holds the OneHalfLight/OneHalfDark themes for those classes; a test fails if it drifts (regenerate with `SMELT_UPDATE_HIGHLIGHT_CSS=1`). Code over `MAX_HIGHLIGHT_BYTES`, an unknown language, or a fence still open shows plain. |
| `src/mcp/` | `server` only | The MCP client (SME-15), a thin wrapper over `rmcp`: the connection registry keyed by `mcp_servers.id`, the `mcp__<server>__<tool>` naming (`parse_tool_name`), listing a server's tools for a model call (`tool_definitions_for`), `call_tool_classed` (a call, handing over its class from the tool's annotations, SME-237; `call_tool` is its test-only shorthand), `connection_check` for the status badge, and `ensure_default_servers` (adds the built-in Exa search server at startup unless one of that name exists). `mod.rs` holds the registry and connecting, `tools.rs` the naming and tool list, `call.rs` a tool call, `oauth_client.rs` the shared OAuth client (SME-205). See [mcp.md](../mcp.md). |
| `src/mcp_oauth.rs` | `server` only | OAuth for MCP servers (SME-16), around `rmcp`'s own OAuth client: `PgCredentialStore` keeps tokens in Postgres so they survive a restart, plus `start`/`handle_callback`/`disconnect` and `callback_handler`, the `/oauth/mcp-callback/{id}` route. See [mcp.md](../mcp.md). |
| `src/request_guard.rs` | `server` only | Axum middleware (`guard`) on every request (SME-51 B1). smelt has no login, so it refuses a non-`GET`/`HEAD`/`OPTIONS` request another site's page sent (`Sec-Fetch-Site`, or `Origin` from older browsers; `same-site` too, since previews are sibling origins), and a `Host` name that isn't smelt's own (DNS rebinding) when `SMELT_BASE_URL`/`SMELT_ALLOWED_HOSTS` say what those are. IP addresses, `localhost` and requests with neither header (curl) pass. |
| `src/telemetry.rs` | `server` only | OpenTelemetry tracing (SME-137). `init` installs the subscriber: the console's `fmt` layer filtered by `RUST_LOG` (`log_filter_directives`), plus, only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, a `tracing-opentelemetry` layer exporting over OTLP/HTTP in batches, with its own fixed filter (smelt's spans and events from INFO, other crates' warnings and errors only, and nothing from OpenTelemetry, reqwest, hyper or h2 themselves). The resource names the service, its version, the database (name only) and the port. `in_span` runs a future in a span and ends the span's export when the future ends, `mark_error` marks a span failed without a console line, `outside_spans` runs work on a task outside every span, and `make_http_span`/`on_http_response` are `TraceLayer`'s. See [Tracing](../architecture.md#tracing-opentelemetry). |
